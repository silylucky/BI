# Grilling Loop（点选后深挖）

用户点名某个 HTML 候选后进入本循环。目标：在改代码前把 deepened module 的形状钉死。

## 门闩

- 已展示 HTML 报告
- 用户明确点选（名称或编号）
- **尚未**大范围改业务代码

## 一次只推进一个问题

按序收敛（可跳过已显然项）：

1. **约束**：性能、一致性、部署、团队习惯、不可破的外部契约
2. **依赖**：哪些必须留在缝外？哪些是泄漏该下沉的？
3. **Deepened module 名字**：用域名词（对齐 CONTEXT）；禁止 FooManager 空名
4. **Interface 形状**：操作列表 + 输入输出域类型（仍可用伪代码；可设计两次再选）
5. **缝后内容**：implementation 内聚什么；adapters 各是谁（≥2 才强调 ports & adapters）
6. **测试**：哪些旧测试删除/搬迁；新测试只打新 interface
7. **迁移切片**：文件集、顺序、风险、回滚点

每步结束用用户的话确认，再问下一问。

## 设计两次（可选）

当 interface 有两种合理形状时：

- 起两个短跑 subagent（或主 agent 两栏对照）
- 维度：locality、leverage、测试硬度、与 ADR 兼容
- 用户选一；记下未选原因（可成 ADR）

## 结晶副作用

| 条件 | 动作 |
|------|------|
| 新域名词 | 写入/创建 `CONTEXT.md` |
| 锐化旧词 | 就地改 `CONTEXT.md` 定义 |
| 拒绝且理由可复用 | 提议 ADR（模板见下） |
| 「现在不做」/「没感觉」 | **不写** ADR |
| 违反现有 ADR 但要做 | 先修订 ADR「后果/状态」，再动代码 |

### ADR 提议模板（仅提议，确认后写）

```markdown
# ADR-XXXX · {{标题}}

## 状态
提议中

## 上下文
架构审计候选「{{候选名}}」在 grilling 中被拒绝/重开。

## 决策
{{用户理由的精确表述}}

## 后果
- 正面：…
- 负面：…（含：未来审计不应再提的边界）
```

路径习惯：`docs/adr/<主题>-<模块|流程>.md`（与 docs-reviewer taxonomy 对齐）。

## 重构切片输出（确认前）

```markdown
## 切片 · {{候选名}}

| 序 | 改动 | 文件范围 | 验收 |
|----|------|----------|------|
| 1 | … | `…` | 测试打在 `…` interface |
| 2 | 删除 shallow 包装 | `…` | deletion test 通过：无透传残留 |
| 3 | 文档 | CONTEXT / 可选 arch 一句 | 名词一致 |

依赖：无 / 前置切片 …
风险：…
```

**停等用户确认切片**再执行。执行时小步；禁止夹带无关重构。

## 与 create-evolution-arch

- grilling 中只需改 arch 的**一句边界/决策** → 可最小 diff `docs/arch.md`
- 需要重写架构章节或评分体检 → 建议用户另开 create-evolution-arch
