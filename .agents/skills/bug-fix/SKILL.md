# Bug Fix（点线面 · 根因分层 · 修复判断）

Agent 已会「读堆栈改几行」。本 Skill 补：**根因落哪一层**、**用 code-scanning 取证扩面**、**选最合理修法**、**确认后 go-fast 批量**。

不替代 Superpowers **systematic-debugging** 的「先根因后修复」铁律；在其之上加**分类、扫描扩面、修复策略**。  
扫仓定位 / 同类形状 / 调用影响面 → **必须先读并遵循** [code-scanning](../code-scanning/SKILL.md)（隐式入口只探测不安装；rg→ast-grep→codegraph 分诊）。  
不替代 [code-reviewer](../code-reviewer/SKILL.md) / [arch-reviewer](../arch-reviewer/SKILL.md) 的仓级扫描。  
线/面批量实现默认走 [go-fast](../go-fast/SKILL.md)。

## 何时启用

| 场景 | 动作 |
|------|------|
| 用户提交 Bug / 报错 / 回归 / 「帮我修」 | 取证 → **code-scanning 定位** → 分层+最合理修法 → 点线面+发散 → 决策卡 → **询问是否修** → 落地 |
| 「类似问题一起修 / 扫同类」 | code-scanning 强制发散扫；确认后 go-fast |
| 「这是架构问题还是代码问题」 | 扫描取证 + 分层 + 发散，出判断卡，可不改代码 |
| 修完要防复发 | 分析卡含防复发；必要时补测试/观测/规则 |

**不要**：未复现就猜补丁；**只会 rg 扫形状**（该用 ast-grep/codegraph 时）；只修本参数/本函数/本页结案；未确认就批量改；仓级假绿清扫冒充单点 Bug（改走 code-reviewer）。

## 铁律

```
无复现/无证据 → 不宣称根因
未用 code-scanning 分诊做定位/扩面（或注明工具缺失降级）→ 不宣称「同类已排清」
未分层 + 未点线面 + 未同类发散 → 不宣称「已修好」
未选「最合理修法」就动手 → 禁止（禁止症状补丁冒充根治）
未询问用户确认 → 不批量改码（紧急缓解除外，须标注）
```

1. **先取证后改码**：复现链完整；不可复现则只采集。
2. **扫描服从 code-scanning**：步骤 2–3 的定位与扩面按三层分诊；隐式**不装**工具，缺则 rg 降级并在决策卡注明 Blind spot。
3. **先分层 + 最合理修法再动手**：语法/代码/流程/架构定错 → 修法必错；修在错误层（如架构问题只 if）= 违规。
4. **点线面 + 同类发散后再收工**：换参数/函数/页面/入口是否仍炸必须回答。
5. **先问后修**；**批量走 go-fast**。

## 必读顺序（≤3 次）

1. 本文件「五步流程」+「扫描定位」+「最合理修法」+「确认后 go-fast」
2. [code-scanning](../code-scanning/SKILL.md) 三层分诊 + 隐式入口；维度见 [analysis-dimensions.md](references/analysis-dimensions.md)
3. [report-template.md](references/report-template.md) + [fix-decision.md](references/fix-decision.md)（含扫描→修法→go-fast）；样例 [examples.md](references/examples.md)

## 五步流程（必须按序）

复制进度：

```
Bug-Fix Progress:
- [ ] 1 取证复现
- [ ] 2 扫描定位根因 + 分层 + 最合理修法（code-scanning）
- [ ] 3 点线面扩面 + 同类发散（code-scanning）
- [ ] 4 修复决策卡（含多维推荐 + 为何不选其他）→ 询问用户是否修复及范围
- [ ] 5 确认后实施（点修本会话 / 线面→go-fast）· 验证 · 防复发
```

### 1. 取证复现

最小采集（缺什么补什么，能自查的不要问用户）：

| 项 | 要什么 |
|----|--------|
| 现象 | 期望 vs 实际（用户语言，禁甩内部函数名糊弄） |
| 复现 | 步骤、环境、账号角色、数据前提、是否必现 |
| 证据 | 堆栈、HTTP 状态/信封、关键日志、UI 截图、失败用例 |
| 近变 | 相关近期提交、配置、依赖、数据迁移 |
| 边界 | 仅某租户/某浏览器/某并发量？ |

不可复现 → 输出「观测缺口」建议，**暂停改业务逻辑**。

### 2. 扫描定位根因 + 分层 + 最合理修法

**2.1 先 Read [code-scanning](../code-scanning/SKILL.md)，再探测（隐式不装）**

```bash
command -v ast-grep; command -v codegraph; ls -d .codegraph sgconfig.yml 2>/dev/null
```

有 codegraph 且查图前：`codegraph status`；范围内 pending → `sync`，失败则降级 rg/ast-grep 并标 Blind spot。

**2.2 按问题形态选层（不要默认全 rg）**

| 要回答的问题 | 用 | 典型 |
|--------------|----|------|
| 错误串、配置键、文案、env 名在哪 | **rg** | 日志关键字、feature flag |
| 缺陷是**代码形状**（空 catch、无 timeout、同错误映射、裸 input） | **ast-grep** 临时 `-p` | 面/发散主武器 |
| 符号定义、谁调用、改它炸哪、因果链上下游 | **codegraph** | 点→线；根因落点 |
| 说不清符号只像「某种逻辑」 | rg + 读文件 / explore | 再提炼成形状或符号 |

**默认组合（根因）**：堆栈/复现锚点 → **codegraph** 顺藤摸瓜定因果链 → 抽出可检索模式 P → **ast-grep** 验是否同构 → **rg** 补字符串/配置漏网。

**2.3 根因四层（主层唯一）**

| 层 | 含义 | 典型信号 | 默认修法方向 |
|----|------|----------|--------------|
| **语法/机械** | 笔误、类型、空指针未判、错误 API 用法 | 静态检查能抓 | 点修 + 补检查/测试 |
| **代码/实现** | 分支漏、状态机错、边界未处理 | 边界清晰只是写错 | 点修或线修（同函数族） |
| **流程/产品规则** | 步骤/权限/状态流转未对齐 | 规则打架或未落地 | 先对齐规则，再改码 |
| **架构/缝** | 泄漏、契约不一致、无超时/幂等、假缝 | 换入口/适配器同构再炸 | **禁止只点修**；缝上统一或回流 |

**分层口诀**：改一个 if 就永远干净 → 偏语法/代码；同一业务换入口还炸 → 偏流程；换模块/适配器还炸或到处同坑 → 偏架构。

**2.4 最合理修法（出卡前必选一，写进决策卡）**

在「能修点绿」的方案里选**成本与复发风险最优**的一档，禁止「最先想到的补丁」：

| 候选 | 何时合理 | 何时不合理 |
|------|----------|------------|
| **A 点修** | 扫描显示无线面同构；主层=语法/局部代码 | 发散轴已命中多处 |
| **B 收拢到唯一实现/helper** | 多处拷贝同一逻辑（ast-grep 命中） | 各处业务规则其实不同 |
| **C 缝上统一**（错误信封、超时、幂等、校验） | 主层=架构/缝；调用方特判会繁殖 | 用 N 处 if 假装缝已修 |
| **D 改规则/产品后再改码** | 主层=流程且规则不清 | 未确认就改状态机 |
| **E 缓解 + 回流切片** | 阻断急、正式修要迁移/ADR | 缓解当结案且不挂号 |
| **F Won't fix** | 伤情≪成本且可监测 | 用户主路径仍阻断 |

**判定口诀**：修完后「换参数/函数/页面」是否还要再开一张同类单？若会 → 当前方案不够合理，升 B/C/E。

细则 [analysis-dimensions.md](references/analysis-dimensions.md)；策略矩阵 [fix-decision.md](references/fix-decision.md)。

### 3. 点 · 线 · 面 + 同类发散（继续用 code-scanning）

| 粒度 | 问什么 | 扫描 | 收工标准 |
|------|--------|------|----------|
| **点** | 本例最小因果链 | codegraph 定符号 + 读源 | 本例复现可变绿 |
| **线** | 同链/同契约/同模板是否同源 | codegraph callers/impact | 线清或明示线债 |
| **面** | 仓内同构模式几处 | **ast-grep** 主扫；rg 补漏 | 候选表 + 可否批量 |

**同类发散（强制）** — 每轴用扫描扩，命中进候选表：

| 发散轴 | 优先工具 |
|--------|----------|
| **参数/数据** | rg 字段/校验名；同 parser 的 codegraph 调用方 |
| **函数/符号** | ast-grep 同形状；codegraph 同 callee 族 |
| **页面/路由/入口** | rg 路由/composable 名；codegraph 共用 hook |
| **动词/对称操作** | ast-grep/rg 同资源其他 method |
| **端/角色/租户** | rg 双端目录 + 权限注解抽样 |

作业顺序：抽出模式 P → 分诊扫描得集合 C → 标 同源/疑似/排除 → 写入决策卡。详见 [analysis-dimensions.md](references/analysis-dimensions.md) §B。

**批量修门槛**：模式可检索 + 手法一致 + 可验证 + 用户确认（含发散候选）。否则修点 + 清单。

### 4. 修复决策卡 → 询问是否修复

用 [report-template.md](references/report-template.md)，至少含：

- 根因一句话 + **主层** + **最合理修法（A–F）** 及为何不选更弱点修
- **扫描摘要**：用了 rg/ast-grep/codegraph 哪层；缺失/Blind spot
- 点 / 线 / 面 + 同类发散候选表
- 若批量：将 **交接 go-fast**
- 风险、验证（含换皮抽检）、防复发
- **我的推荐（必填）**：见下

**推荐是硬要求，不是可选项。** 只摆五个选项让用户自己挑，等于扔掉刚做完的取证与扫描——用户没看过
调用方清单，判断不了「点修下周会不会再炸」。卡里必须选定一项标 `← 推荐`，且：

1. 推荐项**从本次证据推出**（主层 + A–F 定策略，发散候选数 + 手法一致性定范围），不是固定推荐某个编号；
2. 理由**多维展开**并各挂证据：架构与边界（修在缝上还是固化假缝）、长期维护（下次换轴是否再开同类单）、
   可靠性（是否打在因果链上、失败可见、竞态/幂等）、爆炸半径与回滚、成本与时效、验证可行性；
3. **被否选项各写一句**为什么不选、何时反而更优；
4. 写明**代价**（风险、回滚粒度、遗留债）与**置信度**（有 Blind spot / 发散轴未验 / 规则未定 → 不得报「高」）。

导出对应表与禁止写法见 [fix-decision.md](references/fix-decision.md) §6.1。

卡末停问：

> 是否修复？请选：①只修点 ②点+线（go-fast）③点+线+面含发散（go-fast 批量）④缓解+回流 ⑤只要分析不改码

**停等用户确认。** 开场已授权批量 → 仍贴卡摘要再 go-fast。

### 5. 确认后实施 · 验证 · 防复发

| 用户确认 | 怎么落地 |
|----------|----------|
| **只要分析** | 停；清单留债 |
| **只修点** | 本会话按选定修法最小落地；未修发散写收尾 |
| **点+线 / 点+线+面** | **[go-fast](../go-fast/SKILL.md)** 路径 B：决策卡+扫描候选表 → `docs/specs/bugfix-<slug>.md` → 规格门 → unattended |
| **缓解+回流** | 本会话 mitigation；正式项规格或 arch-reviewer，确认后可 go-fast |

纪律：对准根因层与选定修法；验证=原复现+发散抽检；防复发至少一项；收尾含扫描工具与 Blind spot。

## 多维快检（出卡前过一遍）

1. **扫**：code-scanning 用了哪层？缺工具 Blind spot 写了吗？
2. **层**：语法 / 代码 / 流程 / 架构？
3. **法**：最合理修法 A–F 选了哪个？为何不是更弱点修？
4. **面/散**：候选多少？换皮还会炸吗？
5. **伤/时/史/防**：伤情、必现性、近变、防复发缺口
6. **治**：点修够不够？go-fast 批量？回流？

## 硬规则（短）

1. 不复现、无证据，不输出「根因已确定」。
2. 步骤 2–3 **必须按 code-scanning 分诊**；禁止形状问题只靠 rg；工具缺失须 Blind spot，不得假装已全仓排清。
3. 未写明 **最合理修法（A–F）** 不得开修；架构主层禁止只交局部 if 结案。
4. 流程主层先对齐规则；冲突交用户。
5. 未做同类发散不得宣称「同类已排清」。
6. **未询问确认不得批量改码**；线/面确认后走 go-fast。
7. 临时缓解标 `mitigation` + 正式项。
8. 用户向中文简述；分析卡少堆内部符号名。
