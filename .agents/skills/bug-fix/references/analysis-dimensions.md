# 分析维度（点线面 · 分层 · 多维）

出决策卡前按需勾选；不必每维长文，但**空白维要自觉**。

---

## A. 点线面（扩面维）

| 维 | 问题 | 证据手法 | 结论形态 |
|----|------|----------|----------|
| **点** | 本例最小失败因果链是什么？ | 复现 + 断点/日志 + 读失败路径源码 | 单因果链，1–3 个关键符号 |
| **线** | 同一请求/作业/状态机路径上是否同源？ | codegraph 上下游；同一中间件/拦截器/DTO | 「线清」或「线债 N 处」 |
| **面** | 仓内同构模式有几处？ | ast-grep 形状 / rg 契约关键字 / reviewer catalog | 候选列表 + 是否可批量 |

**升级规则**：点修后若线/面仍红，不得宣称「问题已消除」，只能宣称「本例已消除」。

**降级规则**：面很大但修复手法不一致（每处要产品决策）→ 拆成多个点/线，或只出 finding 不批量改。

## B. 同类发散（换皮防漏维）

目标：避免「本参数/本函数/本页已绿，换一套皮同类还在」。点定根因后**每轴至少一句结论**；命中则进候选表。

| 轴 | 核心问句 | 检索提示 | 漏扫症状 |
|----|----------|----------|----------|
| **参数/数据** | 换边界值、空、另一枚举、另一 id 形态还炸吗？ | 同 validator/parser；同 SQL 绑定；同 schema 字段族 | 只修了用户那组入参 |
| **函数/符号** | 兄弟函数、拷贝变体、同 helper 其他封装还炸吗？ | ast-grep 同形状；符号名前缀/后缀族；codegraph 同 callee | 只改了报错栈顶那一个函数 |
| **页面/路由/入口** | 列表↔详情、创建↔编辑、另一菜单深链还炸吗？ | 同 page recipe / 同 composable / 同 API client | 只修了用户截图那一页 |
| **动词/对称** | create 修了，update/delete/import/retry 还炸吗？ | 同资源写路径；同 controller 其他 method | 只堵了 POST 漏了 PUT |
| **端/角色/租户** | 管理端↔用户端、角色 A↔B、租户配置差还炸吗？ | 双端目录；权限注解；tenant 配置分支 | 只在超管账号下验证 |
| **环境/客户端** | 另一浏览器、移动端、导出/打印通道还炸吗？ | 条件编译；UA 分支；导出专用路径 | 只在本机 Chrome 绿 |

## 发散作业顺序

```
0. Read code-scanning；探测 ast-grep / codegraph（隐式不装）
1. 从本例抽出可检索模式 P（形状 → 预备 ast-grep；符号 → codegraph；字符串 → rg）
2. 对上表每轴：按分诊扩检索 → 得候选集合 C
3. 去重；标 同源确信 / 疑似 / 排除（一句理由）
4. C 写入决策卡；可批量? = 手法是否同一模板
5. 验证计划必须含：原复现 + 从 C 抽 ≥1 个换皮点
```

| 轴 | 优先工具 |
|----|----------|
| 参数/数据 | rg 字段名；codegraph 同 parser 调用方 |
| 函数/符号 | **ast-grep** 同形状；codegraph 同族 |
| 页面/路由 | rg 路由/composable；codegraph 共用 hook |
| 动词/对称 | ast-grep / rg 同资源 method |
| 端/角色/租户 | rg 目录与权限注解 |
| 环境/客户端 | rg 条件分支 / 导出路径 |

### 反模式

| 禁止 | 为何 |
|------|------|
| 「先修这一处，同类以后再说」且不列 C | 换皮再炸几乎必然 |
| 用文件名/页面标题当模式，不用代码形状 | 检索扩不开 |
| **形状问题只用 rg**（该 ast-grep 时） | 注释/字符串误报，漏真同构 |
| 把需产品决策的差异塞进同一批量包 | go-fast 会误伤业务规则 |

完整维度仍要过；同类发散是扩面的**强制加项**。

## C. 根因四层（性质维）

| 层 | 是 | 不是 | 一句话测试 |
|----|----|------|------------|
| **语法/机械** | 空引用、错字段名、off-by-one、错误库用法 | 故意的业务分支 | 「换静态检查/强类型能否在写码时拦住」 |
| **代码/实现** | 漏分支、错条件、错误码映射错、本地状态不同步 | 模块职责放错 | 「边界清晰，只是实现写错」 |
| **流程/产品规则** | 审批跳步、状态不允许回退却回了、权限模型与操作不符 | 纯性能调优 | 「按《规则》改码前必须先改规则或确认规则」 |
| **架构/缝** | 领域逻辑塞进 UI/适配器、跨缝泄漏、无统一超时/幂等、双写无协调 | 单函数笔误 | 「换一个入口/适配器仍会以同类方式失败」 |

### 易混对照

| 现象 | 易误判 | 更准 |
|------|--------|------|
| 到处 `catch (e) { return ok }` | 代码 | **架构/缝**（错误策略未在边界统一）或面级代码债 |
| 只有 Safari 炸 | 代码 | 先环境/兼容（仍可能是代码未处理该引擎） |
| 「管理员可以、员工不可以」但产品说员工也该可以 | 代码 | **流程**（权限矩阵） |
| 支付回调重复入账 | 代码竞态 | 多为 **架构**（缺幂等键/唯一约束） |
| 文案写「已提交」实际队列失败 | 文案 | **流程 + 代码**（状态机与 UI 契约） |

**主层唯一**：卡片上只标一个主层；次层可附带（例：主=架构，次=代码特判堆积）。

## D. 影响与严重度（伤情维）

| 维 | 等级参考 | 问句 |
|----|----------|------|
| **用户可见性** | 阻断主路径 / 旁路难用 / 仅展示 | 谁在什么任务上走不下去？ |
| **数据安全性** | 写坏/丢数 / 读脏 / 无 | 是否已产生脏数据？要不要修数脚本？ |
| **安全合规** | 越权、泄漏、审计缺失 / 无 | 能否被他人利用？ |
| **爆炸半径** | 单租户单请求 / 单功能 / 全站 | 最坏一次故障影响多大？ |
| **可逆性** | 热修可逆 / 需迁移 / 不可逆已发生 | 回滚能否恢复？数据能否回放？ |

与 code-reviewer 的 P0/P1/P2 不必强行对齐；单点 Bug 可用：**阻断 / 高 / 中 / 低**。若扩成面且像假绿族，再映射 P0–P2。

## E. 时序与形态（现象维）

| 维 | 取值 | 含义 |
|----|------|------|
| **必现性** | 必现 / 高概率 / 偶现 | 偶现优先补观测，再谈修 |
| **触发型** | 输入 / 状态 / 并发 / 时钟 / 环境 / 额度 | 决定复现装置 |
| **新旧** | 新回归 / 陈年 / 首次暴露 | 新回归优先查近变 |
| **对称性** | 读写对称错 / 仅写 / 仅读 | 影响修数与缓存策略 |

## F. 契约与边界（系统维）

| 维 | 问句 | 真则倾向 |
|----|------|----------|
| **内外** | 失败在本进程内还是外部系统？ | 外 → 契约/超时/幂等/integration-research |
| **同步异步** | 用户以为同步完成、实际异步？ | 流程+观测（进度/失败回抛） |
| **单多租户** | 是否租户配置/数据隔离导致？ | 先比对照租户 |
| **兼容** | 改契约是否破坏旧客户端？ | 线/面修要版本策略 |

## G. 治理与防复发（治本维）

| 维 | 问句 | 动作 |
|----|------|------|
| **测试缺口** | 哪类测试本该红却没有？ | 补单测/契约测/用例 |
| **观测缺口** | 为何靠用户才发现？ | 日志字段、指标、告警、审计 |
| **门禁缺口** | lint/CI/类型能否拦？ | 规则、codegen、schema |
| **文档缺口** | 规则只在口头？ | 领域/PRD/验收勾选 |
| **重复劳动** | 是否第三次修同类？ | 升面，禁止再点修结案 |

---

## H. 修复适宜性（决策前置）

在选策略前对根因问（与主 Skill「最合理修法 A–F」对齐）：

1. **正确性**：最小改动是否恢复不变量？还是只藏症状？
2. **完整性**：点绿而线/面/发散仍红，用户是否可接受？
3. **扫描证据**：修法是否被 ast-grep/codegraph 结果支持（多处同构 → 不宜纯点修）？
4. **时机**：是否必须热修缓解，正式修复另排期？
5. **所有权**：是否该先改规则/架构文档再动码？
6. **机会成本**：面修是否挤占更急的里程碑？→ 可「修点 + 挂号」
