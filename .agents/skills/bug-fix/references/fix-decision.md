# 修复决策方法论

配合主 Skill 步骤 4–5。先选**策略**，再选**范围**，最后才写补丁。

---

## 1. 策略矩阵（主层 × 点线面）

| 主层 ↓ \ 范围 → | 点 | 线 | 面 |
|-----------------|----|----|----|
| **语法/机械** | 默认：直接点修 + 测试 | 同文件/同工具函数一并修 | 若 lint 可全仓扫，交门禁 |
| **代码/实现** | 默认点修 | 同模板函数/同一 state 处理拉齐 | 形状一致才批量；否则列清单 |
| **流程/产品** | 先确认规则，再改本路径 | 对齐整条业务路径的状态与文案 | 矩阵/权限/多入口 → 产品确认后批量 |
| **架构/缝** | **仅允许缓解或最小护栏** | 在缝上修统一策略（超时/错误/幂等） | 回流切片 / arch-reviewer；禁止 N 处复制 if |

**缓解（mitigation）**：熔断、开关、只读降级、拒单保护。必须：标注临时、有正式修复项、有撤出条件。

**Won't fix**：成本 ≫ 伤情、或属环境误用且文档已澄清。须写清理由与监测方式。

---

## 2. 判断树（简版）

```
已复现且有证据？
  ├─ 否 → 补观测 / 要复现材料；不改业务逻辑
  └─ 是 → code-scanning 分诊定位（探测→rg/ast-grep/codegraph）
        → 定主层 + 最合理修法 A–F
        ├─ 流程且规则不清 → grilling / 问用户；暂停改码
        ├─ 架构 / 选 C 或 E → 出缝上统一或回流；点修只作 mitigation
        └─ 语法或代码 / 选 A 或 B → 点线面+发散扫描
              ├─ 面/发散候选且手法一致 → 建议面修（确认后 go-fast）
              ├─ 面大但手法不一 → 点/线 + 清单
              └─ 仅点 → 点修 + 写明「扫描无线面证据」
```

### 最合理修法速查（A–F）

| 码 | 含义 | 扫描旁证 |
|----|------|----------|
| A | 点修 | codegraph/ast-grep 无同构命中 |
| B | 收拢 helper | ast-grep 多处同形状拷贝 |
| C | 缝上统一 | 多入口同失败模式；impact 面大 |
| D | 先改规则 | 代码「按规则」并不唯一 |
| E | 缓解+回流 | 阻断急 + 需迁移/ADR |
| F | Won't fix | 伤情低且可监测 |

## 3. 批量修（面）准入与禁入

**准入（全要满足）**

1. 模式可检索（同一 AST 形状或同一契约违反）
2. 补丁模板单一（参数化即可，不必每人肉决策）
3. 有验证手段（测试、脚本、抽检表）
4. 范围经用户确认（目录/模块/严重度）

**禁入**

- 「既然打开了就顺手重构」
- 把产品文案/权限矩阵差异当成同一 bug 形状
- 架构裂缝用 20 处本地 try/catch「批量消灭」
- 无回滚方案的数据迁移式「修复」夹在 UI 文案修复里

**批量执行秩序**

1. 先修/验证 **点**（模板正确）
2. 再应用到 **线**（证明路径级正确）
3. 最后铺开 **面**（同一 diff 手法）
4. 每步可回滚；面修用独立提交更好（若用户要提交时）

---

## 4. 修复质量闸门

动手后、宣称完成前：

| 闸门 | 通过标准 |
|------|----------|
| 根因对准 | 去掉补丁后原复现仍失败；补丁打在因果链上而非仅 UI |
| 层对准 | 架构问题不是只靠调用方特判结案 |
| 复现变绿 | 原步骤 + 至少一个邻近边界 |
| 无声漂 | 不扩大对外契约；必要变更写明兼容 |
| 债显式 | 未修的线/面写进收尾，不假装不存在 |
| 防复发 | 测试或门禁或观测至少落一项（架构/流程可落文档） |

---

## 5. 常见错误修法（禁止）

| 诱人补丁 | 为何坏 | 正解方向 |
|----------|--------|----------|
| 最外层吞掉异常返回成功 | 假绿、无观测 | 在缝上统一错误映射；失败要可看见 |
| `if (userId === '那个客户')` | 点永远修不完 | 数据/规则/配置化 |
| 只改前端展示与后端不一致 | 双源真相 | 定单一事实源 |
| 睡一会儿「避开」竞态 | 负载下一必炸 | 幂等、锁、队列、唯一约束 |
| 复制粘贴同逻辑到第五处 | 面在扩大 | 收拢到模块/缝 |

## 6. 输出给用户的决策选项（必须询问）

分析卡末尾**停问**，勿默认开修。推荐文案：

> 是否修复？请选一项：  
> 1. **只修点** — 本会话最小修复；线/面/发散记债  
> 2. **修点+线** — **go-fast** 批量（主路径同源）  
> 3. **修点+线+面（含发散候选）** — **go-fast** 批量  
> 4. **缓解 + 回流** — 本会话 mitigation；正式项另排 / 可再 go-fast  
> 5. **只要分析，不改码**

可附加：用户直接回复「3」或「go-fast 批量修同类」即视为确认选项 3。

### 6.1 必须给出推荐，并给出为什么

**只列五个选项让用户自己挑，等于把刚做完的取证与扫描白扔掉**——用户没读过 codegraph 的调用方清单，
无法判断「点修会不会下周再炸一次」。因此卡里**必须**选定一项并标 `← 推荐`，且推荐项要从本次证据推出来，
不是套模板固定推荐 3。

**推荐怎么导出**：先由主层 + 最合理修法 A–F 定策略，再由发散候选数与手法一致性定范围。常见对应：

| 证据长这样 | 通常推荐 |
|---|---|
| 主层=语法/代码，ast-grep 与 codegraph 均无同构命中 | **1 只修点** —— 强行铺面是无据扩散 |
| 同源命中集中在一条链/一个函数族，手法同一模板 | **2 点+线** |
| 多入口同构命中且模式可检索、补丁可参数化、验收可抽检 | **3 点+线+面** |
| 主层=架构/缝，正式修需迁移或 ADR，但线上正在阻断 | **4 缓解+回流** —— 点修只作 mitigation 并挂号 |
| 主层=流程且规则本身没定 | 先 **5 / grilling 对齐规则**，规则未定就改状态机是赌博 |

**理由必须多维展开**，至少覆盖：架构与边界（修在缝上还是固化假缝）、长期维护（下次换轴是否再开同类单）、
可靠性（是否打在因果链上、失败可见、竞态与幂等）、爆炸半径与回滚、成本与时效、验证可行性。
每维给结论并挂证据（扫描命中数、impact 面、伤情级别），空维要写「不适用」及原因。

**还要写清三件事，否则推荐不成立**：

1. **被否选项各一句**为什么不选，以及它在什么条件下反而更优——只夸推荐项是推销不是建议。
2. **推荐的代价**：风险、回滚粒度、留下的债。没有代价的方案通常是没想清楚。
3. **置信度**（高/中/低）。有 Blind spot、发散轴未验证、或产品规则未确认时**不得**报「高」，
   并写明缺哪条证据——用户据此决定是先补证据还是直接开修。

**禁止**：把推荐写成「建议修复以提升质量」这类无信息量的话；为了显得稳妥一律推荐最小改动；
或反过来为了显得彻底一律推荐面修。范围应由证据定，不由姿态定。

## 7. go-fast 交接（线/面批量）

用户确认 **2 / 3**（或等价「批量修同类」）后：

1. **Read** [go-fast](../../go-fast/SKILL.md)，按**路径 B**（决策卡 ≠ 现成 Path A 规格）。
2. 综合材料写入 `docs/specs/bugfix-<slug>.md`，至少含：
   - 根因一句话 + 主层 + **最合理修法 A–F**
   - **扫描摘要**（模式 P、工具层、候选表、Blind spot）
   - 可观察验收（原复现 + 发散抽检）
   - 统一补丁手法 / 禁止症状补丁
   - 非目标（不顺手重构、不改无关规则）
3. 跑 go-fast **规格门**（除非用户 `skip_plan_review`）。
4. 拆工单：按模块或按候选簇拆；文件白名单不相交则可并行；`attendance=unattended`。
5. 小缺陷且候选 ≤ 少数同文件：仍可路径 B 单票 `01`，但**不要**跳过 go-fast 纪律（红绿、证据、禁假绿）。
6. 本会话 bug-fix Agent：交接后以 go-fast 回传为准做收尾卡；勿与 go-fast 双写同一批文件打架。

**只修点（选项 1）**：不强制 go-fast；本会话改完即可。若点修 diff 已牵出公共缝且用户改口要拉齐线面 → 再走本节。

**选项 4**：mitigation 本会话；回流规格可随后 go-fast，或先 arch-reviewer。

---

## 8. 与「只问不修 / 确认门」

| 状态 | 允许 |
|------|------|
| 决策卡已出、用户未答 | 讨论方案、补发散检索；**不写业务修复** |
| 用户选 5 | 只留卡与债 |
| 用户选 1/2/3/4 | 按上表执行 |
| 用户开场已授权批量 | 仍出卡摘要，再 go-fast |
