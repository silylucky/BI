# Severity Rubric

判定时先问：**会不会让运维/用户以为系统正常或功能已交付，或在生产静默做错事？** 会 → 倾向 P0。

与 SKILL「严重度总则」「门禁分流」「宣称判据」冲突时，以 **SKILL + 本文件升级表** 为准；catalog 举例服从本表级别。

## P0 — 必须修才能宣称生产可用

- **任何非测试 stub/mock/假成功路径**（含 env/flag/`profile=dev` 才开启的）——开关不能降级
- 假绿：成功态来自 stub/mock/固定返回值/假 KPI
- **隐式假通**：已宣称对接的外部依赖无真实端点 smoke 工件、或 smoke 打的是本地 mock；写操作重试无幂等键；错误被吞后上游按成功继续（catalog §8）
- **证据矛盾**：某片被宣称完成但 `gate-check slice/batch` FAIL，或用例数较前轮下降
- 有入口的半成品：常驻骨架、假数据列表、主 CTA 无真实交互、提交只 toast
- **进程门禁**：生产可启动且使用仓库已知默认密钥，或 RejectDevDefaults / Validate **已写未调用** / 缺失
- 默认编排（compose/helm 默认 values）已把 stub 开关或已知 dev 密钥打进准生产路径
- 租户/权限隔离漏洞（跨租户读或执行）
- SQL/命令注入、路径遍历、敏感操作越权（IDOR）（catalog §15）
- API 向客户端返回堆栈/SQL/内部路径（catalog §11）
- 已「宣称」的能力实际 `NotImplemented` 或必失败，却仍暴露入口（宣称判据见 SKILL）
- **宣称 HA / 多副本**，但会话、任务队列或 leader 态仅进程内存 / 本地盘（catalog §18）
- 主路径无界全表拉取/导出，流量或数据量上来必炸（catalog §17）

## P1 — 上线前应规划并尽量修完

- 服务端已有能力，但**已宣称**的客户端全端无入口（或某宣称端缺失）
- 坏表单：主路径依赖手填 path / 原始 JSON / YAML；**缺必填标记/字段错误/对齐**；**复杂表单无分区**（catalog §4、§13）
- 多库架构下 SQL/迁移方言不兼容（catalog §9）
- 关键路径日志分类缺失（请求/作业/审计）（catalog §10）
- API 无标准信封或业务错误无统一码（catalog §11）
- 用户可见文案研发口吻/字段名/甲乙方/内部编号上屏（catalog §12）
- 嵌套边框组件无间距导致双描边（catalog §14）
- 同产品 UI 风格明显不一致（页头/空态/分层）
- 可靠性默认值危险：进程内队列、all-in-one 当生产、retention 永 dry-run、吞错无观测
- 无公开 health/ready
- Live 路径硬编码内网 IP；默认指向 fixture/tmp 资源路径
- 水平扩展拓扑与默认配置矛盾（单机 DB/本地存储当多副本）
- **热路径性能放大**（无分页/N+1/无界 fan-out/锁内 I/O）（catalog §17）
- **宣称 HA 下的假高可用 / HA 性能串行化**（内存会话、本地盘队列、每副本全量扫、连接池×replicas）（catalog §18）
- **CI / 部署门禁**未拦截 dev values（进程内 Validate 已接线则不升 P0）
- 有入口但次要交互残缺（不影响主路径闭环时可 P1；主路径残缺升 P0）
- 外部调用无超时 / 无退避重试 / 契约参数硬编码无出处（支付扣费类升 P0）
- **测试 mock 掉被测对象本身**，用例实际什么都没验证（catalog §1.1）
- 外部参数未校验、批量赋值、竞态重复提交（catalog §15）
- CSRF/CORS 明显误配（catalog §15）

## P2 — 记录跟踪，不阻断「最小生产」

- 未引用的死代码 / 空文件（确认无路由、无菜单、无文档宣称）
- 文档与配置字段名漂移
- 版本元数据无意义（`0.0.0` / `*-dev` 未由构建注入）——**除非**已对外发布包仍如此且文档宣称正式版，再升 P1
- 预期的首次 seed 超管（可加「首次改密」文档项；**勿**当安全漏洞标题）
- 未宣称可用、且全端无入口的规划缺口
- 无入口/放大机制锚点的性能疑点（勿升 P1）

**不进 findings（非问题）**：测试双里的**边界 fake**（外部 HTTP/SDK/时钟/随机数/容器替身）、fixture、以及**仅** Storybook/设计系统 demo、不会被产品路由挂上的 mock。豁免边界见 [catalog §1.1](finding-catalog.md)。无压测数字、无代码锚点的「扛不住流量」臆测。

## 升级 / 降级

上文分级已覆盖的不重复；只列容易判错的边界：

| 条件 | 动作 |
|------|------|
| 默认密钥 + Validate 已调用且 prod env 拒绝启动 | → 不报或 P2「勿拷贝 dev yaml」 |
| 默认密钥 + Validate 未接线 / 缺失 | → **P0** |
| CI 未拦 dev values，但进程门禁已拒绝 dev 密钥 | → P1（部署卫生） |
| 坏 YAML 表单但是「高级」折叠且主路径是结构化向导 | → P2 |
| 坏 YAML 表单是创建流水线的唯一方式 | → P1（可升 P0 若默认 echo 假绿） |
| 有仓外调用但**未宣称**已对接、入口已撤 | → P1（缺 smoke）；已 `park` 且文档未宣称 → P2 |
| 测试 mock 的是被测对象的**外部依赖** | → 不报（合法边界 fake） |
| `ha_mode: single` 且文档一致仅单机 | → 不报「缺 HA」；仍可报 §17 热路径 |
| `ha_mode: claimed` 但会话仅内存 | → **P0**（假 HA） |
| 列表无分页但是内部 admin 且有危险确认 + 非默认入口 | → P2 |

**禁止降级**：不得以「有显式开关」「已标 Badge」「仅 dev profile」把 stub 降为非问题或 P2；不得因「本轮没扫到」把某 lane 记为无发现（见 SKILL 硬规则 10）。
