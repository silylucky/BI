# Create Evolution Plan（人工交互）

## 何时使用

- 用户手动触发，为自动化演化设置阶段性人工干预（里程碑与顺序）
- SOP 中「禁止创建/修改 plan.md」约束的是**演化流程内 subagent**；人工干预统一经本 skill
- 典型时机：项目启动排期、picker 回传 `SATURATED`（评分饱和）、方向调整
- **例外 · `honest-writeback`**：仅 [loop-goal-prd](../loop-goal-prd/SKILL.md) / [go-fast](../go-fast/SKILL.md) 在合回且真实验收后，按下方子集勾选对应 plan 行

## 生产姿态（全程强制）

`plan.md` 只编排**可真实交付的生产能力顺序**，不编排演示稿或假完成。

| 禁止 | 要求 |
|------|------|
| 里程碑目标写成「先出骨架 / demo / MVP 可演示」 | 目标写成「真实主路径可用」；范围可小，标准不降 |
| 把 stub 接通、mock 适配器、假绿路径当完成项 | 完成项 = prd 验收在真实依赖下通过 |
| 「契约/骨架/首条路径」中的**骨架占位**当独立可勾选项 | 允许**窄而真实**的首条生产路径；禁止只有接口壳、无真实实现的勾选 |
| 为赶进度把假实现排进当前节并预期勾选 | STUCK 时优先收敛真实范围或拆真实启动切片，不引入假服务 |

**启动切片定义（替换旧「骨架」说法）**：在完整范围暂时无法单轮可靠框定时，拆出的最小切片必须仍是**端到端真实路径**（真实存储/真实外部依赖/真实失败语义），并能独立按 PRD 验收；不得以空壳 API、内存假后端、固定成功响应冒充完成。

## 文档定位

`docs/automate/plan.md` 是自我演化的**人工顺序干预层**，回答「先做哪些 PRD 项、按什么阶段推进、什么时候需要人工改方向」。它不新增需求事实，不替代 PRD；每一行必须映射到已有 prd ID。

| 文档 | 定位 | 本 skill 是否修改 |
|------|------|------------------|
| `goal.md` | 产品方向与边界 | 否 |
| `prd.md` + `prd/*.md` | 功能真理源与状态 | 只在迁移内嵌里程碑时缩短 hub 里程碑节 |
| `plan.md` | 人工里程碑、优先顺序、当前节 | 是 |
| `evolution-state.md` | STUCK 计数、待办池、当前轮次 | 只读，用于建议 |

## 工作模式

| 模式 | 触发 | 输出 |
|------|------|------|
| 新建 | `plan.md` 不存在 | 完整里程碑计划 |
| 体检 | `plan.md` 已存在 | 质量评分 + 对账清单 + 调整建议 |
| 干预 | STUCK / SATURATED / 方向调整 | 重排、插入或拆分里程碑 |
| 迁移 | PRD hub 内嵌里程碑 | 独立 `plan.md` + hub 引用行 |
| **honest-writeback** | loop-goal-prd / go-fast 合回且真实验收后 | 仅将对应 prd ID 行 `[ ]` → `[x]` 并注完成日；见下节 |

## mode: honest-writeback（loop / go-fast 专用子集）

**允许**：

- 对已真实验收的 prd ID：`- [ ]` → `- [x] …（完成于 YYYY-MM-DD）`
- 假绿/未通过：保持未勾选；若先前误勾 → **反勾**并注明原因（可在修订记录或 ledger 记一笔）

**禁止**：

- 重排节、插入新里程碑、拆分/合并节、改节目标措辞
- 新增无 prd 映射的自由文本任务
- 未经真实验收勾选；用 stub/骨架冒充完成

**写者**：默认 go-fast（编排契约 §3）；编排方校验，漏写可按本子集补写。  
**无需**用户预览确认（已过合回+相关测门）。与 P5 自动勾选兼容：同一诚实标准。

## plan.md 结构

```markdown
# 演化里程碑计划

> 人工维护（create-evolution-plan）；演化 agent 只读。
> 当前节 = 第一个含未完成 `[ ]` 的节。
> 约束：每项完成须满足对应 PRD 真实验收；禁止 stub/mock/假绿/MVP demo 勾选。

## M1 — <里程碑名>

**目标**：<一句话，须是生产可用结果，不是「可演示」>

- [x] <prd ID>: <名称>（完成于 YYYY-MM-DD）
- [ ] <prd ID>: <名称>

## M2 — <里程碑名>
…
```

## 首次创建（plan.md 不存在）

1. 读 `goal.md` + `prd.md`（hub 的功能索引、薄弱项汇总与依赖性评分）+ `evolution-state.md`（待办池与 STUCK 计数）
2. 提议里程碑分节：每节 = 节号 + 目标一句话 + prd ID 勾选清单
3. 说明排序依据：goal 优先级、PRD 薄弱项、STUCK、依赖关系、风险控制、**真实路径可交付性**
4. 检查提议项的 PRD 验收是否含 mock/stub/demo 完成定义 → 有则先提示修订 PRD，再排入 plan
5. **交互循环**：用户增删项 / 重排节 / 改目标 → 重新呈现完整 plan → 直到用户确认
6. 写入前展示完整预览，确认后写入 `docs/automate/plan.md`
7. **用语对齐**：节目标与勾选名称跟 prd 分片规范名一致（不另造「演示版 / 临时模块」别名）

## 重复执行（plan.md 已存在）

1. 对照 prd 分片状态，汇报各节完成度；分片已「已实现」但 plan 未勾选的 → 提议勾选（仅当验收为真实路径）
2. 读取 `evolution-state.md` 的 STUCK 计数与待办池，标出可能需要人工干预的条目
3. 与用户调整未完成节（增删 prd ID、插入新里程碑节、重排）
4. 若发现里程碑目标或备注含 MVP/demo/骨架/stub → 提议改写为真实交付表述
5. 写入前展示变更摘要与完整 plan 预览，确认后写入；P5 每轮自动勾选已合并项，本 skill 负责结构变更与全量对账纠偏

## 质量评分（100 分）

| 维度 | 分值 | 检查点 |
|------|-----:|--------|
| PRD 映射完整性 | 15 | 每个任务均可定位到 prd ID |
| 当前节可执行性 | 15 | 当前节 3-8 项，范围可被 G2 批量选题消化 |
| 排序合理性 | 15 | 与 goal、薄弱项、依赖和风险一致 |
| 生产诚实性 | 20 | 节目标与条目无 stub/骨架/MVP demo 假完成；勾选对应真实验收 |
| 状态一致性 | 15 | plan 勾选与分片状态一致，无已实现未勾选 |
| 人工干预价值 | 10 | 能处理 STUCK/SATURATED/方向调整，而非复制 PRD 全量列表 |
| 格式可维护性 | 10 | 行格式适配 P5 自动勾选，节目标清晰 |

评分解释：

| 分数 | 结论 |
|------|------|
| 90-100 | 可稳定约束 G2 选题顺序 |
| 80-89 | 可用，但当前节或状态对账需小修 |
| 70-79 | 会影响选题质量，建议先人工调整 |
| <70 | 不建议作为无人值守里程碑输入 |

**硬门槛**：当前节目标或条目鼓励 stub/骨架/demo 假完成 → 「生产诚实性」0 分，总分上限 69。

## 人工干预建议

当发现下列信号时，主动给出 2-3 个候选方案供用户选择：

| 信号 | 建议 |
|------|------|
| `SATURATED` | 新增下一阶段**真实能力**目标、扩大业务域、或回到 `create-evolution-goal` 修订方向；禁止用 demo 冲分 |
| 同一 prd ID 连续 STUCK ≥3 | 先看依赖性；依赖性 ≥80 时保留在当前主线并重新收敛完整单轮范围，仍不可控时才拆**真实启动切片**；依赖性较低才考虑降优先级或移入人工专项 |
| 高依赖重项（如 REPO-001） | 不因范围大移出当前节；允许单轮一次性完成。只有当完整范围无法可靠框定时，才拆成「契约对齐 / **窄而真实的首条生产路径** / 测试夹具（仅测试）/ 观测与失败语义」；**禁止**「空壳骨架」独立勾选 |
| 当前节长期未完成 | 拆分当前节，保留 3-5 个最可**真实验收**项 |
| 薄弱项 Top5 与 plan 当前节无交集 | 建议插入薄弱项修复里程碑或解释为什么暂不处理 |
| 已实现项未勾选 | 建议对账勾选，不改变 PRD 状态；若「已实现」实为假绿 → 提示先修 PRD/代码，不勾选 |
| 条目依赖未就绪的外部系统 | 排期接入真实依赖，或把功能留在未实现；**禁止**插入 mock 顶替里程碑；契约不明时先跑 [integration-research](../integration-research/SKILL.md) |

## 迁移模式（prd.md 内嵌里程碑）

检测到 prd.md 含「里程碑」正文节（非引用行）时提议迁移：

1. 内嵌里程碑整理为上述 plan.md 分节结构（完成状态从 prd 分片状态派生为勾选）
2. 迁移时清洗 MVP/demo/骨架措辞，改为生产可用目标句
3. prd.md 该节缩为一行：`里程碑见 docs/automate/plan.md（人工维护，create-evolution-plan）`
4. 用户确认后执行；hub 修订记录追加一条「里程碑迁移至 plan.md」

## 与演化流程的边界

| 场景 | 负责方 |
|------|--------|
| 每轮演化合并后增量勾选 | P5（`evolution-pr-finish`） |
| 首次创建、增删节、重排、改目标 | 本 skill（人工） |
| 全量对账（prd 已实现但 plan 漏勾、格式漂移） | 本 skill 重复执行模式 |
| G1 / G2 / P1–P4 | 只读 plan |

- 演化 subagent **禁止**调用本 skill
- 行格式须与 P5 勾选规则一致：`- [ ] <prd ID>: <名称>` / `- [x] …（完成于 YYYY-MM-DD）`
- P5 勾选前若合并结果实为 stub/假绿，应在演化侧拒绝完成态；本 skill 体检时发现则提议反勾并修 PRD

## 交互式引导问题库

按需使用，一次只问一个：

| 场景 | 问题 |
|------|------|
| 当前节过大 | “下一轮更希望优先交付可靠性、体验，还是架构健康？（均须真实路径，不要 demo）” |
| STUCK | “这个卡住项依赖性是否 ≥80？如果是，本轮能否完整真实完成；如果不能，最小**真实启动切片**是哪一段？” |
| 高依赖重项 | “能否单轮完整完成？若不能，最先交付哪一段端到端真实路径才能解锁其他模块？” |
| 用户想插骨架 | “这个切片有没有真实存储/真实外部调用？若没有，它不能单独进 plan 勾选。” |
| SATURATED | “现在是进入新业务域，还是提高已有功能的非功能质量？” |
| 状态不一致 | “PRD 分片显示已实现，但 plan 未勾选；该实现是否走真实依赖？是则对账勾选，否则先降 PRD 状态。” |
| 新增里程碑 | “这个里程碑的完成信号是什么？哪些 prd ID 在真实验收下代表完成？” |

## 红线

- 每节列出的 prd ID 须可在 hub 定位（8 维总表，或功能索引指向的分片）；完全不存在 → 先提示走 `create-evolution-prd` 补条目；仅功能索引缺行 → 本 skill 顺手补一行索引即可
- 不写与 prd 无映射的自由文本任务
- 写入前必须展示预览并获得确认（**例外**：`honest-writeback`）
- **禁止**演化流程 subagent 调用完整模式（新建/干预/迁移）；P5 勾选与 loop **`honest-writeback`** 除外
- **禁止**`honest-writeback` 重排/发明里程碑或假绿勾选
- **禁止**将 stub / mock 假服务 / 骨架空壳 / MVP·demo 假完成排进里程碑完成定义
- **禁止**用「先假后真」作为排序或拆分理由；拆分只允许窄而真实的生产路径
