# 设计锚 `docs/ui/anchor.md`（基准的基准）

回答一个问题：**这个项目的视觉语言从哪来**。有锚 → AI 照锚做；无锚 → AI 发明，20 个页 20 套。

`layout.md` / `*-ia.md` 写**本仓已经长成什么样**，`anchor.md` 写**它应该像什么、依据是什么**：只有前者会把既有的乱当标准，只有后者会脱离实现。

## 1. 可信度分级（每项必标）

| 级 | 含义 | 谁能给 |
|----|------|--------|
| `confirmed` | 用户确认过，或有外部权威来源（组件库官方文档、公司设计规范、已签字设计稿） | 人 / 外部文档 |
| `inferred` | 从仓内代码或已钉死的外部参考提取，有可点击锚点 | 扫描 |
| `assumed` | 无锚点时的临时假设（含直接套 [craft.md](craft.md) 默认值） | AI，**必须**进报告与 `blockers` |

规则：

- 文件头 `confidence` 取**全文件最低项**。
- `assumed` 项**禁止**升格成 `confirmed`「让文档好看」；也**禁止**在报告里省略。
- `assumed` 的条目**不得**作为 [ui-ux-reviewer](../../ui-ux-reviewer/SKILL.md) 判定「合规 / 可毕业」的依据 —— 那是拿自己的假设给自己发证。

## 2. 模板

```markdown
# UI · 设计锚

| 项 | 内容 |
|----|------|
| type | ui |
| module | anchor |
| status | current |
| confidence | confirmed \| inferred \| assumed（取全文最低项） |
| last_verified | YYYY-MM-DD |
| related | [layout.md](layout.md) · <token 真源路径> |

## 组件库

| 项 | 内容 | 可信度 | 锚点 |
|----|------|--------|------|
| 组件库 + 版本 | shadcn/ui（radix + tailwind v4） | confirmed | `fe/package.json` |
| 图标库 | lucide-react | inferred | `fe/package.json` |
| 补充库 | 表格 / 图表 / 日期各至多一个 | | 已有同类则**禁止**再引第二套 |

## Token 真源

| 类 | 真源文件（唯一） | 可信度 |
|----|------------------|--------|
| 颜色 / 主题 | `fe/src/index.css` | inferred |
| 间距 / 圆角 / 阴影 | `fe/tailwind.config.ts` | inferred |
| 字体与字号阶梯 | `…` | |

**禁止**业务页写死 hex 或自造第二套 spacing；改 token 只改真源文件。本文**不**抄色板。

## 外部参考锚（1–3 条）

| # | 参考（链接或仓内路径） | 锚定层次 | 具体拿走什么 | 可信度 |
|---|------------------------|----------|--------------|--------|
| 1 | shadcn Dashboard 示例 `<url>` | 布局骨架 · 信息密度 | 列表页三段式：页头 / 工具栏 / 表+分页 | confirmed |
| 2 | 公司设计规范 `<url 或路径>` | 交互模式 · 组件选型 | 表单校验时机、危险操作确认 | confirmed |
| 3 | `<竞品截图目录 或 姊妹仓路径>` | 信息密度 | 一屏 KPI 数量档位 | inferred |

## 已定取舍

| 维度 | 取值 | 可信度 | 依据 |
|------|------|--------|------|
| 密度基调 | 标准 / 紧凑 / 宽松 | | 标杆页或外部锚 # |
| 圆角档位 | 小 / 中 / 大（写 token 名，不写 px） | | |
| 阴影档位 | 无 / 轻 / 中 | | |
| 色彩语义 | 成功·警告·危险·中性·主 → token 名 | | |
| 字号阶梯 | 页标题 / 区标题 / 正文 / 辅助 → token 名 | | |

## 未钉死项（必须上报）

| 项 | 现状 | 可信度 | 谁来定 |
|----|------|--------|--------|
| … | 暂用 craft.md 默认 | assumed | 待用户确认 |
```

## 3. 外部参考锚的边界

锚定层次只能取这五类（每条锚必须写明取哪一层）：

| 允许（锚定层次） | 禁止 |
|------------------|------|
| 布局骨架：分几段、什么顺序 | 照抄像素：具体 px / 阴影参数 / 渐变 |
| 信息密度：一屏放多少、KPI 几个 | 抄业务导航文案、模块名、品牌色 |
| 交互模式：校验时机、确认框、反馈位置 | 把参考仓（ark/nex）业务 IA 复制进本仓 |
| 组件选型：这类场景用 Sheet 还是独立页 | 引入参考方的 UI 库来「统一」本仓 |
| 状态与反馈模式：三态与 toast 家族 | 拿外部锚当验收标准（验收看本仓 token 与标杆） |

一句话：**抄结构与判断依据，不抄外观与内容。**「不许照抄像素」不等于「不许有外部依据」—— 没有外部依据就只剩 AI 即兴，那是更坏的一端。

## 4. 「最小基准」的定义（go-fast unattended 缺锚时）

go-fast 无人值守缺 `docs/ui` 时可落**最小基准**，指且仅指下面 6 项。少于这些 = 没有基准，应回传 `BLOCKED`；多于这些 = 在没人确认的情况下扩大臆造面。

| # | 必需项 | 从哪来 | 缺时怎么办 |
|---|--------|--------|-----------|
| 1 | 组件库 + 版本 | `package.json` / 依赖清单 / 用户指定 | 绿地未选型 → 选一个主流库并标 `inferred`；**禁止**写「自研组件库」 |
| 2 | token 真源路径 | 仓内实际文件 | 文件不存在 → 写明本批 S0 将创建的路径，并标 `assumed` |
| 3 | ≥1 条外部参考锚 + 锚定层次 | 组件库官方示例页优先 | 无网无文档 → 标 `assumed` 并进 blockers |
| 4 | 密度基调 + 色彩语义映射 | 标杆页 / 外部锚 | 套 craft 默认 → 标 `assumed` |
| 5 | `layout.md`：壳层 + 页模板 + **页头形态**（title-card / flush / minimal）+ 禁止项 | 扫描 ≥3 页判定；见 scan-workflow §4.1 | 绿地 → 由 S0 壳层波次产出后回填，先写「待 S0 落地」 |
| 6 | 本批页面在 `*-ia.md` 的「页菜谱对照」行（含标杆页路径） | 扫描 | 绿地无标杆 → 写「无标杆（绿地），对照外部锚 #N」，**禁止**编造仓内路径 |

**绝对不能凭空填**（无锚点时只能留空或标 `assumed`，不许编）：

| 项 | 原因 |
|----|------|
| 组件库与版本 | 是选型事实，编了实现 subagent 会去装不存在的包 |
| token 真源文件路径 | 必须真实存在或本批真会创建；编路径 = reviewer 校验必挂 |
| 标杆页路径 | 编一个不存在的标杆，全批会围着空气对齐 |
| 具体数值（侧栏宽、圆角 px、色值 hex） | 无代码锚点只写**档位名**，数值由 token 真源决定 |
| 「已确认 / 已评审」类措辞 | unattended 没有人确认过任何东西 |

## 5. 绿地项目怎么建锚（死锁出口）

全新仓没有成熟页可提取，但这不等于只能即兴。按序：

1. **钉组件库与 token 来源** —— 这是**选型**不是发明：读依赖；无依赖则按技术栈选一个主流库，写清版本，标 `inferred`。
2. **从组件库官方示例取布局骨架** —— 作外部锚 #1，层次写「布局骨架 · 信息密度」；官方文档在手可标 `confirmed`。
3. **补公司规范 / 姊妹项目 / 竞品截图**（用户给过时）—— 写清拿走哪一层。
4. **剩下的取舍标 `assumed`** —— 常见是密度基调、圆角阴影档位、字号阶梯；进 `blockers` 与「未钉死项」。
5. **S0 壳层波次落地后回填** —— 壳/模板/共享组件实际路径写回 `layout.md`，首批最完整的一页登记为标杆，可信度升 `inferred`。

**禁止**：跳过 1–2 直接即兴；把 4 的 `assumed` 标成 `confirmed`；拿「最小基准」当借口写整套臆造设计规范。

## 6. attended 与 unattended

| | attended | unattended |
|---|---------|-----------|
| 写入 | Phase 3 预览确认后写 | 直接写，**不停问**，范围收敛到 §4 六项 |
| 可信度 | 确认过的项可标 `confirmed` | 一律只能 `inferred` / `assumed` |
| 未钉死项 | 当场问清 | 进 `blockers` + 报告，**禁止**静默；待下次 attended 或 reviewer 复核 |

unattended 允许写是为了不死锁；代价是**可信度分级 + 强制上报**，缺一就退回自证闭环。
