# 密度 · 交互 · 抛光（做页硬纪律）

配合 [page-design.md](page-design.md)。目标：**信息够用但不堆满、交互有章法、观感干净但不炫技**。  
优先级：`docs/ui/anchor.md` 已定取舍 > 本仓标杆 > 下文默认值。**套下文默认值 = `assumed`**，须按 [anchor.md](anchor.md) §1 上报，不得当成已确认基准。

---

## 1. 信息丰富度（不能太空，也不能太密）

| 过稀（简陋） | 刚好 | 过密（压迫） |
|--------------|------|--------------|
| 大块无意义留白、单列挤在中间 | 一屏主任务清晰，次要可扫到 | 控件贴边、多卡嵌套、表头工具栏塞爆 |
| 只有标题无说明/无操作 | 页头 = **左**标题+说明 · **右**主/次操作（形态跟全站 title-card/flush；主 CTA 可在标题卡右侧） | 页头堆四五个同等实心主按钮；全站标题卡却生成裸 h1；该有右操作却空右侧 |
| 空表「暂无数据」四个字 | 空态：原因 + 主/次 CTA | 空态塞营销长文或假 KPI |

**规则**

1. **一页一个主任务**；次要入口降为 ghost / 次按钮 / 更多菜单。  
2. **首屏只放决策所需**：列表页优先「筛选 + 表 + 分页」；详情优先「身份区 + 关键字段」；其余进 Tab / 折叠 / 次级页。  
3. **同级块间距一致**（见 §5）；不要靠「再加一张 Card」制造层次。  
4. **KPI/摘要 ≤ 一排可扫完**（常见 3–4 个）；更多进「查看全部」或下钻，禁止首屏十二宫格墙。  
5. 优化时问：删掉这块，主任务是否仍可完成？能删则删或降级。

## 2. 交互承载：何时 Dialog / Sheet(抽屉) / 独立页

| 载体 | 用何时 | 不用何时 |
|------|--------|----------|
| **AlertDialog** | 删除、不可逆、权限敏感确认；文案写清后果 | 普通表单、长说明 |
| **Dialog（居中 Modal）** | **短表**（约 ≤5～7 字段）、简单确认+少量输入、轻量预览 | ≥8 字段、多步、高级筛选、需对照背后大表长时间操作 |
| **Sheet / Drawer** | 中等表单、侧滑编辑、筛选面板、需**瞥见背后列表**的上下文编辑 | 极短确认（用 Alert/Dialog）；向导式 3+ 步（倾向独立页） |
| **独立页面** | 长表、多步向导、深详情、需独立 URL/深链/权限刷新、复杂主从 | 两三个字段的小改（勿整页跳转增加成本） |

**同域一致**：同一资源「新建/编辑」载体必须统一（或写进 `docs/ui`）；禁止有的 Dialog、有的整页无理由。

**遮罩**：Dialog 约 20%–30% 黑，Sheet 略浅；禁止 `/80` 闷屏（与 ui-ux-reviewer 一致）。

**层内纪律**

- 有主取消/关闭；提交中禁用主按钮防连点。  
- 成功：关闭层 + **全局反馈**（§4）或回到列表可见新状态。  
- 失败：**表单级**错误优先；全局 toast 作补充，勿只 toast 不标字段。

## 3. 字段必填与校验提示

| 项 | 要求 |
|----|------|
| 必填标记 | 标签旁统一 `*` 或「必填」文案（跟标杆）；勿有的星有的不标 |
| 说明 | 规则不清时用 label 下短 hint（一行）；勿把说明书塞进 placeholder |
| placeholder | 仅示例格式（如 `如：web-prod-01`），**不代替** label，不写「请输入xxx（必填）」 |
| 校验时机 | 提交时必跑；失焦校验可选；**输入过程中**避免每个键都红字闪烁 |
| 错误展示 | 字段下方红字/错误 Token；汇总错误可在表单顶一条；与后端字段错误对齐 |
| 可选块 | 长表用「选填」分组或折叠，降低密度 |

禁止：只靠浏览器原生弹泡、无中文；必填未填却全局 toast「失败」但不标哪一字段。

## 4. 全局消息（Toast / Message）

| 场景 | 做法 |
|------|------|
| 写操作成功 | 短 toast（≤1 行）：做了什么；可跟「查看」链接；自动消失 |
| 写操作失败（无字段归属） | 错误 toast 或页顶 Alert；可重试时给行动 |
| 字段校验失败 | **优先字段下提示**；不要只打一条「请检查表单」 |
| 后台/异步任务 | 进行中用明确状态（行内 Badge/进度）；完成再用 toast，勿静默 |
| 频率 | 同屏短时间合并；禁止连环 5 条成功 toast |

统一走本仓 `toast` / `message` / `notification` API；禁止 `alert()`、禁止每页私写右上角浮层。

## 5. 边距与节奏（组件间距）

**原则：跟 Token / 标杆，不发明第三套 spacing。**

| 层级 | 默认锚点（无标杆时） | 说明 |
|------|----------------------|------|
| 页内容区 | `p-4 md:p-6` 或壳规定 | 与 `layout.md` 一致 |
| 块与块（页头↔工具栏↔表） | `gap-4`～`gap-6` | 纵向节奏稳定 |
| 工具栏内控件 | `gap-2`～`gap-3` | 过稀像散装、过密像挤 |
| 表单字段间 | `gap-4`；分组标题与首字段 `gap-2` | 分组用间距或细分割线，勿套卡 |
| 卡片/表面内 | `p-4`～`p-6` | 内外 padding 同菜谱一致 |
| 按钮组 | 主次按钮 `gap-2`；主右或跟标杆 | 危险按钮勿跟主 CTA 同等视觉抢夺 |
| **输入框内** | 跟设计系统 Input 默认；常见 `px-3 py-2` | **禁止**私改某页 Input 的上下左右 padding 制造「更松/更紧」 |
| **页头标题区** | 标题↔副标题 `gap-1`～`gap-1.5`；标题区↔操作 `gap-3`～`gap-4` | 副标题与标题视觉成组，勿标题贴顶、说明飘远 |
| **Label ↔ 控件** | `gap-1.5`～`gap-2` | 跟标杆 Form 壳；禁止 label 与 input 挤成一团或隔半屏 |

**禁止**：同一页混用 `p-2`/`p-8` 无理由；用空 `<div className="h-12">` 硬撑代替体系间距；Card 里再套大 Card 当留白；**绕过共享 Input/PageHeader 在单页覆写内边距**。

## 6. 卡片 / 色调表面

控制台卡片靠**结构 + 语义图标**分层，不靠装饰色条堆「高级感」。

| 要做 | 不要做 |
|------|--------|
| KPI / 入口 / 摘要卡：**带语义色的 icon**（或小色调 icon 底），文案中性 | **大面积卡片顶部色条 / 厚顶边框着色**当主装饰（易俗、难主题化、抢内容） |
| **一层**表面承载主内容；内部分区用 `gap`、细分割线、分组标题 | **卡片套卡片**（外层 Card/圆角白底内再套带边框/底/圆角的 Card 或「表区域框」堆主内容） |
| 需强调时：轻背景 Token（`muted` / 语义浅底）或左边 2～3px 语义条（慎用、同菜谱一致） | 每张卡不同顶栏渐变、重描边、双层阴影 |
| 步骤/清单：同一表面内用编号行 + 状态 + 链接；或**平铺**同级步骤条（无外框再套内框） | 「大白卡片里再并排三张小卡片」当检查清单/引导（典型套卡） |
| 说明/提示：页头下一行 `Alert`/`Callout`（贴内容区，**不再外包一层 Card**） | 内容 Card 里再塞一条带边框灰底「提示条卡片」 |
| **列表页**：页头下**一层**表面内排「工具栏 → 表 → 分页」；表与分页**不要**再包第二层圆角描边框 | **工具栏卡套表格卡**：外层白卡（含搜索/筛选）内再套一圈带边框圆角的「表+分页」框（双层边距+双描边） |

与 §1 一致：不要靠「再加一张 Card」制造层次。套卡与顶栏色条均属过抛/噪点，优先删装饰留结构。

**页头标题卡 ≠ 内容套卡**：若 `docs/ui/layout.md` 全站形态为 `title-card`，页首那一张「icon + 标题 + 说明」共享标题卡是**壳层约定**，必须保留；禁止把它删掉导致全站漂移。禁止的是：**标题卡之下**再套内容大卡、或大卡里再套步骤小卡/提示条卡、或**列表外卡再套表格内框**。

**分层 ≠ 套卡**：工具栏与表需要「分区」时，用同一表面内的 `gap` / 细分割线 / 浅底带宽即可；**禁止**用「外 Card + 内 Card」假装分层。

**反例 A（步骤套卡）**：页主内容已是白底圆角卡片，里面又放「首次发布检查清单」大卡，再并排「1/2/3」三张小卡——应改成：页头 + 一层清单（编号行或同级步骤条）+ 下方表格；去掉外卡或去掉内卡，只留一层。

**反例 B（列表套卡 · 极常见）**：页头下一块大白卡，卡内上方是搜索/筛选，下方再套一层圆角描边框包住表头+行+分页——双层边框与双重 padding 即套卡。应改成：要么整页一层表面（筛+表+分页同卡、表无第二描边），要么表区平铺无内框（仅用分割线与工具栏分开）。

## 7. 详情页：默认只读 → 编辑按钮 → 可编辑

菜谱 E（详情）默认交互：

1. **进入详情 = 只读**：DescriptionList / 只读字段展示；主操作区给「编辑」（及删/其它次要）。  
2. **点编辑后**才进入可编辑：同页切 edit mode、或 Sheet/独立编辑路由——跟同域标杆。  
3. **新建页**（`/new`）例外：可直接表单态；成功后进只读详情或回列表。

**禁止**：打开已有资源详情就直接是满屏可改表单（易误改、无「我在看什么」心智）。  
权限无编辑权 → 不展示编辑入口（诚实只读），勿灰掉仍可点。

## 8. 用户向文案（副标题 · 提示 · 空态 · 按钮 · 校验 · toast）

凡**用户能在产品界面里读到的字**（页头副标题、字段 label/hint、空态、按钮、校验错误、toast、确认框、菜单名、列标题、帮助短句、Alert/Callout）—— **站终端用户 / 客户**写，不站研发、运维、售前合同或内部交付流程。

go-fast / loop-* 实现片**生成或改写**这类文案时同此条；技术真名留给代码、日志、「技术详情」折叠与开发者文档。

| 表面 | 要写 | 禁止写进用户主路径文案 |
|------|------|------------------------|
| 页头副标题 / description / Alert | 这页能完成什么任务、注意什么、证据从哪来 | 内部状态机变迁、流水线步骤码、服务名堆砌、**实现术语**、**合同/项目角色口吻**（见下） |
| 字段 label / hint / 空态 | **人话**下一步（从哪进、点哪个按钮、缺什么业务对象） | 后台枚举码、`STA-00X` / `ERR_*`、topic 名、表名、API path、**请求/查询参数名**、**snake_case / camelCase 字段名**（如 `ci_id`、`stree_node_id`、`userId`）、内部模块缩写当主句 |
| 按钮 / 菜单 / 列标题 | 动词 + 业务对象（「提交变更」「导出清单」） | 把接口名、命令名、工单 ID、技术动作当按钮字（「Invoke sync」「跑 gate」） |
| 校验 / toast / 确认框 | 发生了什么、用户能做什么 | 堆栈摘要、HTTP 状态当主句、把异常类型名甩给用户 |
| 状态展示 | 人话（「处理中」「已完成」「失败，可重试」） | 把原始 status code 当主文案；码仅可进「技术详情」折叠（高级排障） |

**也禁止（内部术语 / 研发黑话上屏）**：ADR、PRD、plan 勾选、worktree、stub/mock、假绿、seam、blast radius、subagent、ledger、orchestrator、Path A/B、fleet、evidence、gate-check、RFC 编号当说明、把仓库路径/包名当界面句子。产品里应说业务事（「变更单」「审批人」「还缺配置」），不说工程工序。

**也禁止（合同 / 项目交付口吻上屏）**：面向**客户在用的产品**时，界面禁止写 **甲方 / 乙方 / 丙方**、我方/贵方、招标/验收口径堆砌、交付边界免责声明体（「由××基建承担；禁止用××冒充××」这种对内纪律句）。那是合同或内部跑数纪律，不是给操作员看的产品说明。

| 反例（合同口吻） | 应写成（客户产品口吻） |
|------------------|------------------------|
| 「数据复制/同步由**甲方**基建承担；本页通过探测 lag/心跳提供 RPO 证据，禁止用切换成功冒充同步时延。」 | 「复制与同步在基础设施侧完成。本页展示探测到的延迟与心跳，用作恢复点参考；切换成功不代表数据已追平。」 |

**典型翻车（空态）**：写「请带上 `ci_id` 开会话 / 从某某带 `stree_node_id`」——客户看不懂参数名。应写成：「请先打开某个配置项，再点「远程」；或从服务树成员行发起远程。」参数名只留在路由实现与开发者文档。

**自检句**：不懂你们内部缩写、也没见过 API 字段表 / 研发流程 / **合同角色**的业务用户，能否只靠屏幕文案完成任务？不能 → 改文案，勿指望用户读码表、猜字段名、或把自己当成「甲方」。

**允许**：高级折叠「技术详情」里放原始码/字段名（默认收起）；开发者专用页（明确标受众）可例外；**对话里对编排方/ledger 的工程术语**不在此限（那不是产品 UI）。

## 9. 抛光 · 过抛 · 简陋

### 何谓抛光（要做）

- 统一页头、工具栏分层、表/分页对齐标杆  
- 空/错/载三态齐全且文案可读（§8 用户向）  
- 主按钮 loading、防连点；删除红+确认  
- 状态分色（非一片蓝）；走 Token；卡片用语义 icon（§6）  
- 详情默认只读（§7）  
- 对齐、截断（`truncate`+tooltip）、数字/时间格式统一  

### 避免抛光过度（不要做）

| 过抛 | 为何有害 | 改回 |
|------|----------|------|
| 重阴影、大渐变、玻璃拟态堆叠 | 噪、与控制台气质冲突 | 扁平/轻表面，跟设计系统 |
| 处处微动效、无意义 skeleton 循环 | 慢、假精致 | 仅加载与状态切换短反馈 |
| 为「好看」加双层卡片、装饰线、图标墙、**卡片大面积顶边着色** | 密度假高、主任务被抢 | 删装饰；语义靠 icon / 轻底（§6） |
| 自定义一套间距/圆角「更精致」 | 与邻页漂移 | 锁 Token |
| 文案玩梗、中英混排炫技 | 不专业 | 产品语言（§8） |

### 避免简陋 / 粗糙（不要做成）

| 简陋信号 | 修法 |
|----------|------|
| 裸 h1 + 按钮散落 | 标准 PageHeader |
| 原生 select/button、灰链无层次 | 设计系统基元 |
| 表格无分页/无空态/错误甩 stack | 统一壳 |
| 必填无标、失败只 console | §3 §4 |
| 大片留白或控件贴死 | §1 §5 |
| 行操作实心蓝钮一排 | **ghost** 幽灵按钮 + `…` + 删除红（与页头 solid 主 CTA 分工） |
| 详情一进就是编辑态 | §7 |
| 副标题/提示/空态塞内部码、字段名、或「甲方」等合同口吻 | §8 |
| 大卡套小卡步骤清单 / 内容区再套提示条卡 | §6 |

**口诀**：先对齐标杆结构，再补齐状态与反馈；**加料前先问是否帮主任务**；**文案先问用户懂不懂（别把客户写成甲方）**。

## 10. 设计卡补充字段

在 page-design 设计卡上追加：

```text
密度: 标准（对标 <标杆页>）| 偏紧 | 偏松（须理由）
承载: 新建=…; 编辑=…; 删除=AlertDialog
详情模式: 只读默认 + 编辑按钮（新建页除外）
卡片: 语义 icon；禁套卡（含大卡套步骤小卡、内容区再套提示条卡、**列表外卡再套表格内框**）；禁大面积顶边着色
必填: 星号+提交校验+字段下错误
反馈: 成功=toast; 失败=字段优先+toast 补充
间距: 跟标杆 / Token（含 Input/页头内边距，不新造）
文案: 用户向人话；禁甲方/乙方等合同口吻；禁内部码/字段名/工程黑话进副标题·hint·空态·Alert·按钮·toast
抛光: 对齐结构+三态；不做渐变/重阴影/图标墙
```

## 11. 自检加项

- [ ] 首屏无信息墙、无空洞装饰留白  
- [ ] Dialog/Sheet/独立页选型符合 §2 且同域一致  
- [ ] 必填与错误提示符合 §3  
- [ ] 全局反馈走统一 toast，无 `alert`  
- [ ] 间距节奏与标杆一致（含输入框/标题区内边距，§5）  
- [ ] 卡片：有语义 icon 分层；无套卡（含大卡套步骤小卡、内容区再套提示条卡、列表外卡再套表格内框）；无大面积顶边着色（§6）  
- [ ] 详情（非新建）默认只读，经编辑按钮才可改（§7）  
- [ ] 用户可见文案为人话：无甲方/乙方等合同口吻、无内部状态码、无字段名/查询参数名作主句、无工程黑话上屏（§8）  
- [ ] 无过抛信号、无简陋信号（§9）
