# 做页 / 改页设计步骤（消费 `docs/ui`）

本流程给 **go-fast、ui-ux-reviewer 修复批次、或任何写前端的 agent**。  
前提：目标仓已有可用的 `docs/ui/`（没有 → 先跑主 Skill 提取）。

**密度 / 抽屉·Modal·独立页 / 必填提示 / 全局消息 / 间距 / 卡片表面 / 详情只读 / 用户向文案 / 抛光** → 必读 [craft.md](craft.md)。

---

## A. 新做一页

按序执行，**不可跳步开写 JSX/模板**。

### 1. 读基准（必读）

| 顺序 | 读什么 | 拿走什么 |
|------|--------|----------|
| 0 | `docs/ui/anchor.md` | 组件库、token 真源、外部参考锚与**锚定层次**、已定取舍、各项**可信度** |
| 1 | `docs/ui/layout.md` | 落在哪个域壳、内容区节奏、可用页面模板、**页头形态**（title-card / flush / minimal）、**禁止项** |
| 2 | 对应 `docs/ui/*-ia.md` | 导航归属、权限表面、同域标杆与菜谱 |
| 3 | layout/IA 链出的设计系统 / `fe-ui` / `components/README` | 用哪些基元，禁止手写 button/input |
| 4 | **标杆页源码**（IA 表里的路径） | 页头（是否标题卡）、工具栏、空错态、**密度与间距**的实装方式 |
| 5 | [craft.md](craft.md) | 信息量、承载、间距、卡片、详情只读、用户向文案、抛光 |

缺基准时按下表走，**禁止**自由发挥、**禁止**跳过 0 直接开写：

| 缺什么 | attended | unattended（不许停） |
|--------|----------|---------------------|
| 缺 `anchor.md` | 停 → 跑 create-ui-docs 或请用户点名锚 | 按 [anchor.md](anchor.md) §4 落最小基准，`assumed` 项进 blockers |
| 缺 layout/IA | 同上 | 同上；壳与模板待 S0 波次落地后回填 |
| 缺标杆页（绿地） | 请用户点名参照 | 用外部参考锚的骨架，标 `assumed`；本页做成后登记为首个标杆 |

无锚时**只能**套 [craft.md](craft.md) 默认值 —— 那是 `assumed`，不是基准，必须上报，且不得据此宣称合规。

### 2. 定菜谱（先分类再布局）

对照 IA「页菜谱对照」或 ui-ux-reviewer 菜谱 A–F：

| 问自己 | 动作 |
|--------|------|
| 这一页更像列表 / 详情 / 仪表 / 作用域 Tab / 树+详 / 规则编辑？ | 选定**一个**主菜谱 |
| 同菜谱标杆是哪一页？ | 写下路径，实现时逐块对齐 |
| CRUD 放哪？ | 按 [craft.md](craft.md) §2：短表 Dialog、中表 Sheet、长表/深链独立页；**与同域标杆一致** |
| 信息是否过满/过空？ | 按 craft §1 砍块或补全页头/空态，勿靠套卡凑密度 |

输出设计卡（可写在 PR/回复里）：

```text
路由: /…
壳: <layout 名>
页头形态: title-card | flush | minimal   # 抄自 layout.md
页头组件: <…>
页头右操作: 主CTA=solid×1；次要=outline/ghost   # 标杆有右操作则本页必须有槽位，勿把主入口只塞表工具栏
列表行操作: ghost；>4→…；删除红+确认   # 禁止行内实心蓝钮
菜谱: B 列表
标杆: fe/src/pages/…/AssetList.tsx
模板: TableListPage（或等价）
CRUD: 新建=Dialog；编辑=Sheet；删除=AlertDialog+destructive
详情模式: 只读默认 + 编辑按钮（/new 除外）
密度: 标准（对标标杆）
卡片: 语义 icon；禁套卡；禁大面积顶边着色（页头标题卡不算内容套卡）
必填: 星号 + 提交校验 + 字段下错误
反馈: 成功 toast；失败字段优先
文案: 用户向人话；禁内部码/字段名/查询参数名/工程黑话/甲方进副标题/hint/空态/按钮/toast
权限: 无权限 → 诚实空态（非假可点）
抛光: 结构+三态；无渐变/重阴影/图标墙
```

### 3. 组页面（只拼已有壳）

1. **套域壳** — 不新建第二套侧栏/顶栏。  
2. **套页面模板/共享壳** — PageShell / TableListPage / 本仓 Header+列表壳；**页头必须用 layout 登记的形态与组件**（`title-card` 仓勿省略标题卡；标杆有**右侧按钮**则页头右槽必须能放主/次 CTA；`flush` 仓勿硬加标题卡）。禁止页内重写等价物。  
3. **块顺序跟标杆** — 典型列表：页头（含右操作）→ 工具栏（左搜筛 / 次要筛选）→ 表 → 分页；**一层**表面，勿卡片套卡片（禁「外卡含筛选 + 内框包表/分页」）；散装筛选禁；KPI 用语义 icon，禁大面积顶边着色（craft §6）。  
4. **控制信息量** — 首屏只保主任务；次要进 Tab/折叠/`…`（craft §1）。  
5. **基元走设计系统** — Button/Input/Badge/Dialog 等；无硬编码 hex。  
6. **间距跟 Token/标杆** — 块间 `gap-4`～`gap-6`；Input/页头内边距跟共享壳（craft §5）；禁止同页乱套 padding。  
7. **行操作** — **幽灵按钮 ghost**（无实心底、hover 浅底）；>4 → `…`；删除红 + 确认。**禁止**行内实心 Primary 一排（与页头主 CTA 抢视觉）。  
8. **表单 / 详情** — 必填标记、hint、字段级错误（craft §3）；**已有资源详情默认只读**（craft §7）；提交中防连点。  
9. **空 / 错 / 加载 / 全局反馈** — PageState 对齐标杆；成功/失败 toast 走统一 API（craft §4）；副标题与 hint **用户向人话**（craft §8：禁字段名/查询参数名/工程黑话进主文案）。
10. **挂导航** — 按 IA 写入 nav 真源；无入口的「已实现」不算完成。  
11. **抛光边界** — 做齐结构与反馈；不做过抛装饰；消除简陋信号（craft §9）。

### 4. 自检（提交前）

- [ ] 未违反 `layout.md` 禁止项  
- [ ] 与标杆同菜谱的页头/工具栏/**密度/间距**无明显漂移  
- [ ] 页头形态与 `layout.md` 一致（该有标题卡则有；标杆有右操作则右槽有主/次 CTA；全站 flush 则无硬套卡）  
- [ ] 列表行操作为 ghost（非实心蓝钮一排）；>4 已收进 `…`；删除为红  
- [ ] 无平行手写第二套列表壳/页头  
- [ ] Dialog/Sheet/独立页选型合理且同域一致  
- [ ] 必填与错误提示、全局 toast 符合 craft  
- [ ] 卡片无套卡/无大面积顶边着色；详情（非新建）默认只读  
- [ ] 副标题/hint/空态用户向：无内部状态码、无 `ci_id` 类字段名/查询参数名作主句  
- [ ] 无过抛（重阴影/渐变墙/顶边色条）与无简陋（裸 h1/散装按钮）  
- [ ] 权限与失败态诚实（无假绿 KPI）  
- [ ] 若改了壳/IA/菜谱/密度约定 → **回写** `docs/ui`

## B. 优化已有页（防越改越飘）

### 1. 定性

| 类型 | 做法 |
|------|------|
| **漂移修复** | 对照 `docs/ui` + 同菜谱标杆，列出差集（页头/工具栏/行操作/空态/密度/色）再改 |
| **过密/过稀** | 按 craft §1 做减法或补结构，勿靠加 Card/加留白「调感觉」 |
| **增强功能** | 先保持壳与菜谱不变，只加块；新块仍用共享基元；新表单按 craft §2 选型 |
| **应抽共享** | 同构 ≥2～3 页复制 → 先抽公共壳再改页（见 ui-ux-reviewer 复用纪律） |
| **过抛回退** | 去掉装饰性阴影/动效/图标墙/卡片大面积顶边着色，回到标杆表面 + 语义 icon |

### 2. 改造约束

- **只对齐本仓** `docs/ui` 与标杆；外部锚只能提供骨架/密度/交互/选型层次的依据（见 [anchor.md](anchor.md) §3），禁止借优化引入新 UI 库或照抄外部像素。  
- 出改造方案时写清：菜谱、对标页、改哪些区块、密度意图、**不做清单**（勿顺手改 IA/RBAC 模型）。  
- 改完若成为新标杆 → 更新 IA「页菜谱对照」并改 `last_verified`。

### 3. 优化自检

- [ ] 视觉差变小，而非「另一套好看」  
- [ ] 信息量更合适（非更花或更空）  
- [ ] 无新增硬编码色 / 私有阴影体系  
- [ ] 交互承载与反馈更一致  
- [ ] 文档与代码仍一致

## C. 和谁分工

| 谁 | 职责 |
|----|------|
| create-ui-docs | 产/修 `docs/ui` 基准与设计锚 |
| **本文 + [craft.md](craft.md)** | 做页/改页步骤与密度·交互·抛光纪律 |
| go-fast | 红绿实现；开工前强制走 A/B + craft；把锚与契约写进 implementer-prompt |
| ui-ux-reviewer | 先验基准可信度，再对照基准扫漂移；修复批次仍走 B + craft |

无基准时：**不要**用本文代替创造设计系统——先按 [anchor.md](anchor.md) 钉锚。
