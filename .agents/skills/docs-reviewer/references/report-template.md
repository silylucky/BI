# Report Template（文档评审标准报告）

评审结束必须按此结构输出（Markdown）。标题含项目名与日期。

```markdown
# [项目] 文档完整性评审 · YYYY-MM-DD

## 总览

| 项 | 内容 |
|----|------|
| 范围 | 整仓 / PR·变更面 / 模块… |
| Docs Card | 见下 |
| 扫描方式 | 并行 lane D1… / 主 agent 串行 |
| Blind spots | 无 / Dx：原因… |
| P0 / P1 / P2 | n / n / n |
| 覆盖 | 应有 n · 完整 n · 漂移 n · 缺失 n |
| prd-sync | 合适 / 需改 / 缺失 |
| 建议 | 文档可毕业（仅剩 P2） / 补完 P0 再宣布完整 / 暂缓（含 Blind spot 时不得写可毕业） |

一句话结论：…

### Docs Card（摘要）

- 文档根 / 非标准路径：…
- 代码面：API… · 服务… · UI… · 数据… · mock 痕迹…
- 跳过的 lane：…（原因）

## 覆盖矩阵

| 应有路径 | 类型 | 状态 | 动作 |
|----------|------|------|------|
| `docs/api/…` | api | 缺失 / 漂移 / OK | 新建 / 修补 / — |

（可只详列非 OK；OK 可统计一句带过。）

## 可消费深度（api / domain）

| 路径 | 类型 | 闸门 | 结论 |
|------|------|------|------|
| `docs/api/…` | api | A1–A8：… | 通过 / P1 不可消费（缺…） |
| `docs/domain/…` | domain | D1–D8：… | 通过 / P1 缺 Process Test Pack |

判定标准见 consumable-depth.md。仅有端点名表或领域散文 → 不得标「完整」。

## Blind spots / 未完成 lane

| Lane | 状态 | 说明 |
|------|------|------|
| … | 跳过 / 失败后不足 | … |

（无则写「无」。存在失败 Blind spot 时，不得写「文档可毕业」。）

## prd-sync 结论

| 建议 | 保持 / 创建 / 合并修补（要点…） |

| 证据 | 代码依据 + 文档路径（或应有路径） |
| 为何致命 | 谁会误判或无法上线 |
| 建议修法 | 新建模板类型 X / 改写诚实 mock / 修 prd-sync… |
| 可批量 | 是（批次…）/ 否（需产品确认口径） |
```
