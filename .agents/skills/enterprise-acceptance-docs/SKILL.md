# Enterprise Acceptance Docs（政企验收文档）

技术栈无关。Agent 已会扫代码写文档；本 Skill 补：**模板摄入与标题树对齐**、**证据→政企书面语翻译**、**标杆克隆（非研发脑补结构）**、**可验收红线**、**版式优化（列表/表格/图）**。

与姊妹 skill 分工：工程 `docs/api|adr|…` → [docs-reviewer](../docs-reviewer/SKILL.md)；终端用户帮助 → [user-guide-writer](../user-guide-writer/SKILL.md)；假绿/stub → [code-reviewer](../code-reviewer/SKILL.md)；真机走查 → [browser-reviewer](../browser-reviewer/SKILL.md)。**本 Skill** 产出给验收方与业务领导阅读的终验/设计类材料，不是仓库维护手册。

## 何时启用

| 场景 | 动作 |
|------|------|
| 给定系统仓 + 文档模板（MD/Word/目录提纲） | 摄入模板 → 扫仓 → 按标题树成稿 |
| 已有部分章节、要补齐同风格模块 | **先克隆标杆章**，再填本模块能力 |
| 稿件「太像代码注释」/ 无法预读 | 按文风重译；删路径/函数名墙 |
| 缺流程图、架构图、界面截图 | 出图；可访问环境则真机截图 |
| 多文档同模块（需求+方案+详细设计…） | 能力同源、粒度按文档类型分流 |

**不要**：无模板/无标杆时自创「接口要点 / 错误码附录」结构；把 mock/未交付对端写成已交付；为凑篇幅重复段落。

## 必读顺序（≤3 次）

1. 本文件「硬规则」+「工作流程」
2. [references/template-intake.md](references/template-intake.md) + [references/style-guide.md](references/style-guide.md) + [references/format-optimization.md](references/format-optimization.md)
3. 落笔用 [references/doc-type-profiles.md](references/doc-type-profiles.md)；图与截图 [references/diagram-screenshot.md](references/diagram-screenshot.md)；交稿前 [references/quality-checklist.md](references/quality-checklist.md)。好/坏对照见 [references/examples.md](references/examples.md)

历史项目专用章节号表可另附工作区笔记；**通用默认不以某一固定项目的 01–06 章号为真源**——以用户给定模板目录为准。

## 硬规则

1. **模板标题树为真源**：小节名、层级、编号形态以模板/标杆目录为准；禁止自创尾巴章（补充机制、错误码附录、修订说明…）。
2. **先克隆标杆，再填能力**：同文档最近已完成模块的标题顺序、段落节奏、图位、列表/表格习惯——一并抄结构，不抄业务原句。
3. **证据进脑，正文出政企书面语**：扫描决定写什么/写多深；正文写「谁（角色）→ 做什么 → 状态如何流转 → 如何留痕」。禁止把扫描笔记原样倾倒。
4. **称谓严谨**：禁止「我方 / 甲方 / 你方 / 贵方 / 我们 / 你们」。主语用「系统 / 平台 / 本模块 / 支持… / 管理人员可…」。
5. **禁止代码标识刷屏**：函数名、类名、包路径、HTTP 路径墙、错误码表、DSN、配置键大表默认不进正文（数据库设计类除外，且仍按模板列写字段，不写 ORM 方法名）。
6. **无证据整段不写**：禁止「未对接 / 待确认 / mock / 前端未开放 / 不以××为准」等自我暴露；目录有标题则用已有能力做映射覆盖，不点名未交付对端。
7. **可验收 ≠ 写尽实现**：验收看目录对、能力清、图可读、界面能指认；指标仅写代码/配置/既有需求中出现的数字。
8. **版式服务预读**：优先匹配模板对无序/有序/表格的用法；技术堆砌改写成短段 + 列表 + 对照表。见 [format-optimization.md](references/format-optimization.md)。
9. **图是标杆的一部分**：技术方案/详细设计类标杆有流程图与组成图时，待补模块必须同构；禁止用 Mermaid 源码冒充 Word 终验插图（需栅格图）。
10. **扫描工具**：大规模取证优先读 [code-scanning](../code-scanning/SKILL.md) 三层分诊；有 codegraph 则查调用与影响面，字符串/配置项仍用 rg。只探测不擅自安装。

## 工作流程

```
Task Progress:
- [ ] 1. 定靶：目标文档类型 + 模板路径 + 待写章节/模块范围
- [ ] 2. 摄入模板：抽出标题树、必填节、标杆章、列表/表习惯（template-intake）
- [ ] 3. 拆标杆：同文档已完成模块 → 标题树、图位、段落密度、称谓与版式
- [ ] 4. 扫描系统：边界/主流程/菜单功能/权限/对接/数据模型/非功能数字（无证据省略）
- [ ] 5. 标题匹配：模板叶子 ↔ 能力映射表；缺口用映射覆盖或整节省略（禁暴露）
- [ ] 6. 成稿：按文档类型粒度翻译；优化列表/表格；02/05 类同步出流程/架构图
- [ ] 7. 可访问环境：真机截图嵌入；不可访问则图题占位，不伪称已截
- [ ] 8. 自检：style-guide + quality-checklist；禁写项扫描
- [ ] 9. 落盘；有 Word 合并管线则重合并并抽检目录与插图
```

### 证据不足时

| 情况 | 交付正文 |
|------|----------|
| 代码无该能力 | **整段不写** |
| 目录有细分标题、代码是能力映射 | 保留目录标题，写清如何覆盖 |
| 仅有通用扩展口 | 只写已有接口含义，不点名未对接对端 |
| 后端有、界面未开放 | **只写界面已开放项** |
| RTO/RPO 等 SLA | 写探测/切换日志等**证据口径**，勿无据硬承诺，勿「未保证」自曝 |

### 内部对照（勿进交付正文）

作者自用：mock 开关、联调替身、未开放菜单、未对接系统名、真实 SLA 缺口——可记笔记，**默认不进 Word/终验稿**。

## 分步要点

### 1. 定靶与模板摄入

用户须给出（缺一则先问清再写）：

- 系统代码/配置根（可多仓）
- 文档模板或已有半成品（目录全文或标杆 docx/md）
- 本次范围（哪几章 / 哪几个业务模块）

产出 **Template Card**（见 [template-intake.md](references/template-intake.md)）：文档类型、标题树、标杆节、版式线索、深度期望。

### 2. 对齐标杆（强制）

| 抄什么 | 不抄什么 |
|--------|----------|
| 小节标题顺序与命名 | 他模块业务事实 |
| 段落节奏（总起 → 加粗小标题 → 短段 → 图） | 假截图 |
| 图出现位置 | 双重编号 |
| 列表/表格列名习惯 | 「我们/甲方」等称谓（标杆若有，改写掉） |

常见文档类型的合格深度见 [doc-type-profiles.md](references/doc-type-profiles.md)。

### 3. 代码扫描清单（证据用）

1. 模块边界 → 文档小节标题  
2. 主流程 / 状态流转 / 审批链 → **角色叙事**（不写枚举码表）  
3. 功能点：菜单与页面操作  
4. 校验与权限（需求类可保留产品提示原文）  
5. 外部对接（有证据才写系统名）  
6. 数据模型（数据库设计类）  
7. 非功能数字（有据才写）  

入口：`README`、`docs`、OpenAPI、路由、菜单/IA、migrations、Compose/Helm、CI。大规模扫描遵循 code-scanning。

### 4. 翻译与版式

见 [style-guide.md](references/style-guide.md) + [format-optimization.md](references/format-optimization.md)。

| 扫描到的 | 正文应写成 | 禁止 |
|----------|------------|------|
| 状态枚举 `open/merged` | 合并请求可合入或关闭，过程可追溯 | 状态机码表墙 |
| 路由 `/api/v1/...` | 提供××管理能力 | REST 路径表 |
| 函数 `SubmitPullRequest` | （不出现）用业务动作描述 | 方法名清单 |
| 错误码 `SCAN_GATE_*` | 门禁未通过时不得合入/发布 | 错误码附录 |
| `mock` 适配器 | （不写） | 生产能力清单含 mock |

### 5. 图与截图

见 [diagram-screenshot.md](references/diagram-screenshot.md)。技术方案/详细设计：每模块至少业务流程泳道图 + 模块组成/分层图（若标杆有）。界面节：真机图或诚实图题占位。

### 6. 交付

- 标题层级与模板编号一致；避免手写编号 + 样式自动编号双重编号  
- 「代码依据」路径列表可附给用户核对，**默认不进终验正文**  
- 不擅自改标杆已完成章节  
- 交稿前跑 [quality-checklist.md](references/quality-checklist.md)

## 模块边界（多系统同稿时）

写某一模块时只写其职责闭环；勿把相邻系统的监控/台账/发布/告警入口混写成同一节。能力交叉处用「协同 / 对接」一句带过，细节归所属模块章。
