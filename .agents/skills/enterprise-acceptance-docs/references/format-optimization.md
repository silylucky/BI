# 版式优化（标题 · 列表 · 表格）

目标：验收材料**可扫读**。先服从模板习惯；模板未规定时按下表优化。

## 标题匹配

1. 叶子标题字面跟随模板（含「描述」等后缀若目录有则保留）。  
2. 加粗小标题（`**环节名**`）用于段内结构，**不替代**应进目录的 Heading。  
3. 需求类「系统功能」下：每个可独立验收的操作面做成**可进目录的功能点**（Heading 再降一级），禁止整节一段到底。  
4. 禁止在正文手写与样式冲突的完整章号串（易双重编号）。

## 何时用有序列表

| 适合 | 示例 |
|------|------|
| 主业务流程步骤 | `1、提交申请；2、审批；3、开通；4、归档` |
| 操作先后固定的界面步骤 | 打开菜单 → 填写 → 提交 |
| 验收步骤（若模板要求） | 按序可勾选 |

顿号 `1、` 与点号 `1.` 以**标杆**为准，全文统一。

## 何时用无序列表

| 适合 | 示例 |
|------|------|
| 并列能力/构成 | 子系统构成、权限项、筛选条件 |
| 界面分区要素 | 列表区、筛选区、详情区 |
| 非强制顺序的注意点 | 校验规则要点（需求类） |

避免「每一句都做成子弹」——总起段仍用短段落。

## 何时用表格

| 适合 | 典型列 |
|------|--------|
| 系统对接 | 对接对象、主要内容、对接方式、实时性 |
| 角色权限 | 角色、可执行操作、数据范围 |
| 状态说明（需求类、少量） | 状态、含义、可迁移动作 |
| 数据库字段 | 与模板既有表头完全一致 |
| 图题清单 / MANIFEST | 图号、图题、文件、状态 |

**不要**用表格倾倒：API 路径全集、错误码全集、函数名、配置键缺省值（除非该文档类型标杆本身就是这种表且用户只要对齐）。

## 功能点正文习惯（需求类）

```text
#### 功能点名称
支持…。{角色}可…。
新增：…。
编辑：…。
删除：…。
筛选：支持按…筛选。
```

校验失败提示尽量保留产品**原文**。

## 压缩代码味的改写套路

| 原稿气味 | 改写 |
|----------|------|
| 连续反引号标识符 | 删标识符，留业务动词与宾语 |
| 「调用 XxxService.yyy()」 | 「系统完成××并记录结果」 |
| 「返回 code=…」 | 「失败时提示…并保持可追溯」 |
| 大段 YAML/JSON | 删；必要时一句话说明可配置项类别 |
| 模块英文包名 | 用中文模块名（与目录一致） |

## 密度控制

- 每小节先 **1 句总起**，再列表或 2–4 个加粗块。  
- 单段超过约 8 行且含多种动作 → 拆列表或拆小标题。  
- 同段重复「支持支持支持」→ 合并为一条「支持 A、B、C」。  
- 禁止为凑篇幅复制上节改数字。
