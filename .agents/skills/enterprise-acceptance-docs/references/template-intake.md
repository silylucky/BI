# 模板摄入（任意系统 · 任意模板）

每次任务先产出 **Template Card**（可极短，写在草稿头），再扫描与成稿。

## Template Card 字段

| 字段 | 说明 |
|------|------|
| `doc_type` | 需求 / 技术方案 / 详细设计 / 初步设计 / 集成实施 / 数据库 / 其他（写原文名） |
| `template_paths` | 模板或半成品路径（md/docx/目录导出） |
| `title_tree` | 从模板抽出的待写标题树（含编号形态） |
| `benchmark_section` | 同文档已完成标杆节路径与标题 |
| `required_leaves` | 目录要求必须出现的叶子（如「业务流程」「系统功能」下功能点） |
| `format_hints` | 标杆用的列表符号、表头列名、图题句式、「以下为…界面示意」等 |
| `depth_bar` | 合格深度（对照 [doc-type-profiles.md](doc-type-profiles.md)） |
| `systems` | 本次代码仓与模块边界 |
| `scope` | 本次只写哪些章/模块 |
| `merge_pipeline` | 若有 MD→Word 合并脚本则记下入口 |

## 摄入步骤

1. **打开模板全文目录**（Word：大纲/导航窗格；MD：全部 `#` 标题）。  
2. **锁定标杆章**：同类型最近已完成模块；记下其下三级标题名（勿改名）。  
3. **识别必填模式**：  
   - 是否要求「系统功能」下再拆可进目录的功能点？  
   - 是否有「界面示例 / 页面设计」？  
   - 对接表固定列名是什么？  
   - 数据库表用何种列（字段/类型/空/主键/描述…）？  
4. **版式取样**：标杆用 `1、2、` 还是 `1. 2.`；功能操作用 `新增：` 还是无序列表；加粗小标题是否成段首。  
5. **称谓取样**：若标杆出现「我方/甲方」，成稿时**统一改掉**（见 style-guide），不要复制合同对抗语气进验收正文。  
6. **产出映射表**（内部）：`模板叶子标题 → 拟覆盖的产品能力（一句话）→ 证据来源（文件/菜单，不进正文）`。

## 标题匹配规则

| 情况 | 处理 |
|------|------|
| 模板叶子与代码能力一一对应 | 按叶子成稿 |
| 模板细分多于代码实体 | 保留叶子标题，用「能力映射」叙述覆盖，不写「无独立子系统」 |
| 代码有能力、模板无叶子 | **不擅自加章**；除非用户要求扩目录 |
| 模板标题过时/错名 | 以模板为准写标题；正文用正确业务名解释一次；或请示用户改目录 |

## 多模板并行

一次补多份文档（如需求+技术方案+详细设计）时：

1. 先建**能力真相表**（模块 → 流程要点 → 功能点 → 对接 → 表）——只做内部笔记。  
2. 再按各模板标题树分别灌入，粒度见 doc-type-profiles。  
3. **禁止**把详细设计的路径级内容粘进技术方案标杆位。

## 无标杆时

仅有空模板提纲、同文档无已完成章：

1. 用 [doc-type-profiles.md](doc-type-profiles.md) 默认骨架。  
2. 仍禁止自创「错误码附录」等尾巴。  
3. 首章写成后请用户确认为标杆，再批量其余模块。
