# 调研简报模板

写入 `docs/integrations/<slug>.md`。方括号为占位；未知写「待确认」，禁止臆造端点。


```markdown
# 集成简报：<依赖显示名>

| 字段 | 值 |
|------|-----|
| slug | `<slug>` |
| 触发源 | PRD `Fxx` / arch §8 / code-reviewer `P0-x` / 用户 |
| 类型 | protocol \| vendor \| contract \| tech_choice \| hybrid |
| 可行性 | A \| B \| C \| D |
| 凭据 | have \| need \| blocked（与 `.dev` `integrations[].credential` 同值） |
| smoke | `contracts/<slug>.smoke.<ext>` ｜ 最近成功工件：`.evidence/…` 或「未跑（缺 XXX_TOKEN）」 |
| 状态 | draft \| confirmed \| blocked \| superseded \| auto_best |
| 日期 | YYYY-MM-DD |

## 1. 目标与边界

- **要对齐的产品能力 / 选型问题**：…
- **In Scope（首版真实路径）**：…
- **Out of Scope**：…（含：禁止 stub/mock 交付）

## 1.1 术语对齐

> 只钉「叫什么」，不写 SDK/配置细节（细节见 §5–§6）。

| 采用（规范名） | 含义（1–2 句） | 避免混用 |
|----------------|----------------|----------|
| 例：OIDC 登录 | 授权码 + PKCE 对接企业 IdP | SSO、OAuth（过宽）、单点 |

仓内已有 domain/术语文档时：冲突已裁定则按本表；未裁定标 `（待确认）`。

## 2. Integration Card（摘要）

- 仓内痕迹：…
- 宣称 vs 代码：一致 / 矛盾（简述）
- 环境：沙箱·账号·证书（具备 / 缺失 / 待确认）

## 3. 可行性结论

一句话 + 刻度理由（A–D）。若 C/D：列出阻塞与建议（撤入口 / 等材料 / 换依赖）。

## 4. 候选方案（2–3）

| 方案 | 来源（链接） | 契合本栈 | 风险 | 备注 |
|------|--------------|----------|------|------|
| 官方 SDK / 标准库 | URL | 高/中/低 | … | |
| 社区库 / 参考实现 | URL | … | 维护·许可证 | 不得仅凭 star |
| 自研 / 另选引擎 | URL | … | … | |

### 4.1 八维对照（必填）

刻度与 [integration-research 八维](../SKILL.md) / plan-reviewer 同尺。依赖 stub 交付的候选：「生产诚实」= 0，不得推荐。  
**无 smoke 上限**：未真打过的候选，「生产诚实」「交付可验证」各 ≤ 60（沙箱本可得却没打 → ≤ 40）。

| 维度 | 方案 A | 方案 B | 方案 C |
|------|--------|--------|--------|
| 长远规划 | | | |
| 产品体验 | | | |
| 生产诚实 | | | |
| 架构边界 | | | |
| 可靠性 | | | |
| 可运维 | | | |
| 安全合规 | | | |
| 交付可验证 | | | |
| **总分** | | | |

**选定**：方案 X（总分 …）。并列时的 tie-break：…  
`auto_best`：是/否。

### 4.2 非显然否决（可选）

| 否决方案 | 否决理由（非显然） |
|----------|--------------------|
| … | … |

## 5. 标准对接 / 落地流程（推荐）

1. **配置与密钥**：配置项、密钥存放、轮换
2. **鉴权**：协议要点（如 client_credentials / bind DN / AK-SK）
3. **连通性探测**：最小只读调用与超时
4. **业务最小操作**：首版真实写/读（点名 API）
5. **失败语义**：超时、4xx/5xx、部分失败；**不得假成功**（须经场景探针）
6. **可观测**：日志字段、审计、metrics（若适用）

### 5.1 场景探针 → 测试（每行必须指到一个测试）

| 场景 | 期望可见行为 | 对应测试（文件::用例） |
|------|----------------|------------------------|
| 依赖超时 | … | … |
| 鉴权失效 401 / 证书过期 | … | … |
| 限流 429 退避 | … | … |
| 幂等 / 重试重放 | … | … |

「对应测试」列有空 → 回传 `failure_semantics_tested: false`，不得宣称失败语义已落地。

### 5.2 smoke（真打留证）

| 项 | 值 |
|----|-----|
| 脚本 | `contracts/<slug>.smoke.<ext>`（最小鉴权 + 一次只读/幂等写，可重复执行） |
| 打向 | 真实端点 / 厂商沙箱 URL：…（**不得**是本地 mock 或 Postman 假服务器） |
| 凭据来源 | `.dev` `integrations[].credential_env`：`XXX_KEY_ID` / `XXX_KEY_SECRET`（**只记名**） |
| 断言 | 状态码 + 关键字段：… |
| 最近一次结果 | PASS `.evidence/<run_id>/…` ｜ 未跑（缺凭据，见 §9） |

跑法见 [smoke-contract.md](smoke-contract.md)（`evidence-run --phase smoke` → `gate-check smoke`）。

## 7. 真实验收草案（待确认 → PRD）

至少 2 条。标注：`（待确认）`。

## 9. 阻塞项

## 10. Followups

```
