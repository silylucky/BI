# 会话纪律与流程（Phase 0–5）

## 会话纪律（研究进行中）

研究不是只搜链接；下列动作贯穿 Phase 0–4，决议**当场**落进简报草稿：

### 锐化模糊称呼

用户或 PRD 用营销词 / 过载词时，立刻提出规范名。「你说的『单点登录』是 OIDC 授权码、SAML，还是仅表单代理？」「『账号』指 IdP 主体、本系统 User，还是厂商租户？」简报「术语对齐」写：**采用** + **避免混用**。

仓内若已有 `docs/domain/` 或其它术语表：冲突时点名问清，以确认后的简报为准回填，**勿** silently 覆盖。

### 对账声明与代码

用户或文档声称「已对接 / 可配置」时，对照仓内适配器、配置键、stub。矛盾当场摊开：「PRD 写已实现，代码仍是 NotImplemented — 以哪边为真？」简报 Integration Card 记实。

### 用具体场景压失败语义

写失败语义前，至少发明 2 个探针场景（依赖超时、鉴权失效、部分成功、限流、证书过期等），逼出「返回什么、是否可重试、UI/API 如何表现」。禁止只写「做好错误处理」。

**决议即时落盘**：推荐方案、Out of Scope、阻塞项一旦敲定 → 立刻更新 `docs/integrations/<slug>.md`，不要攒批；未确认的标 `（待确认）`。

## 流程（必须）

### Phase 0 · Integration Card（短）

写出卡片（可写入简报文首）：

| 项 | 内容 |
|----|------|
| 触发源 | PRD 分片 ID / arch §8 条目 / code-reviewer finding ID / 用户口述 |
| 依赖名 | **规范名**（见术语对齐）；如「OIDC 登录」「深信服超融合 VM」 |
| 类型 | `contract`（外部契约） / `tech_choice`（技术方案选型） / `protocol` / `vendor` / `hybrid` |
| 仓内痕迹 | 适配器路径、配置键、stub 位置、已有 SDK/组件依赖 |
| 宣称 vs 代码 | README/菜单宣称 × 代码实态（一致 / 矛盾待裁定） |
| 环境 | 沙箱 URL、测试账号、`.dev` 是否具备（未知标待确认） |

### Phase 1 · 仓内勘察

1. 有界扫描适配器/config/env 模板（勿全仓无目的扫）
2. 读相关 PRD 分片验收句、arch §8（若存在）；**与代码对账**，矛盾写入 Card
3. 若已是完整真实实现且有契约 → 简报写「已就绪」+ 缺口（若有），**不要**重复选型
4. 收集仓内已用称呼；草稿「术语对齐」初稿

### Phase 2 · 外网研究

按 [research-workflow.md](research-workflow.md)：

1. 官方文档 / OpenAPI / SDK（优先）
2. 标准流程（鉴权 → 连通性 → 最小写/读 → 失败语义）
3. GitHub/社区参考（注明星数/维护活跃与风险，**不得**仅凭 star 定案）
4. 本栈契合度（语言、许可证、部署形态：公有云 vs 私有化）
5. **场景探针**压失败语义（超时 / 鉴权失效 / 部分成功等）

每类至少尝试检索；闭源无结果 → 诚实 BLOCKED，列「需要用户提供的材料」。

### Phase 3 · 简报

按 [brief-template.md](brief-template.md) 写入 `docs/integrations/<slug>.md`。

必含：术语对齐、可行性、候选方案（2–3）、**八维对照表**、**非显然否决**（若有）、推荐标准对接/落地流程、真实验收草案、首版真实切片、阻塞项、followups。

### Phase 3.5 · smoke 真打

见 [smoke-contract.md](smoke-contract.md)（路径/内容/打向/凭据/判定、evidence-run + gate-check、失败语义落地、无凭据处理）。

### Phase 4 · 确认或 auto_best

**attended / 单独调用**：向用户展示 Card、推荐、八维摘要、阻塞；等人确认后再 Phase 5。未确认 → **结束**；不得自行改真理源或用 stub 顶上。

**`unattended` + `auto_best`（go-fast / loop-goal-prd / loop-goal-product）**：在简报内完成八维择优并写明选定方案 → **不等人**；调用方按选定写入 specs 并真接。本 Skill 仍不直接改业务树。难回退选型须标 `needs_adr: true`（可事后补 ADR）。

### Phase 5 ·（仅确认后）最小回写

| 用户确认项 | 动作 |
|------------|------|
| 写入 arch | 最小补丁 §8（依赖方、协议、认证、超时/重试、失败语义、数据归属、链到简报）；用简报规范名 |
| 修订 PRD | 验收改为真实路径句式；无沙箱则状态 ≤ 未实现；禁止 mock 通过 |
| 调整 plan | 有契约才排入；BLOCKED 项移出当前完成定义 |
| 写入 ADR | **仅三者皆真**：难回退、无上下文会惊讶、真有取舍 → `docs/adr/<主题>-<模块\|流程>.md`，链回简报；否则跳过 |
| 实现指引 | 可开实现任务；完成定义 = 真接或撤入口（对齐 code-reviewer） |

#### 何时提议 ADR（确认后）

| 宜写 | 不写 |
|------|------|
| 鉴权厂商/协议锁定、SDK vs 自研 HTTP 且替换成本高 | 可随时换的小工具库 |
| 跨上下文集成方式（同步 HTTP vs 事件）已拍板 | 「先接沙箱再谈」的临时决定 |
| 合规/部署禁区导致的否决（如禁止某云） | 显然唯一可行路径、无真实备选 |
| 否决了合理备选且六个月后可能被再提 | 纯执行细节（超时毫秒数等，放 arch/简报即可） |

ADR 正文保持短：上下文 → 选项表 → 决策与理由 → 后果；详流程仍以简报为准，ADR **链到** `docs/integrations/<slug>.md`。
