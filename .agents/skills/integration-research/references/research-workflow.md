# 研究工作流

配合主 Skill Phase 1–3。目标：**可追溯证据 → 2–3 候选 → 八维择优**，不是长文综述。

```text
仓内勘察 → 定 kind → 外网取证（有界）→ 候选表 → 八维打分 → 选定/park
  → 场景探针 + 真实验收草案 → 落盘简报 → smoke 脚本 + 真打留证
```

**硬禁全程有效**：契约/选型不明时禁止 stub/mock/假成功顶替交付；**没打通过的真 SDK 代码同样不算已对接**。  
**时机**：整套流程属于 go-fast「开工前 0.6 盘点」，不是实现后的补作业。

---

## 0. 先仓内（必做，再外网）

| 查什么 | 为何 |
|--------|------|
| 适配器 / client / 已有组件 | 避免重复选型；优先沿用仓内已验证路径 |
| 依赖清单（`go.mod` / `package.json` / lock 等） | 已有 SDK/库 → 候选默认加分 |
| `.env.example` / `values.yaml` / `.dev` | 环境与配置键是否已有槽位 |
| stub / mock / NotImplemented / 假成功 | 与 reviewer finding 对齐；记入 Card |
| PRD / README / 菜单宣称 vs 代码 | 矛盾写入 Card，勿采信宣称 |
| arch 边界与已有端口 | 候选不得把厂商类型打进核心 |
| 已有称呼（配置键、domain 文档） | 喂「术语对齐」 |

### 0.1 声明对账

对触发相关的「已实现 / 可配置 / 已对接」：

1. 定位代码（或不存在）  
2. 结果：`一致` / `仅骨架` / `矛盾`  
3. **attended**：矛盾须问清以哪边为准再写验收草案  
4. **unattended / auto_best**：矛盾按**代码实态**记；宣称降级为未实现；禁止为圆宣称而 stub  

### 0.2 定 kind（决定检索轨）

| kind | 何时 |
|------|------|
| `contract` | 主要缺外部怎么接（鉴权/API/失败语义） |
| `tech_choice` | 主要是多方案选一（库/引擎/形态） |
| `protocol` / `vendor` / `hybrid` | 仍可用；检索时套用下列轨 |

---

## 1. 外网取证（有界）

**时间盒**：单主题默认一轮检索可完成简报；链接失效换次选，禁止无限翻页。  
**每候选至少**：1 条官方或可核验主证据链接 + 许可证/维护信号（若开源）。

### 1.1 轨 A · 外部契约（contract / protocol / vendor）

1. 官方文档 / RFC / OpenAPI / 开发者中心（优先于博客）  
2. 鉴权模型、最小只读/写入调用、错误码与限流  
3. 沙箱/账号/证书要求；无公开 API → 停猜，列需材料（NDA/手册）→ 可行 C/D  
4. 营销词落锚到具体 API 能力，否则 Out of Scope  
5. 称呼消歧：OAuth2 ≠ OIDC ≠ SAML 等，采用最窄正确名  

### 1.2 轨 B · 技术方案选型（tech_choice）

1. **问题句**先写清：「在约束 C 下，在 A/B/D 中选什么，使主路径可真实验收」  
2. 候选池（通常 2–3，不超过 4）：  
   - 仓内已用 / arch 已点名  
   - 官方 SDK 或标准实现  
   - 成熟社区库（维护活跃 + 许可证可读）  
   - 自研 HTTP/适配（仅当上者不合或边界必须自控）  
3. 每候选取：文档入口、兼容本栈版本、许可证、星/最近提交（参考，**不唯 star**）、已知坑  
4. **优先可复用**：成熟开源/官方维护 > 从 0 造；自研须在八维「长远/可运维」说清为何值得  

### 1.3 hybrid

先钉契约（轨 A），再在兼容实现里做选型（轨 B）。

### 1.4 工具

WebSearch（官方名 / OpenAPI / 错误码 / 对比词）→ WebFetch（提炼鉴权与最小 API，勿整本粘贴）→ GitHub（官方 org + 本栈语言；记 license / last commit）。矛盾来源 → 简报标风险，降权或淘汰该证据。

## 2. 候选表 → 八维（必做）

先填简报候选表（来源链接、契合、风险），再打 **八维**（主 Skill 同尺；锚点见 plan-reviewer `dimensions.md`）。

| 步骤 | 动作 |
|------|------|
| 1 | 淘汰：无证据链接、或交付依赖 stub/假成功（生产诚实 = 0） |
| 2 | 对其余候选打八维；**禁止**整行同分 |
| 3 | 总分 = 算术平均；取无硬门槛最高者 |
| 4 | 并列 tie-break：官方/标准实现 > 成熟社区库 > 自研；仍并列写理由 |
| 5 | 写入简报 §4.1；`auto_best` 时 `selected` + `auto_best: 是` |

旧「官方性/许可证/栈契合…」检查项**折入八维取证**，不再另起平行评分表抢戏。

---

## 3. 场景探针 → 代码 + 测试（不止写进简报）

至少 2 行（契约类建议 ≥3），且**前四类是硬性覆盖面**，每行必须指到一个测试：

| 探针 | 要逼出的结论 | 落地物 |
|------|----------------|--------|
| 依赖不可达 / 超时 | 可见错误；是否重试；**是否假成功** | 超时配置 + 超时测试 |
| 鉴权失效 (401) | 与「权限不足」可否区分；是否自动刷新 | 401 分支 + 测试 |
| 限流 (429) | 退避策略、上限、用户可见态 | 退避实现 + 测试 |
| 部分成功 / 重放 | 幂等键、重试是否重复扣费/建单 | 幂等键 + 重试测试 |
| 选型特有（若 tech_choice） | 升级破坏、数据迁移、供应商不可用 | 按需 |

禁止「做好错误处理」一句话代替探针表；禁止只填「期望行为」而无对应测试名（那是 `failure_semantics_tested: false`）。

## 3.5 smoke 脚本（约定见 [smoke-contract.md](smoke-contract.md)）

写 `contracts/<slug>.smoke.<ext>` → `evidence-run --phase smoke` 真打 → `gate-check smoke --slug <slug>` 退出码 0。  
**必须打真实端点或厂商沙箱**；凭据只从 `.dev` `integrations[].credential_env` 的变量名读。

## 4. 可行性与 BLOCKED

刻度表与 `credential` 对齐口径见 [主 Skill「可行性刻度」](../SKILL.md#可行性刻度)（唯一真源，本文件不重复维护）。

BLOCKED 时简报仍写清：材料清单（含缺哪个 env 变量名）+ 此前 PRD/入口如何诚实处理（降状态/撤入口）。

## 5. 反模式

- 只丢 GitHub 链接，无流程、无八维、无失败语义  
- 「先 stub / 假成功再补契约」  
- Postman 假服务器 / 本地 mock 当 smoke 或生产验收（**对的做法**：真实端点或厂商沙箱）  
- 写完真 SDK 代码从没跑过一次就标已对接  
- 实现完再补简报走过场（研究属于开工前）  
- 营销页当 API 契约  
- 未仓内勘察就外网开选，丢掉已有依赖  
- 为圆 README 宣称而忽略代码 stub  
- 每个小库都提议 ADR（多数只留简报）  
- `unattended` 干等用户或无八维就开工  
- 唯 star 定案；或无许可证检查  

---

## 6. 与真接交界

| 模式 | 本工作流终点 |
|------|----------------|
| attended / 单独 | 简报 + smoke 过 → 用户确认 → arch/PRD/可选 ADR → go-fast 真接 |
| unattended `auto_best` | 简报含八维选定 + smoke 过 → 调用方写 specs → **直接真接**（不等人） |
| B 级（缺凭据） | 简报 + smoke 脚本（未跑）+ blockers 列 env 变量名 → `DONE_WITH_CONCERNS`；**禁**标已实现 |
| park / C–D | 简报 + blockers；冲其他项；禁 stub |

真接时：完成定义 = 真实依赖验收（**smoke 工件 + 失败语义测试**）；未就绪 → 撤入口/降状态，而不是 flag 挂假实现。术语以简报「术语对齐」为准。
