# 八维择优（选型刻度）

对每个**候选方案**打 0–100，总分 = 算术平均。调用方 `auto_best` / 本简报推荐均用此尺。细则锚点见 [plan-reviewer dimensions](../../plan-reviewer/references/dimensions.md)。

> 本段八维为**集成研究专用**，与 plan-reviewer 的八维不是同一套字段名，编排层勿混用。

| # | 维度 | 选型时看什么 |
|---|------|----------------|
| 1 | **最佳长远规划** | 演进、锁定成本、是否把临时适配写成终局 |
| 2 | **最佳产品体验** | 对用户任务/失败可见性的影响是否更优 |
| 3 | **最佳生产诚实** | 能否真接验收；**依赖 stub/假成功的候选直接淘汰**（本维 0） |
| 4 | **最佳架构边界** | 与 arch 缝/端口是否契合；是否泄漏厂商类型进核心 |
| 5 | **最佳可靠性** | 超时/重试/幂等/降级是否可落地；禁假成功 |
| 6 | **最佳可运维** | 配置、观测、升级、供应商锁定与运维成本 |
| 7 | **最佳安全合规** | 密钥、权限、审计、供应链/许可证风险 |
| 8 | **最佳交付可验证** | 首版真实路径能否独立验收；沙箱/探针是否可得 |

**选定规则**（`auto_best` / 简报推荐）：无硬门槛（stub 交付、无证据）的候选中总分最高；并列 → 官方维护 SDK/标准实现 > 成熟社区库 > 自研。写入简报「八维对照」表。

**无 smoke 上限（防「假通」）**：候选尚无成功的真实端点 smoke 证据时，**「生产诚实」与「交付可验证」两维各 ≤ 60**；沙箱/凭据本可得却没打 → 两维各 ≤ 40。「用的是官方 SDK、代码看着很真」**不构成**这两维的加分理由 —— endpoint / scope / 签名全错的代码同样语法正确。
