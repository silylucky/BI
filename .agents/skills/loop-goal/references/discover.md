# 产品地图发现（loop-goal Phase 1）

目标：在**不写业务树**的前提下，产出可切军团的产品地图。

## 输入源（按序消费，有则读）

| 优先级 | 源 | 取什么 |
|--------|----|--------|
| 1 | `docs/automate/goal.md` | 产品定位、边界、成功指标 |
| 2 | PRD hub / 分片、`docs/automate/plan.md` | 能力域、里程碑、流程名 |
| 3 | `docs/arch.md` | 模块边界、部署、约束 |
| 4 | `docs/ui/`（若有） | IA、壳、页菜谱 |
| 5 | 路由 / 菜单 / 导航代码 | 真实入口与域划分 |
| 6 | `docs/domain` / 既有剧本 | 已命名业务流程 |
| 7 | [scenario-playbook discovery](../../scenario-playbook/references/discovery.md)（若存在） | 自动发现关键路径的口径；**不强制**生成全套剧本 |

扫描底座：只探测不装（同 loop-polishing Phase 0 / code-scanning 隐式入口）。`scan_tools` 写入舰队 ledger。

## 产出文件

`docs/material/loop-goal/<YYYY-MM-DD>-<slug>-product-map.md`

### 必含节

```markdown
# Product Map · <repo-or-product>

## 产品定位
（一短段：给谁、解决什么、非目标）

## 业务线 / 域
| id | 名称 | 一句话 | 主入口（路由/菜单） | 证据 |
|----|------|--------|---------------------|------|

## 关键业务流程
| id | 流程名 | 所属域 | 端到端摘要 | 写操作？ | 证据 |
|----|--------|--------|------------|----------|------|

## 交互与引用
| from | to | 关系（导航/API/共享组件/权限/数据） | 证据 |
|------|----|--------------------------------------|------|

## 共享壳（全局）
- layout / nav / auth / 权限模型 / 设计锚 …

## 军团候选
| legion_id | 建议 scope | scope_level | 含流程 ids | 初判并行风险 |
|-----------|------------|-------------|------------|--------------|

## 待确认 / 盲区
- …
```

## 切军团规则

1. **默认一域一军团**；若单域过大（多条无关主流程）→ 按流程再切。  
2. **紧密耦合**（强共享写模型 / 同一状态机）→ **合并**为同一军团，勿假并行。  
3. **共享壳**单独不派「壳军团」修壳（除非用户点名）；壳变更由冲突图串行合回时处理，或标 `neighbor` 抽检交给触及壳的军团。  
4. 候选数 > `fleet_cap * 预估波数预算` 时：优先 P0/P1 主路径域，其余进舰队 ledger `deferred_legions`。  
5. 每条候选必须能写出**有界** `scope` 字符串（模块名或流程名），禁止 `整仓`。

## 禁止

- 无路由/文档/代码证据却发明业务线  
- 把「整个后台」当成一个 scope 塞进单军团（应再切或标大域并拆流程）  
- 在 Discover 阶段调 go-fast 或改业务实现
