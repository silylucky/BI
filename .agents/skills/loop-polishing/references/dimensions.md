# 打磨八维（loop-polishing · composite）

总分 = 下列八维算术平均（各 0–100）。刻度与姊妹 reviewer 对齐精神，但**合成在本环**，避免直接拿单一 reviewer 总分冒充综合分。

| # | 维度 | 主要取证 | 刁钻一问 |
|---|------|----------|----------|
| 1 | **产品任务** | product-reviewer | 是否在帮完成真实工作，而非逼填表/堆功能？ |
| 2 | **业务流程** | product `flow` | 主路径短稳？例外/逆操作/权责能否打穿？ |
| 3 | **架构边界** | arch-reviewer | 模块是否 deep？缝是否泄漏？改一处是否无 locality？ |
| 4 | **代码诚实** | code-reviewer | 有无假绿/stub/半成品入口/裸协议表单/可靠性坑？ |
| 5 | **视觉密度** | ui-ux-reviewer | 是否对齐本仓标杆/菜谱？语义色与密度是否专业？ |
| 6 | **交互反馈** | ui-ux shell-interaction | 提交/空错载/权限/导航是否诚实可操作？ |
| 7 | **邻域契合** | 邻域抽检 | 与上下游模块名词、状态、入口、权限是否裂缝或重复？ |
| 8 | **UX 闭环** | product + ui-ux | 可发现、可恢复、可信任；新人能否上路？ |

## 刻度（每维）

| 分 | 含义 |
|----|------|
| 90–100 | 刁钻用户难打穿；可作标杆 |
| 75–89 | 可上线，仍有清晰刺点 |
| 60–74 | 主路径能走，例外/信任/一致性不稳 |
| 40–59 | 明显半成品或结构性问题 |
| 0–39 | 假绿、不可用或硬门槛成片 |

## 硬门槛对总分

任一未清硬门槛（假绿、有入口半成品、主路径不可用、严重越权表面等）→ **`total` 上限 69**（与 product-reviewer 精神一致），即使若干维虚高。

## 焦点轮次如何贡献

| lane | 更新 |
|------|------|
| `composite` | 重算全部八维 + `total`；`composite_mode=full` 重取证，`light` = 合成上次焦点维分 + **抽检硬门槛**（须入口/主路径证据）。**首个 composite 强制 `full`**——无历史焦点维分可合成，`light` 只会捏造基线（见 [round-roster.md](round-roster.md)） |
| `product` / `flow` | 更新维 1–2（及证据）；`total` stale |
| `arch` | 更新维 3；按授权级放行（`polish_safe` 自动 / `local-deepen` 升格时 / `structural` deferred，见 finding-normalize） |
| `code` | 更新维 4 |
| `ui` / `ux` | 更新维 5–6、8 |
| `neighbor` | 更新维 7 |

`light` **禁止**空想抬分：硬门槛抽检失败 → 相关维与 `total` 上限仍按硬门槛规则封顶 69。

## 邻域边界

Phase 0 写明：`neighbors: [模块A, 模块B]`（从 import、路由、菜单、PRD 依赖性推断，最多 3 个）。  
邻域默认 **只读抽检**；跨邻域大改 → `deferred` 或拆另一次 loop scope。
