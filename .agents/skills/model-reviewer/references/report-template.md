# 模型审计报告模板

落盘 `docs/material/model-reviewer/<YYYY-MM-DD>-<slug>.md`（再评加 `-rN`，禁止覆盖上轮）。
按序填空；给用户看时用中文；简短优先，但**表清单与 finding 不得抽样**。

```markdown
# 数据模型审计 · <库或域名> · <YYYY-MM-DD>

## Model Card
- 引擎/版本：              # 决定可用修法
- 真源：                   # migrations 路径；三源是否一致（不一致 → 见 M-x 真源分裂）
- 范围：                   # 整库 / 表族 / 变更面
- 量级：                   # 主表行数量级、日增、无界增长表
- 多租户/分片：            # 隔离方式；现有分片或分区键
- 扫描工具：               # rg-only / +ast-grep / +codegraph；codegraph 新鲜度 clean/synced/stale
- 规则来源（应然）：       # 读过的文档路径；文档为空则写 code-inferred
- 代码入口（实然）：       # 读过的 DAO/Service 目录
- 已定取舍：               # ADR / docs/data 里已记录的，避免复诉

## ADR 复核（有 ADR/目标态时必填）

**ADR 是「声称的应然」，不是真源。** 先判它对不对，再谈现网有没有跟上。

| ADR | 模型角度（八维重打） | 架构角度 | 前提是否已变 | 现网绕开它的证据 | verdict | 动作 |
|-----|---------------------|----------|-------------|-----------------|---------|------|
| | 命中硬门槛/反模式？ | 缝泄漏/不可回滚/与 HA 矛盾？ | 量级·租户·引擎·合规 | 新结构无写入 / 转换层 / 仍走旧通路 | sound / outdated / wrong | 收口 / 重开ADR / 转 arch-reviewer |

`outdated` 或 `wrong` 时**不得**判「未收口」，改出重开建议 + 新目标态候选 + 硬决策清单。

## 三方对账矩阵（文档规则 ↔ 代码用法 ↔ 库约束）

| 规则（一句话） | 出处 | 库是否设防 | 代码是否设防 | 结论 | finding |
|----------------|------|-----------|-------------|------|---------|
| | `docs/...:行` 或 code-inferred | yes/no/partial | yes/no | ok / gap / drift | M-x |

**代码替库兜底清单**（`gap` 中最要紧的一类；库不设防 = 脏数据只是还没进来）：

| 兜底位置 | 兜的是什么 | 绕过它的路径 | finding |
|----------|-----------|--------------|---------|
| `service/x.go:88` 查后插防重 | 业务键唯一性 | 并发、运维 SQL、第二个服务 | M-x |

## 目标态 vs 现网（命中 I 组时必填）

> `mode=redesign`（原本无目标态）时，「目标态」= 本次设计的候选目标，
> 并须附目标 DDL 草案、业务改造方案、ADR 草稿与硬决策清单（见 [target-design.md](target-design.md)）。

目标态（ADR/arch 定的形状，或本次设计的候选）：

```mermaid
graph LR
  A[实体A] --> B[实体B]
```

现网实际通路：

```mermaid
graph LR
  A[实体A] --> B[实体B]
  A -.多态绑定表.-> B
  A -.选择器.-> B
```

| 差异 | 类型 | 旧通路是否仍被写入 | 迁移停在哪步 | finding |
|------|------|-------------------|--------------|---------|
| | 未收口 / 已漂移 / 目标态需重开 ADR | yes/no（出处） | expand/backfill/switch/contract | M-x |

**实体间通路清单**（≥2 条即 I2 候选）：

| 实体对 | 通路 | 承载结构 | 谁在写 |
|--------|------|----------|--------|

## 真实访问路径（供 D8，来自代码实证）

| 路径（按什么查/排/聚合） | 出处 | 命中索引 | 是否覆盖 | 结论 |
|--------------------------|------|----------|----------|------|

拿不到代码证据时此表写 `unverified`，D8 分数降置信度，**不得**凭 DDL 猜。

## Blind spots

| 维/表 | 未覆盖原因 | 影响 |
|-------|------------|------|

非空 → `status` 禁止 DONE；覆盖生产主路径/核心事务表 → BLOCKED。

## 穷尽自检
- 表清单覆盖：N/N（skipped M 张，均有原因）
- 各组 finding 数：A_ B_ C_ D_ E_ F_ G_ **H_ I_**（H 为 0 须说明读过哪些 DAO/Service；I 为 0 须说明已列过实体通路清单）
- 通路检查：核心实体对 N 对 → 多通路 M 对；迁移未收口 K 处
- 对账覆盖：抽出规则 N 条 → ok_ / gap_ / drift_；finding 中 `code_cross` + `doc_cross` 合计 N 条
- 二次 sweep：已跑 / 未触发（阈值：整库 <10 / 表族 <8 / 单表或变更面 <5）

## 目标态设计与业务改造方案（仅 mode=redesign）

按 [target-design.md](target-design.md) S2–S7 填：统一身份一句话 → 唯一合法通路表 →
约束落法 → 目标 DDL 草案（标有损点） → 业务改造方案八节 → ADR 草稿路径。

### 硬决策清单（≤5，一次问完）

| # | 问题 | 选项 | 推荐 | 理由 | 影响哪张表/哪一节 |
|--:|------|------|------|------|-------------------|

未答的决策项在 DDL 草案里必须显式标 `待确认`，**不得**出「最终」版本。

## Top recommendation
一句话：先做什么，为什么先做它。

## 请确认（是否修复？）
> 请选一项回复；「← 推荐」标在与 Top recommendation 一致的那项上：

- [ ] 1 只做最小代价止痛项（P0 的 min_cost）
- [ ] 2 按逐条推荐执行（含必要迁移）
- [ ] 3 做长期最优形状（大迁移，需 ADR + 灰度 + 窗口）
- [ ] 4 只要报告，不改库

`mode=redesign` 时改用：

- [ ] 1 先冻结旧通路写入止血（不动结构）
- [ ] 2 按目标态执行改造（含数据合并，需窗口）
- [ ] 3 只要方案，不动库
- [ ] 4 目标态需要调整（我来说明业务差异）
```
