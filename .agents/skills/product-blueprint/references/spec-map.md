# mode=spec / audit 加深

## blueprint / 确认蓝图 → go-fast 规格映射

`mode=spec`（或用户确认蓝图后点名出规格）时，`docs/specs/<slug>.md` **必须**含下表左列；右列为蓝图来源。缺映射 → 规格未开工就绪。

| go-fast 开工就绪节 | 蓝图来源 |
|--------------------|----------|
| 问题陈述 | §1 JTBD / 最贵失败 |
| 方案 | §2 架构关系 + §4 主路径摘要（勿贴巨图代替文字） |
| 用户故事 | 场景对照表 + 角色表 → 改写为「作为…我想…以便…」 |
| 可观察验收 | §8；须真实路径；主成功 + 关键失败 |
| 实现决策 | 架构图边界、硬决策结论、外部依赖表；难回退标 ADR 需求 |
| 测试决策 / seam | 规划席 + 架构席要点；测公共边界、不测内部 |
| 范围外 | §11 |
| 补充说明 | 架构/业务 Mermaid（建议保留）、证据袋路径、蓝图路径、偏航表摘要 |

**规格门失败 → 最小补丁清单**（修完再跑门，勿空喊 BLOCKED）：

| 硬门槛类 | 补丁动作 |
|----------|----------|
| 验收假绿 / mock | 改写成真实依赖句；删 demo 完成定义 |
| 缺失败路径 | 补一条拒绝/超时/权限不足 |
| 用语漂移 | 与 goal/domain/arch 对齐名词（见术语表） |
| 范围外缺失 | 补 § |
| 实现决策空 | 从架构图 + 硬决策表压缩 5～10 条 |

tickets：默认仍交 go-fast 拆；本 Skill 不拆除非用户点名。

确认蓝图后出 spec：可跳过「再问硬决策」（配额已用尽的结论写入实现决策）；**仍须**成稿轻量复评（规划+产品至少）+ self-check F 节 + `go-fast-spec-gate`。

## mode=audit 缺口严重度

成稿须含下表（可与偏航表合并）：

| ID | 缺口 | 严重度 | as-is 证据 | 建议 | 接力 |
|----|------|--------|------------|------|------|
| G1 | … | P0/P1/P2 | 代码/路由/文档路径 | … | product-reviewer / blueprint 纠正 / go-fast |

| 严重度 | 含义 |
|--------|------|
| **P0** | 主路径不可用、假成功、无审计的关键写、与业内基线冲突且无理由 |
| **P1** | 例外/逆操作缺失、权限菜单不对齐、图示现状与代码严重不符 |
| **P2** | 文案/空态/可发现性、非主路径体验 |

- 图：**强制 as-is**；若建议改造，附 to-be 小图或同图注释（见 [diagrams.md](diagrams.md)）。  
- **禁止**输出八维分数表冒充 product-reviewer；可在交接写「建议 `/product-reviewer scope=…`」。  
- audit 确认后停；不改代码/PRD。
