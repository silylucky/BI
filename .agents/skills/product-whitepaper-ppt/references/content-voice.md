# 白皮书内容口径（强制）

本 Skill 产出的是**产品白皮书 / 宣传与售前材料**，不是研发手册、不是 ADR 宣讲、不是 Code Review 附录。

## 这是白皮书

面向：客户、管理层、售前、技术决策者（买/选型/立项）。

读者读完应能回答：

1. 这产品解决谁的什么问题？  
2. 关键能力与差异是什么？（可验证，但不贴源码）  
3. 系统大致怎么组成？（信任边界、部署形态、集成面）  
4. 典型业务怎么跑通？（角色与结果，不是函数调用栈）  
5. 落地要具备什么条件、下一步找谁？

语气：产品叙事 + 适度技术可信度。一句能力主张，最多一句「何以可信」的支撑（模块/能力名），**不要**把支撑写成实现说明书。

## 这不是白皮书（禁止进主叙事）

截图那种页 = **不合格**：

| 禁止写进正文的 | 应去哪 |
|----------------|--------|
| Cookie 名（`nex_session`）、Header 名（`X-User-Id`） | `docs/api` / 安全 ADR |
| 中间件类名（`AuthMiddleware`）、Handler/Logic 分层口号 | `docs/arch` / 代码 |
| ADR 编号当演讲主句（「见 ADR 0001」） | 脚注或附录「延伸阅读」最多一行 |
| `OkJson` / `WriteErr` / `code === 0` 信封细节 | API 文档 |
| 「当前实现是 SQLite」当架构主标题（除非选型本身是卖点） | arch；白皮书只说「统一数据层 / 可替换存储」类产品语言 |
| 内部路由表、包路径、函数名当流程节点主标签 | 用角色 + 用户动作 + 业务系统名 |
| **空坐标 / 空 In·Out 象限撑版**（轴在、点无、标题还是「定位一句话」） | 改 comparison/breakdown，写满具体边界条目 |
| **流程列复制粘贴 / 多卡同名 / 叠字 / 假流程 %** | 每步写不同业务动作；换 layout；无披露数据就不要 % |
| **空图槽「点击上传」** | 无素材选无媒体页；有素材先 media:stage |
| **标题乱断行 / 半截句** | 缩短主张或按 L1/L2 意群拆行 |

扫仓是为了**核对事实**，不是为了把工程细节原样贴进 PPT。

## 架构章怎么写才像白皮书

| ✓ 白皮书架构 | ✗ 工程说明书 / 翻车页 |
|--------------|------------------------|
| 控制台 / API 服务 / 数据与对象存储 / 外部 IdP·通知 | 浏览器带 Cookie 打 `/api/v1/*` |
| 身份认证与权限控制（会话或令牌） | 不读 `X-User-Id`；HttpOnly 细节 |
| 同步业务请求：接入 → 鉴权 → 业务处理 → 统一响应 | 四步贴中间件与 JSON 字段 |
| 异步：任务队列、重试、可观测 | worker 类名与日志字段 |
| 角色用人话：控制面 / 作业面 / 边缘代理 | `--role=server`、二进制名串接、`pkgs/observe` |
| 拓扑用关系/分层盒子 | **用假折线/雷达「路径强度」冒充拓扑** |

同步路径页标题示例：

- ✓「请求如何进入系统并安全落地」  
- ✗「同步主路径：浏览器 → API → 数据」再跟 Cookie/ADR 列表  

拓扑页自检：若预览里出现叠字、字段粘连（`name`+`role` 糊成一串）、或图表轴标签当架构组件 → **整页作废重选 layout**。

## 业务场景章

节点语言：**角色做了什么 → 系统保证什么 → 用户看到什么成功**。  
不要：`POST /tickets` → `TicketService.Create`。

异常页：用业务症状（「没有权限」「插件连不上」），系统行为用产品语言（「拒绝写入并提示申请角色」），不要贴 RBAC 中间件实现。

## sourceRefs 的用法

- `sourceRefs` 写在 **outline.json** 给 Agent 自检，**不要**默认印在幻灯片正文。  
- 需要增信时：页脚一行「依据：产品能力 · 权限模型」即可，勿堆文件路径墙。

## 自检三问（每页）

1. 客户/老板听得懂吗？  
2. 删掉所有类名/Cookie/ADR 后，主张还成立吗？  
3. 这页是在「卖清能力与可信度」，还是在「培训新同事读代码」？  

第 3 问若是后者 → 整页重写或移出白皮书。
