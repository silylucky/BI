# 白皮书 Deck 大纲（≥30 页）

默认 **36 页**。可增至 40–48；不得砍掉必选块导致 <30。

内容口径见 [content-voice.md](content-voice.md)：产品宣传白皮书，不是把 arch/ADR/中间件细节贴进 PPT。

## 配额

| 区块 | 页数 | 必选 |
|------|-----:|:----:|
| A 开场 | 4 | ✓ |
| B 产品定位与价值 | 4 | ✓ |
| C 核心亮点 | 6 | ✓ |
| D 技术架构（产品级） | 7 | ✓ |
| E 业务场景详细流程 | 10 | ✓ |
| F 落地与收束 | 5 | ✓ |
| **合计** | **36** | |

## A · 开场（4）

| # | role | 标题意图 |
|--:|------|----------|
| 1 | cover | 产品名 · 产品白皮书（人话价值主张；短标题） |
| 2 | statement | 我们解决谁的什么问题 |
| 3 | breakdown | 目录 |
| 4 | context | 本材料怎么读（不含研发手册；**禁半截文案**） |

## B · 定位与价值（4）

| # | role | 标题意图 |
|--:|------|----------|
| 5 | context / breakdown | 目标用户与场景（**默认无图**；有截图再配 media） |
| 6 | **comparison** 或 **breakdown** | 定位句 + **具体** In/Out 条目（**禁止空象限图**） |
| 7 | comparison | 与替代方案差异（可验证） |
| 8 | metrics | 能力覆盖或已披露指标（勿编数字；数据点不足则改 breakdown） |

**第 6 页正确：** 一句话定位作标题；下方两列至少各 3 条 In / Out（或边界原则短列表）。  
**第 6 页禁止：** 空坐标 + IN SCOPE/OUT OF SCOPE 标签；标题仍写「定位一句话」；用假「交付复杂度×成熟度」图冒充边界。

## D · 技术架构（7）— 产品级可信度

让技术决策者信任「能扛」，不是培训读仓库。

| # | role | 标题意图 |
|--:|------|----------|
| 15 | transition | 章节：技术架构 |
| 16 | **relationship** | 总览：控制台 / 服务 / 数据 / 外部依赖（**禁止 metrics**） |
| 17 | **breakdown** | 能力域职责（权限、任务、集成…） |
| 18 | process | 业务请求如何被安全处理（产品步骤） |
| 19 | process | 异步 / 集成 / 扩展点 |
| 20 | context | 部署与运行形态（短表 OK；禁 CLI） |
| 21 | risks | 安全与可靠性承诺（鉴权、审计、失败可见） |

**第 16 页正确：** 少量命名盒子 + 关系（谁连谁），一眼能讲清部署边界。  
**第 16 页禁止：** 折线/雷达/「路径强度」假数据；叠字；把 `--role=` / 二进制启动参数当主视觉。  
**第 18 页正确：** 发起操作 → 校验身份与权限 → 业务执行与落库 → 可确认的成功/失败。  
**第 18 页禁止：** Cookie 名、Header、中间件类名、ADR 编号、`code===0`、函数调用链。  
**第 20 页正确：** server / worker / agent（或等价角色）用**人话职责**一行；扩容原则一句话。  
**第 20 页禁止：** `--role=server`、配置文件名堆砌、包路径。

## E · 业务场景（10）

≥2 主场景；节点 = 角色动作 + 业务结果。

| # | role | 标题意图 |
|--:|------|----------|
| 22 | transition | 章节：业务场景 |
| 23 | breakdown | 场景地图 |
| 24–27 | process/risks | 场景 A：总览、步骤、分支、异常（业务语言；**步骤正文互异**） |
| 28–30 | process | 场景 B：总览、步骤、系统协作（**禁止列复制粘贴**） |
| 31 | result | 场景 ↔ 产品能力映射 |

**场景步骤页正确：** 每列不同动作（选目标 / 护栏确认 / 提交 / 编排执行 / 回传审计）+ 底部价值点也互不重复。  
**场景步骤页禁止：** 每列同一句基建流程；多卡同名；叠字；无来源的阶段假 %。  
**场景总览页正确：** 清晰阶段名（产生→降噪→值班→行动→闭环），一句成功标准。  
**场景总览页禁止：** 大字叠成无法读；右侧多框标题撞名。

## F · 落地与收束（5）

| # | role | 标题意图 |
|--:|------|----------|
| 32 | actions | 落地路径 |
| 33 | trend | 路线图/扩展（仅已文档化） |
| 34 | team | 相关产品文档入口 |
| 35 | observation | 给决策者的三条结论（**短主张 + 完整句**；禁乱断行） |
| 36 | closing | 下一步 |

**第 5 页正确：** 角色/规模/场景用卡片或列表说清；无截图则全页文案。  
**第 5 页禁止：** 右侧「影像 1/2 · 点击上传」空槽占版。  
**第 35 页正确：** 2–4 条完整决策结论，每条可一口气读完。  
**第 35 页禁止：** 长句被组件折成「数据留｜在内网」这类词中切断。

工程细节附录仅当用户明确要求时另加，不占主叙事。

## 扩页

加场景、亮点、集成案例；禁止靠粘贴 API/ADR 正文凑页。
