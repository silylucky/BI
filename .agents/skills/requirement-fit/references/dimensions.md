# 八维子项与打分锚点

每维先扫子项，再合成 0–100。有硬门槛命中时该维 ≤40（见主 Skill）。

打分时写清：**主要依据的 REQ-ID 或条款** + **仓内锚点**。

---

## 1. 功能覆盖

| 子项 | 高分锚点 | 低分锚点 |
|------|----------|----------|
| 必须项 | 绝大多数 `FULL`，残余有明确分期 | 多个必须项 `MISSING`/`UNKNOWN` |
| 评分项 | 高分值项有 `FULL` 或可信 `PROXY` | 高分值项空白或仅文案 |
| 域完整性 | 同域条目匹配态一致、可演示 | 同域东拼西凑、入口断裂 |
| 诚实标注 | `PARTIAL` 缺口写清 | 夸大「基本都有」 |

**参考刻度**：必须项满足率（FULL=1, PARTIAL/PROXY=0.5）≥0.9 且无硬门槛 → 常落 85+；<0.5 → 常 <60。

---

## 2. 产品体验

| 子项 | 高分锚点 | 低分锚点 |
|------|----------|----------|
| 任务闭环 | 对标角色能从入口完成主任务 | 有 API 无入口 / 有页无主路径 |
| 权限表面 | 无权限诚实（隐藏/禁用/空态） | 假可点、菜单 404 |
| 空错载 | 对标场景有统一壳与可读文案 | 白屏、裸报错、无反馈 |
| 与条款角色 | 招标角色（管理员/审计/业务）有对应表面 | 只服务开发者控制台 |

有 `docs/ui/` 时以其菜谱/标杆为体验基线；没有则抽 1～3 个最完整页，并降置信。

---

## 3. 安全合规

| 子项 | 高分锚点 | 低分锚点 |
|------|----------|----------|
| 认证授权 | SSO/LDAP/RBAC 等条款有真路径 | 仅本地账号却声称统一身份 |
| 审计留痕 | 关键操作可查、可导出（若条款要求） | 无审计或仅日志文件口头承诺 |
| 数据保护 | 隔离、脱敏、加密点与条款对齐 | 多租户串数据、密钥硬编码 |
| 合规表述 | 等保/密评/国产化等**只写有证据的部分** | 无证据写「已满足等保三级」 |

无相关条款时：本维给「不适用说明」并打 **中性分 75–85**（勿无故打满分或零分）；有条款则按证据严打。

---

## 4. 集成互通

| 子项 | 高分锚点 | 低分锚点 |
|------|----------|----------|
| 协议/厂商 | 官方 SDK/标准协议真接或已确认简报 | 空适配器、TODO、假成功 |
| 失败语义 | 超时/拒绝/部分失败可观察 | 吞错当成功 |
| 验收环境 | 有沙箱/联调说明或 BLOCKED 已标出 | 假设「客户现场一定通」 |

缺口大时：改造建议应指向 [integration-research](../../integration-research/SKILL.md)，本维分数反映**当前仓**而非「未来研究完」。

---

## 5. 部署运维

| 子项 | 高分锚点 | 低分锚点 |
|------|----------|----------|
| 部署形态 | 私有化/信创/云主机等与条款一致且有部署文档或 compose/helm | 仅本地 dev 脚本却称生产就绪 |
| 高可用/备份 | 条款要求有架构与操作说明 | 单点、无备份策略 |
| 观测与升级 | 健康检查、日志/指标、升级路径 | 黑盒、只能重装 |
| 配置与密钥 | 外置配置、无默认生产密码入库 | 密钥进仓、无环境分离 |

参考 `docs/service/`、`docs/arch.md`、`.dev`（若有）与真实部署清单。

---

## 6. 架构可承载

| 子项 | 高分锚点 | 低分锚点 |
|------|----------|----------|
| 边界 | 缺口落在已有模块/端口，缝清晰 | 需打穿多域或复制第二套系统 |
| 数据模型 | 扩展字段/实体有归处 | 无模型却承诺复杂业务 |
| 技术债 | 改造可切片 | 必须大爆炸重写才能满足必须项 |
| 与 arch 一致 | 方案不与 `docs/arch.md` 关键决策冲突 | 方案否定已定栈且无 ADR 意识 |

---

## 7. 证据可应标

| 子项 | 高分锚点 | 低分锚点 |
|------|----------|----------|
| 可演示路径 | 逐步操作 + 期望结果可交给售前/评测 | 「代码里有」但无人会点 |
| 文档/材料 | api/domain/ui/帮助能支撑条款话术 | 只有口嗨或过时 README |
| 一致性 | 声称、文档、代码三方一致 | 白皮书超前、代码落后 |
| 测评配合 | 若条款要测试报告/日志样例，有采集点 | 无法配合现场测评 |

`FULL` 条目若不能演示 → 本维扣分，并考虑降为 `PARTIAL`。

---

## 8. 缺口可交付

| 子项 | 高分锚点 | 低分锚点 |
|------|----------|----------|
| 方案具体 | 目标行为、验收、切片、不做清单齐全 | 「加强功能」「优化体验」空话 |
| 真实依赖 | 外部系统有研究路径或已标 BLOCKED | 默认 mock 验收 |
| 工作量可信 | S/M/L 与依赖说清 | 无依据的「两周全做完」 |
| 风险 | 合规/性能/数据迁移风险写明 | 假装无风险 |

无缺口（几乎全 `FULL`）时：本维评「方案纪律与残留 PARTIAL 质量」，通常 80–95，勿机械打 100。

---

## 合成提示

1. 先定硬门槛 → 再打维分 → 再算综合分。  
2. 维间允许相关，但**禁止抄同一分数**；至少在功能覆盖 / 体验 / 证据三维拉开。  
3. `UNKNOWN` 多 → 功能覆盖与证据维应明显低于「感觉良好」的宣传分。
