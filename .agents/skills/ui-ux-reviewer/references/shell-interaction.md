# Shell · Navigation · Interaction（壳 / 导航 / 交互反馈）

补齐「单页好看但产品壳或主路径交互仍不可上线」的漏检。与视觉五维并行；不替代完整无障碍或性能审计。

## 1. 壳与导航完整性 — 优先 P1

| 反模式 | 级别 | 说明 | 修法 |
|--------|------|------|------|
| 布局为侧栏/顶栏预留空间，但导航内容为空 | P1 | 用户看见大块空白（如 `ml-[290px]` + 空 `sections`） | 填导航、收起侧栏、或换无侧栏布局 |
| 菜单有项、路由无页 / 路由有页、菜单无入口（已宣称功能） | P1 | 入口漂移 | 对齐菜单与路由；或改宣称 |
| 点击菜单 404、空白 Outlet、重定向环 | P0 | 主路径不可用 | 修路由或撤菜单 |
| 深页无面包屑/返回且侧栏高亮丢失 | P1 | 迷失 | 补面包屑或保持父级导航激活 |
| 多套布局壳并存且同域混用（无设计说明） | P1 | 产品碎裂 | 同域统一壳；例外写入 FE Card |

**扫法**：对照路由表 × 侧栏/顶栏配置；抽查「有 layout margin/padding 预留」的页，看对应 slot 是否有真实 nav items。

## 2. 权限与错误表面 — 优先 P1（可升 P0）

面向 **Console/Admin**（有角色/权限时必查）：

| 反模式 | 级别 | 说明 | 修法 |
|--------|------|------|------|
| 无权限仍展示可点主 CTA，点击后才 403 原文/堆栈 | P1 | 假可点 | 隐藏或禁用并说明；错误走统一壳 |
| 401/会话过期无回到登录或丢 `redirect` | P1 | 用户卡死 | 统一鉴权跳转与回跳 |
| 权限不足页与「未实现」空页难以区分 | P1 | 误判产品烂尾 | 专用 forbidden 态文案 |

**非问题**：按钮按权限隐藏（无入口）且文档未宣称该角色可用。  
**安全深挖**（越权 API）→ [code-reviewer](../../code-reviewer/SKILL.md)，本 Skill 只评**表面体验**。

## 3. 异步与提交反馈 — 优先 P1

| 反模式 | 级别 | 说明 | 修法 |
|--------|------|------|------|
| 主提交无 loading / 可连点导致重复提交 | P1 | 双单、重复创建 | pending 禁用按钮或显式 loading |
| 成功/失败无反馈（无 toast、无就地错误、无跳转） | P1 | 用户不知道是否生效 | toast 或表单级错误；成功有下文 |
| 仅 `console.log` / 吞掉 catch | P0/P1 | 静默失败 | 与完整度「错误壳」合并报 |
| 列表筛选/分页不反映 loading，旧数据冒充新结果 | P1 | 误判数据 | 筛选时 busy 态或明确刷新 |

## 4. 响应式抽检 — P1（主路径破坏时）

不做全断点精修；上线前对**每个域至少 1 个列表 + 1 个表单/详情**抽检：

| 反模式 | 级别 | 说明 | 修法 |
|--------|------|------|------|
| 常用宽度下主 CTA / 页头操作被裁切且无法滚动触达 | P1 | 主路径不可用 | 换行、折叠到菜单、sticky 工具栏 |
| 宽表横向溢出整个视口（非表内滚动） | P1 | 碎布局 | 表区域 `overflow-x-auto`；外层勿撑破 |
| 移动端若产品宣称支持，关键流完全不可用 | P0/P1 | 假宣称 | 修关键流或改宣称「仅桌面」 |

**FE Card** 写清：`响应式承诺：桌面 only / 含平板 / 含移动`。仅桌面则移动问题降为 P2 或不报。

## 5. 主题（仅当产品有暗色/多主题时）

| 反模式 | 级别 | 说明 | 修法 |
|--------|------|------|------|
| 硬编码浅色底/深色字，暗色模式下不可读 | P1 | 主题开关成摆设 | Token / `dark:`；去掉写死浅底 |
| 一页支持 dark、同构邻页大面积写死 | P1 | 复用+主题双问题 | 进共享壳时带主题 |

无主题开关 → 本项跳过并在报告注明。

## 6. Dialog / Sheet / 抽屉 · 遮罩透明度 — 默认 P1

控制台里弹层应**压住背景但仍能辨认上下文**。组件库（尤其 shadcn/Radix）常见默认 `bg-black/80`，过闷，验收时按本仓共享 Overlay **统一调浅**，禁止各页各写一套。

### 标准（浅色/默认主题）

| 表面 | 遮罩（黑） | 说明 |
|------|------------|------|
| **Dialog / Modal** | **20%–30%**（优先 `/25`–`/30`，或 `rgba(0,0,0,0.2–0.3)`） | 表单、详情预览；背后列表/页头应清晰可辨，不只是「隐约」 |
| **Sheet / Drawer** | **15%–25%**（优先 `/20`） | 侧滑编辑；比 Dialog 再浅一档，避免整屏发闷 |
| **AlertDialog（危险确认）** | **25%–35%** | 可略深以强调阻断，**仍不得 ≥ 50%** |
| **失败线** | **≥ 50%** 或未覆盖的 `bg-black/80`/`/70`/`/60` | 记 **P1**；同产品混用深浅多套 → 另记风格 P1 |

暗色主题：仍用半透明黑或 Token（如 `--overlay-scrim`），以「背后内容可辨」为准，勿改成近实心底。

### 硬规则

1. **共享一处**：Overlay 透明度写在本仓 `Dialog`/`Sheet`/`Drawer` 基础组件或 Token；业务页禁止临时 `className` 把遮罩加到 `/80`。
2. **扫法**：搜 `DialogOverlay` / `SheetOverlay` / `DrawerOverlay` / `bg-black/80` / 高透明度 `rgba(0,0,0,…)`；对照标杆弹层截图或运行时。
3. **非问题**：全屏沉浸式媒体灯箱（若产品明确）可更深，须在 FE Card/设计说明标明；普通 CRUD 弹层不适用例外。
4. **修法优先级**：改共享 Overlay → 全站生效；勿逐页微调。

### 与视觉维关系

遮罩过深进 findings 类别写 `视觉·遮罩` 或 `壳·弹层`；改造方案 RP 写明目标透明度与改动文件（通常一处共享组件）。

## 回传格式（可并入域 lane）

```text
- 壳/导航：…
- 权限表面：…（无 RBAC 则跳过）
- 异步反馈：…
- 弹层遮罩：Dialog/Sheet 透明度… · 是否共享 Token…
- 响应式抽检：断点… · 页… · 结论…
- 主题：跳过 / findings…
```

## 明确不做（防膨胀）

- 完整 WCAG / 读屏审计（可另开 a11y skill）
- 性能、包体、Lighthouse 全项
- SEO、社交媒体卡片
- 视觉回归截图流水线（可选人工抽检，非本 Skill 强制；真机遮罩观感可用 browser-reviewer 佐证）
