# 语气、结构与阅读体验

## 语气

- **你**做主语：点击、选择、填写。少用「用户应」「系统将」。
- 短句；一段一个意思。
- 术语首次出现给**一句人话解释**，其后可用术语。
- 中文产品用中文 UI 称谓；不要中英混杂无必要。
- 自信、具体；避免「可能」「也许」「一般而言」连篇（部署差异除外，并写明）。

## 扫描友好排版

- 标题层级：一篇一个 H1（或 frontmatter title + 正文从 H2）；H2 少而稳。
- 步骤用有序列表；选项用无序或表格。
- **粗体**仅用于与界面一致的控件名（**保存**、**邀请成员**）。
- 单篇任务文建议扫读长度：约 1～3 屏；更长则拆「基础 / 高级」或另开参考文。
- 需要图时：放在关键步骤下，alt 写清「应看到什么」；无图则文字必须自足。

## 信息优先级（自上而下）

1. 我能用这篇做什么？（标题 + 开篇 1～2 句）  
2. 开始前要有什么？（精简前置）  
3. 怎么做？（步骤）  
4. 怎样算成功？（可观察结果）  
5. 不行怎么办？（按需）  
6. 接下来去哪？（相关）  

不要把「适用角色」写成空洞标签墙；若角色不明显，开篇一句「适合：…」即可。

## 步骤写法公式

```
N. 在「〈页面/区域〉」〈动作〉**〈控件文案〉」。
   （可选）你会看到〈结果〉。
```

示例：

```
3. 在「新建项目」对话框中选择 **空白项目**，填写 **名称**，并选择所属 **组织**。
   你会看到创建按钮变为可点击。
4. 点击 **创建**。
   你会进入该项目的概览页，侧栏出现代码、流水线等入口。
```

## 成功标准

优先用户可观察：

- ✅ 「我的项目」列表中出现刚建的名称；可点进概览。  
- ⚠️ 可作补充：「地址栏路径包含 `/projects/`」。  
- ❌ 仅写内部 ID 正则或 Cookie 已设置。

## 前置条件清单（合格示例）

- 已登录。（链到登录文，若读者可能未登录）  
- 你是该组织的 **组织管理员**，或拥有 **创建项目** 权限。  
- 已有至少一个组织。（链到「创建组织」）  

不合格：`具备本操作所需的项目/组织/平台权限` + `有效 nex_session`。

## 排障条目公式

```
**〈症状，用户语言〉**  
原因：〈一句〉  
处理：〈可执行动作〉  
```

只保留本稿高发项。登录过期统一：「若被带回登录页，请先完成 [登录](…) 再回到本页。」

## Frontmatter（若帮助系统需要）

可保留 `title` / `summary` / `role` / `order` 等供导航，但：

- `summary` = 场景或收益，不复读 title  
- 元数据不能代替正文质量  
- 不要为填满 schema 发明无用字段内容
