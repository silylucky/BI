# Create Evolution Plan（人工交互）

## 何时使用

- 用户手动触发，为自动化演化设置阶段性人工干预（里程碑与顺序）
- SOP 中「禁止创建/修改 plan.md」约束的是**演化流程内 subagent**；人工干预统一经本 skill
- 典型时机：项目启动排期、picker 回传 `SATURATED`（评分饱和）、方向调整

## 文档定位

`docs/automate/plan.md` 是自我演化的**人工顺序干预层**，回答「先做哪些 PRD 项、按什么阶段推进、什么时候需要人工改方向」。它不新增需求事实，不替代 PRD；每一行必须映射到已有 prd ID。

| 文档 | 定位 | 本 skill 是否修改 |
|------|------|------------------|
| `goal.md` | 产品方向与边界 | 否 |
| `prd.md` + `prd/*.md` | 功能真理源与状态 | 只在迁移内嵌里程碑时缩短 hub 里程碑节 |
| `plan.md` | 人工里程碑、优先顺序、当前节 | 是 |
| `evolution-state.md` | STUCK 计数、待办池、当前轮次 | 只读，用于建议 |

## 工作模式

| 模式 | 触发 | 输出 |
|------|------|------|
| 新建 | `plan.md` 不存在 | 完整里程碑计划 |
| 体检 | `plan.md` 已存在 | 质量评分 + 对账清单 + 调整建议 |
| 干预 | STUCK / SATURATED / 方向调整 | 重排、插入或拆分里程碑 |
| 迁移 | PRD hub 内嵌里程碑 | 独立 `plan.md` + hub 引用行 |

## plan.md 结构

```markdown
# 演化里程碑计划

> 人工维护（create-evolution-plan）；演化 agent 只读。
> 当前节 = 第一个含未完成 `[ ]` 的节。

## M1 — <里程碑名>

**目标**：<一句话>

- [x] <prd ID>: <名称>（完成于 YYYY-MM-DD）
- [ ] <prd ID>: <名称>

## M2 — <里程碑名>
…
```

## 首次创建（plan.md 不存在）

1. 读 `goal.md` + `prd.md`（hub 的功能索引与薄弱项汇总）+ `evolution-state.md`（待办池与 STUCK 计数）
2. 提议里程碑分节：每节 = 节号 + 目标一句话 + prd ID 勾选清单
3. 说明排序依据：goal 优先级、PRD 薄弱项、STUCK、依赖关系、风险控制
4. **交互循环**：用户增删项 / 重排节 / 改目标 → 重新呈现完整 plan → 直到用户确认
5. 写入前展示完整预览，确认后写入 `docs/automate/plan.md`

## 重复执行（plan.md 已存在）

1. 对照 prd 分片状态，汇报各节完成度；分片已「已实现」但 plan 未勾选的 → 提议勾选
2. 读取 `evolution-state.md` 的 STUCK 计数与待办池，标出可能需要人工干预的条目
3. 与用户调整未完成节（增删 prd ID、插入新里程碑节、重排）
4. 写入前展示变更摘要与完整 plan 预览，确认后写入；P5 每轮自动勾选已合并项，本 skill 负责结构变更与全量对账纠偏

## 质量评分（100 分）

| 维度 | 分值 | 检查点 |
|------|-----:|--------|
| PRD 映射完整性 | 20 | 每个任务均可定位到 prd ID |
| 当前节可执行性 | 20 | 当前节 3-8 项，范围可被 G2 批量选题消化 |
| 排序合理性 | 20 | 与 goal、薄弱项、依赖和风险一致 |
| 状态一致性 | 15 | plan 勾选与分片状态一致，无已实现未勾选 |
| 人工干预价值 | 15 | 能处理 STUCK/SATURATED/方向调整，而非复制 PRD 全量列表 |
| 格式可维护性 | 10 | 行格式适配 P5 自动勾选，节目标清晰 |

评分解释：

| 分数 | 结论 |
|------|------|
| 90-100 | 可稳定约束 G2 选题顺序 |
| 80-89 | 可用，但当前节或状态对账需小修 |
| 70-79 | 会影响选题质量，建议先人工调整 |
| <70 | 不建议作为无人值守里程碑输入 |

## 人工干预建议

当发现下列信号时，主动给出 2-3 个候选方案供用户选择：

| 信号 | 建议 |
|------|------|
| `SATURATED` | 新增下一阶段目标、扩大业务域、或回到 `create-evolution-goal` 修订方向 |
| 同一 prd ID 连续 STUCK ≥3 | 拆小验收标准、降低当前节并发、或把该项移入人工专项 |
| 当前节长期未完成 | 拆分当前节，保留 3-5 个最可交付项 |
| 薄弱项 Top5 与 plan 当前节无交集 | 建议插入薄弱项修复里程碑或解释为什么暂不处理 |
| 已实现项未勾选 | 建议对账勾选，不改变 PRD 状态 |

## 迁移模式（prd.md 内嵌里程碑）

检测到 prd.md 含「里程碑」正文节（非引用行）时提议迁移：

1. 内嵌里程碑整理为上述 plan.md 分节结构（完成状态从 prd 分片状态派生为勾选）
2. prd.md 该节缩为一行：`里程碑见 docs/automate/plan.md（人工维护，create-evolution-plan）`
3. 用户确认后执行；hub 修订记录追加一条「里程碑迁移至 plan.md」

## 与演化流程的边界

| 场景 | 负责方 |
|------|--------|
| 每轮演化合并后增量勾选 | P5（`evolution-pr-finish`） |
| 首次创建、增删节、重排、改目标 | 本 skill（人工） |
| 全量对账（prd 已实现但 plan 漏勾、格式漂移） | 本 skill 重复执行模式 |
| G1 / G2 / P1–P4 | 只读 plan |

- 演化 subagent **禁止**调用本 skill
- 行格式须与 P5 勾选规则一致：`- [ ] <prd ID>: <名称>` / `- [x] …（完成于 YYYY-MM-DD）`

## 交互式引导问题库

按需使用，一次只问一个：

| 场景 | 问题 |
|------|------|
| 当前节过大 | “下一轮更希望优先交付稳定性、体验，还是架构健康？” |
| STUCK | “这个卡住项应该拆小、降优先级，还是保留为当前阶段主线？” |
| SATURATED | “现在是进入新业务域，还是提高已有功能的非功能质量？” |
| 状态不一致 | “PRD 分片显示已实现，但 plan 未勾选，是否按分片状态对账？” |
| 新增里程碑 | “这个里程碑的完成信号是什么？哪些 prd ID 代表完成？” |

## 回传格式

```yaml
status: DONE | DONE_WITH_CONCERNS | BLOCKED
phase: create-evolution-plan
mode: create | audit | intervene | migrate
score: 0
artifacts:
  - docs/automate/plan.md
summary:
  - ""
followups:
  - ""
```

## 红线

- 每节列出的 prd ID 须可在 hub 定位（8 维总表，或功能索引指向的分片）；完全不存在 → 先提示走 `create-evolution-prd` 补条目；仅功能索引缺行 → 本 skill 顺手补一行索引即可
- 不写与 prd 无映射的自由文本任务
- 写入前必须展示预览并获得确认
- **禁止**演化流程调用本 skill
