# PRD 8 维子项加权评分

## 何时使用

- 生成或更新 `docs/automate/prd.md`
- 每轮演化**合并后**对涉及功能项重新评分
- `evolution-topic-picker` 选题时读取评分选薄弱项

## 评分模型（per-feature，0–100）

### 8 维 + 权重（键与历史一致）

| 维度 | 键 | 权重 | 适用 |
|------|-----|:----:|------|
| 用户价值 | `user_value` | 高 ×3 | 通用 |
| 完整度 | `completeness` | 高 ×3 | 通用 |
| 可靠性 | `reliability` | 高 ×3 | 通用 |
| 交互体验 | `ux` | 中 ×2 | **前端条件维**（无界面整维 N/A） |
| 架构健康 | `architecture` | 中 ×2 | 通用 |
| 测试覆盖 | `test_coverage` | 中 ×2 | 通用 |
| 性能 | `performance` | 中 ×2 | 通用 |
| 安全性 | `security` | 中 ×2 | 通用（**受监管业务**可在该 prd 内升 ×3） |

### 子项档位（0/1/2 + N/A）

- 每个子项打 **`2` 完全达标 / `1` 部分达标 / `0` 未达**；不适用标 **`N/A`（必附一句理由）**，从分子分母同时剔除。
- 不用 0–10：三档之外多为主观假精度，给虚高留空间。

### 计分公式（保留 1 位小数）

```
维度分% = Σ(适用子项得分) / (Σ适用子项数 × 2) × 100        // 0–100；N/A 不计
功能项加权总分 = Σ(维度分% × 维度权重) / Σ(适用维度权重)         // 0–100；整维 N/A(如纯后端 ux) 剔除该维权重
```

## 防偷懒（强制，覆盖度不靠"少子项"换成本）

1. **清单不缩水**：子项清单固定且 comprehensive；省成本靠"粗档位"，禁止删面向。
2. **逐项强制表态**：每条子项必须显式标 `2/1/0/N/A`；**漏项 → 整维作废**（视为未评分）。**作废 ≠ N/A**：作废维不享受 N/A 的剔权待遇——该功能项评分视为无效、必须补全后重评，严禁用「漏项」替代「N/A」来降权套利。
3. **N/A 必附理由**：如「本功能无导入导出 → 批量项 N/A」。
4. **证据要求**：`2` 附锚点（`tests/x.test.ts P95<200ms`）；`0` 附缺陷；`1` 附差距。无证据不得给分。
5. **禁止整行同分敷衍**；**允许且要求降分**（腐化/退化/验收标准提高时必降）。
6. `状态` 与 `completeness` 须一致（未实现 → `completeness` 维度分% ≤ 20）。

## 八维子项清单（去重，具体可判定）

> 档位 `2/1/0/N/A(附理由)`。标「前端」「服务」「受监管」为条件子项。

### user_value 用户价值（高 ×3）
1. 精准命中 `goal.md` 指定的核心业务痛点
2. 覆盖用户显性诉求（验收标准列明的明确需求）
3. 覆盖隐性/潜在诉求（高频但未明说的真实场景）
4. 带来可量化效率提升（步骤数/耗时较旧版下降）
5. 降低操作成本（减少手动/重复动作）
6. 目标用户群体全覆盖，无被排除的核心角色
7. 相比旧版本有明显增益（非功能平移）
8. 价值可被用户直接感知，无需解释即懂
9. 符合 goal 长期方向，不偏航
10. 无冗余无效功能堆砌（YAGNI）

### completeness 完整度（高 ×3）
1. PRD 功能点全部落地，无 TODO/占位/空壳
2. 主流程端到端可走通，无缺失环节
3. 上下游衔接完整（入口→处理→出口/回执）
4. 验收标准逐条满足（勾选项全绿）
5. 常规场景全覆盖
6. 边缘/特殊场景覆盖（空数据/超大数据/异常分支）
7. 状态机完整：各状态可达且可逆，无死状态
8. 联动/关联数据同步完整
9. 文档完备：接口文档参数+示例、表结构、变更记录与实现一致
10. 版本迭代遗留需求补齐

### reliability 可靠性（高 ×3，含数据稳定）
1. 非法/缺失输入有拦截与结构化处理
2. 异常操作有兜底（不崩溃、有降级路径）
3. 高频/瞬时并发下稳定，无竞态
4. 长时间运行无异常累积（句柄/连接/内存不泄漏）
5. 中断后可自动恢复，重试幂等
6. 故障隔离，不扩散全局
7. 报错信息可定位（含上下文，不吞异常）
8. 重复提交不产生重复/脏数据（幂等/去重）
9. 临界值/边界条件正确（0/最大/负数/超长/空集）
10. 外部依赖异常时降级/熔断
11. 关键数据有备份与回滚通道
12. 数据变更全链路可追溯（审计/变更日志）

### ux 交互体验（中 ×2，**前端条件维**：无界面整维 N/A）
**交互**
1. 核心操作路径简短高效（最少步骤达成目标）
2. 每步操作即时反馈明确（loading/成功/失败态）
3. 页面跳转、状态切换流畅，无闪烁/卡白
4. 操作逻辑贴合行业通用习惯，无反直觉设计
5. 按钮/入口位置合理易查找
6. 批量/快捷操作体验良好
7. 模态弹窗、浮层使用规范（可关闭、不滥用、焦点正确）
8. 支持键盘快捷操作；键盘焦点遍历有序（适配无障碍基础）

**视觉**
9. 整体视觉风格统一
10. 组件样式全局一致（同类控件同款）
11. 字体/字号/行高规范统一
12. 图标风格、尺寸统一且表意清晰
13. 页面布局规整，遵循网格体系
14. 信息层级分明，主次一目了然
15. 色彩搭配舒适，无刺眼配色
16. 文本与背景对比度合规（WCAG AA）
17. 控件全状态完整（默认/hover/active/focus/disabled/loading/error）
18. 留白、间距协调，视觉不拥挤
19. 深色/浅色模式适配正常，多主题场景样式不错乱

**容错&引导**
20. 空状态有合理提示与引导（非空白页）
21. 错误给出明确原因 + 解决指引（非笼统"操作失败"）
22. 表单逐字段精准校验：必填项标识、类型/格式即时提示、错误样式（红框/错误文案）到位
23. 高危操作前置风险提示 + 二次确认
24. 失误支持撤回/修正
25. 流程中断处有接续引导
26. 重复提交/连续点击做防重拦截（高频操作防异常，按钮置灰/节流防抖）

**上手**
27. 核心功能一眼可识别，命名通俗
28. 常规操作无需额外学习；复杂功能有分步指引
29. 新用户入门引导完善
30. 隐藏功能有弱提示

### architecture 架构健康（中 ×2，含可维护/运维）
1. 模块职责单一清晰
2. 低耦合高内聚，依赖方向合理
3. 对外接口定义规范统一（命名/入参/返回结构一致）
4. 接口参数与返回结构稳定（版本兼容）
5. 预留扩展点，新增不改核心
6. 分层清晰，无跨层调用
7. 第三方依赖精简、版本锁定可控
8. 组件/服务复用性强，无复制粘贴
9. 复杂度合理，无过度设计
10. 依赖关系无循环、无冗余
11. 可维护：命名语义清晰、关键逻辑有注释、格式统一、硬编码配置化、单函数职责单一
12. 运维友好：日志分级合理、可一键启停/重启、监控告警接入、配置集中管理（**服务**条件）

### test_coverage 测试覆盖（中 ×2）
1. 核心主流程有测试用例
2. 分支流程全覆盖
3. 边界值/极值有测试
4. 异常/故障场景有测试
5. 关键逻辑有单元测试
6. 接口集成测试完整可用
7. 自动化脚本稳定可执行，无 flaky
8. 回归用例齐全
9. 高频变更模块重点覆盖
10. 测试结论与问题记录完整；覆盖率达项目约定阈值（如有）

### performance 性能表现（中 ×2）
1. 核心接口响应达标（P95 在约定阈值内）
2. 页面/首屏加载正常（**前端**）
3. 大数据量渲染/查询无卡顿
4. 长列表分页/滚动/虚拟化性能良好（**前端**）
5. 并发访问下性能无明显衰减
6. 内存占用合理，无泄漏
7. 带宽/网络资源消耗可控
8. 定时/后台任务执行高效
9. 导入导出等批量操作流畅
10. 长时间使用性能无持续下降

### security 基础安全（中 ×2，受监管域可升 ×3）
1. 所有输入过滤校验（含接口入参：必填/类型/范围/枚举/长度）
2. 防注入（SQL/脚本/命令/路径穿越）
3. 权限分级 + 访问控制严格
4. 越权（水平/垂直）风险规避
5. 敏感数据传输加密（TLS）
6. 敏感数据存储脱敏/加密
7. 会话凭证安全，防盗用/CSRF
8. 密码/密钥妥善管理（不硬编码、不入日志）
9. 操作日志留痕可追溯
10. 高危操作二次校验
11. 合规：数据采集/使用/留存符合规范（**受监管**）
12. 合规：对外输出/报表口径合规（**受监管**）

## 读写分工（hub + 分片）

| 内容 | 位置 | 维护时机 |
|------|------|----------|
| 8 维维度分% + 加权总分、薄弱项汇总、修订记录 | `docs/automate/prd.md`（hub） | 初评 / P5 重评 |
| 状态、验收标准、goal_ref、代码锚点、演化建议、里程碑对齐 | `docs/automate/prd/F<NN>-<域>.md`（分片） | 初评 / P5 重评 |

子项逐项 `2/1/0/N/A` 表态是**评分过程**的强制 checklist；持久化只落维度分% + 加权总分（hub）+ 每维一句证据（修订记录 / PR 结案评论），**不写入分片**，避免文档膨胀。

模板：`.cursor/automate/templates/prd-hub.md` · `.cursor/automate/templates/prd-feature.md`。

## 评分流程

### 初次评分（prd 生成或首次对齐）

1. 读 `docs/automate/goal.md` 定范围边界
2. 按代码锚点抽样读实现（路由、UI、测试、错误处理）
3. 逐维走子项清单：每条 `2/1/0/N/A` + 一句证据/理由 → 算维度分% → 算加权总分，**禁止整行同分敷衍**
4. `状态` 与 `completeness` 维度分% 须一致（未实现 → ≤20）

### 合并后重评分（每轮 Phase 5 必做）

1. 识别本轮 PR 触及的 prd 功能 ID
2. 仅对**涉及项**重新走代码抽样 + 子项清单（附证据，允许降分）
3. **hub**：更新 8 维维度分% + 加权总分对应行、刷新系统薄弱项汇总、追加修订记录一条并裁剪至最近 10 条
4. **分片**：更新 `状态`、验收标准勾选、`演化建议`；按 `evolution-pr-finish(-github)` 规则写 `里程碑对齐`
5. **plan.md**：P5 在同一 §5.5 流程内按 skill「plan 勾选规则」同步勾选（仅 `- [ ] <prd ID>:` → `- [x] …（完成于 日期）`；不由 prd-scoring 直接写 plan）
6. **STUCK 计数**：触及项加权总分 `<90` → 在 `docs/automate/evolution-state.md`「选题卡住计数」表对该 ID **upsert**（连续未过轮次 +1，记最近加权总分与日期）；`≥90` → **删除**该行
7. **禁止**在薄弱项汇总区追加历史性 note / blockquote

### 系统薄弱项汇总（prd.md 顶部固定节）

```markdown
## 系统薄弱项汇总（按总分升序，供选题）

| 排名 | ID | 功能 | 总分 | 最薄弱维度 | 建议优先级 |
|------|-----|------|------|------------|------------|
| 1 | FEAT-xxx | … | 42.5 | 测试覆盖(30%) | 高 |
```

每轮合并后刷新此表（取加权总分最低 Top 10 或任一维度分% ≤40 的项）；总分为 0–100，最薄弱维度括注其维度分%。

## 选题挂钩

- `evolution-topic-picker` 优先从**薄弱项汇总**和 `状态=未实现|部分实现` 项选题
- 同分时：`user_value` 低分优先；有 `docs/automate/plan.md` 时其次参照 plan 顺序（**只读**）；无 plan 时纯 8 维
- 选中项须在「本轮演化目标」引用其 **prd ID + 当前加权总分**
- 评分饱和判定（薄弱项 Top5 加权总分均 ≥90）由 `evolution-topic-picker` 执行，见该 skill「饱和熔断」
- **STUCK**：同一功能项连续 ≥3 轮被选中仍 `<90` → picker 在 round-target 与 summary 标 `STUCK`，建议人工 `create-evolution-goal` / `create-evolution-plan` 复核验收标准（非硬阻塞）
