# 报表中心 人工验收测试用例

> 在 VitalSpan 管理端 **手动操作** 的测试说明书 · 最近更新 2026-07-30  
> 配套：[报表中心使用指南](../user-guide/report-center-how-to.md) · [F08-RPT](../automate/prd/F08-RPT.md) · [UX backlog](../ux-critique/2026-07-30-report-center-backlog.md)

## 用法

- 每条 Case 独立执行，在记录表打 ✓ / ✗ 并备注实际现象
- 前置条件不满足时标记 **阻塞**，不强行判失败
- 自动回归对照：`cd fe && npx vitest run src/pages/admin/reports/`

---

## 准备工作（一次性）

| 项 | 要求 |
|----|------|
| 环境 | 后端 `uvicorn` + 前端 `pnpm dev` 已启动 |
| 访问 | `http://localhost:5173/admin` |
| 账号 | 至少准备 **admin**、**analyst**（或 viewer）各一；开发密码见 `backend/.env.example` |
| 数据 | 种子数据含至少 1 个报表 catalog 模板 + 1 条预制 binding（默认 dev 环境通常已有） |

## 第一组：导航与权限（IA）

> **目标**：侧栏入口、角色可见性与页标题一致  
> **观察点**：菜单文案、403/不可见项

### Case 1.1 — analyst 可见消费入口

**操作步骤**：

1. 使用 analyst 账号登录。
2. 展开侧栏 **报表 → 报表中心**。
3. 依次进入 **全部报表**、**预制报表**。

**预期**：

- 子菜单含 **全部报表**、**预制报表**。
- **不含** **报表模板**、**报表调度**。
- **全部报表** 页标题为「全部报表」；**预制报表** 页标题为「预制分析报表」。

---

### Case 1.2 — admin 可见管理入口

**操作步骤**：

1. 使用 admin 账号登录。
2. 展开 **报表 → 报表中心**。

**预期**：

- 子菜单额外含 **报表模板**、**报表调度**。
- 进入 **报表调度** 页描述为「管理报表定时任务，查看执行历史与失败重试。」（无内部编号）。

---

## 第二组：全部报表 Hub（消费侧）

> **目标**：找模板、默认报表、预制预览  
> **PRD**：RPT-002 / RPT-004

### Case 2.1 — 搜索与格式筛选

**操作步骤**：

1. admin 或 analyst 进入 **全部报表**。
2. 在 **授权报表模板** 搜索框输入已知模板名称关键字。
3. 点击 **PDF**（或 Word / Excel）筛选按钮。

**预期**：

- 搜索框 placeholder 为「搜索报表名称…」（不含 templateKey 字样）。
- 匹配项减少；无匹配时显示「无匹配报表」。
- 格式筛选后仅显示对应类型卡片；卡片副标题为「PDF 报表」等可读文案。

---

### Case 2.2 — 打开并运行授权模板

**操作步骤**：

1. 在 Hub 某模板卡片点击 **打开并运行**。
2. 等待页面加载。

**预期**：

- 进入浏览页，标题为模板名称。
- 自动出现 **运行结果** 表格（或占位友好文案，非工程报错口吻）。
- 页头有 **返回全部报表** 链至 `/admin/reports/center`。
- 页底 **报表导出** 无「模板 ID」输入框（消费侧隐藏 UUID）。

---

### Case 2.3 — 角色默认报表卡片

**操作步骤**：

1. 在 **系统 → 用户/角色** 为某角色绑定默认报表模板（若环境支持）。
2. 使用该角色账号打开 **全部报表**。

**预期**：

- 加载过程中 Hub 顶区有骨架占位（非空白闪烁后消失）。
- 配置正确时显示 **角色默认报表** + **打开默认报表**。
- 若 ID 已绑定但目录无节点，显示「默认模板暂未在目录中同步」兜底（非静默无卡片）。

---

### Case 2.4 — Hub 预制预览展开

**操作步骤**：

1. 在 **预制分析** 区块确认预览条数。
2. 若总数 > 6，点击 **展开全部 (N)**，再点 **收起**。

**预期**：

- 默认最多 6 条；展开后显示全部预制项。
- **进入预制报表** 链至 `/admin/reports`。

## 第三组：预制分析报表

> **目标**：列表、搜索、运行、深链  
> **PRD**：RPT-002

### Case 3.1 — 列表搜索与运行

**操作步骤**：

1. 进入 **预制报表**。
2. 在工具栏搜索框输入 displayName 片段。
3. 点击某行 **运行**。

**预期**：

- 列表为表格壳层（非旧版小卡片 ScrollArea）。
- 显示「筛选结果 N 条」。
- 仅被点击行按钮为「运行中…」，其他行 **运行** 仍可点。
- 下方出现 **运行结果** 表格。

---

### Case 3.2 — Hub 深链自动运行

**操作步骤**：

1. 从 Hub 预制行点击 **运行**（或手动访问 `/admin/reports?binding={bindingKey}`）。
2. 观察是否自动执行。

**预期**：

- 进入预制页后自动调用运行，结果区展示数据。
- 同一 binding 仅自动运行一次（刷新可再触发）。

---

### Case 3.3 — viewer 无权运行（若环境可配）

**操作步骤**：

1. 使用 viewer 登录，对限制角色的预制项点击 **运行**。

**预期**：

- 显示 **无权运行预制报表** 空态，非未处理 API 报错。

---

### Case 3.4 — 返回链与导出区位置（admin）

**操作步骤**：

1. admin 进入 **预制报表**，未运行前观察页面结构。
2. 运行一条后再次观察。

**预期**：

- 页头有 **返回全部报表**。
- **报表导出** 在 **运行结果** 之后；未运行前导出按钮禁用并提示需先运行（管理员可见模板 ID 字段）。

---

## 第四组：报表导出

> **目标**：消费侧导出闭环  
> **PRD**：RPT-001 / API-005

### Case 4.1 — 浏览页导出 PDF

**操作步骤**：

1. 从 Hub **打开并运行** 某 PDF 模板。
2. 在 **报表导出** 选择 **PDF**，点击 **发起导出**。

**预期**：

- 状态显示中文（如「处理中」「已完成」）。
- 成功后出现 **下载** 按钮（或明确失败 toast，非 silent fail）。

## 第五组：报表模板（管理侧）

> **目标**：目录、扩展、预览  
> **PRD**：RPT-003 / RPT-004 / RPT-006

### Case 5.1 — 新建模板并保存扩展

**操作步骤**：

1. admin 进入 **报表模板**。
2. 点击 **新建模板**，在左侧选中新建节点。
3. 打开 **扩展配置** Tab，添加指标，填写 **变更说明**，保存。

**预期**：

- toast「扩展配置已保存」。
- **预览** Tab 可看到渲染结果变化（或占位说明）。

---

### Case 5.2 — 模板块编辑

**操作步骤**：

1. 选中 Word/Excel/PDF 模板，进入 **模板块** Tab。
2. 做一处块结构修改并保存。

**预期**：

- 保存成功反馈；再次进入内容保持。

---

## 第六组：报表调度（管理侧）

> **目标**：列表、历史、中文状态  
> **PRD**：RPT-005

### Case 6.1 — 调度列表与状态文案

**操作步骤**：

1. admin 进入 **报表调度**。
2. 查看 **状态** 列 Badge。

**预期**：

- 状态为中文（如 **已调度**、**已暂停**），非 `scheduled`  raw 英文。

---

### Case 6.2 — 执行历史与重试

**操作步骤**：

1. 点击某调度行的模板名称展开历史。
2. 对失败记录（若有）点击 **重试**。

**预期**：

- 历史 **状态** 列为中文（如 **执行失败**、**已生成（投递降级）**）。
- 重试提交后有成功 toast 或明确错误提示。

---

### Case 6.3 — 日/周/月调度向导

**操作步骤**：

1. admin 进入 **报表模板** → 选中模板 → **调度** Tab。
2. 在新建调度表单选择 **每周**、星期、执行时间。
3. 查看预览文案后 **创建调度**。

**预期**：

- 预览显示中文频率（如「每周一 08:00」），非裸 `0 8 * * 1`。
- 「高级 Cron」默认折叠，展开后可编辑 cron 表达式。

---

### Case 6.4 — 完整接收人配置

**操作步骤**：

1. 在调度表单点击 **添加**，分别配置：**角色**（管理员）、**用户**（可选）、**邮箱**（如 `ops@example.com`）。
2. 创建并激活调度。
3. 进入 **报表调度** 列表查看 **接收人** 列。

**预期**：

- 未配置有效接收人时无法提交（按钮禁用或 toast 提示）。
- 列表 **接收人** 列显示摘要（如「角色:管理员、ops@example.com」）。

---

### Case 6.5 — 看板定时报告

**操作步骤**：

1. admin 进入任意有组件的看板 **分享页**（`/admin/dashboards/:id/share`）。
2. 在页底 **定时报告** 卡片配置频率、接收人、PDF 附件，点击 **创建定时报告** → **激活**。
3. 进入 **报表调度** → **看板/大屏** Tab。

**预期**：

- 列表 **源类型** 为 **看板**；**调度源** 为看板名称。
- 点击 **查看源** 回到该看板分享页（大屏应为 `/admin/data-screens/:id/share`）。
- Hub admin 快捷入口 **看板定时报告** 链至调度页对应 Tab。

## 第七组：异常与回归

### Case 7.1 — API 失败可恢复

**操作步骤**：

1. 停止后端或模拟网络错误。
2. 刷新 **全部报表** 或 **预制报表**。

**预期**：

- 页顶 **PageErrorBanner** 显示可读错误信息。
- 点击 **重试** 可重新加载（恢复后端后）。

---

### Case 7.2 — 空目录空态

**操作步骤**：

1. 在无 catalog 模板的环境（或隔离测试库）打开 **全部报表**。

**预期**：

- **暂无授权报表** 空态，含引导「浏览预制报表」按钮。

## 第八组：G5 可视化 PDF（交付签收）

> **目标**：看板定时报告附件为可视化快照，非布局文字清单  
> **PRD**：RPT-005 · [交付闭环设计](../feature-design/2026-08-03-report-center-delivery-closure.md)

### Case 18 — 看板定时 PDF 视觉验收

**前置**：

- `playwright install chromium` 已执行
- 单实例前端 dev：`pnpm dev --host 127.0.0.1 --port 5173`
- 后端 `FE_BASE_URL=http://127.0.0.1:5173`（`FE_BASE_PATH` 留空）；重启 uvicorn
- SMTP（可选）：`docker compose up -d mailhog`（1025 / UI 8025）

**操作步骤**：

1. admin 登录 → 打开含至少 1 个图表的看板 → **分享** → **定时报告**。
2. 配置 PDF 附件、接收人 → **创建** → **激活** → **立即执行**。
3. 展开执行历史，查看 **产物类型** 与 **状态**。
4. 下载附件 PDF，目视检查内容。

**预期**：

- 历史 `artifactKind` 显示 **可视化快照**（非布局摘要）。
- 渲染失败时状态为 **执行失败**，`errorMessage` 说明原因（非 silent 成功）。
- PDF 可见画布/图表区域；正文 **不得** 以 `LAYOUT INVENTORY PREVIEW` 开头。
- 邮件（MailHog 运行时）：收件箱可见 **PDF MIME 附件**，无需登录下载链接。

## 第九组：P3-SMOKE 真导出与 Dataset 桥接

> **目标**：模板 RenderSpec 真字节导出 + extension metric Dataset 查数  
> **PRD**：RPT-001/003/006 · P3 最终形态

### Case 19 — 模板真导出 PDF/Excel/Word

> **自动化签收**：`tests/test_report_manual_cases_p3.py::test_case_19_template_export_pdf_excel_word_bytes`

**前置**：

- 已创建 catalog 模板节点（`templateKind=pdf|excel|word`）并完成 extension 配置（至少 1 条 SQL metric + 有效 `dataSourceId`）
- admin 登录

**操作步骤**：

1. **全部报表** → 打开目标模板 → **运行**。
2. 在导出区分别发起 **PDF / Excel / Word** 导出（或 IF-03 `GET /reports/export?templateId=…&format=…`）。
3. 下载文件，检查文件头与内容。

**预期**：

- PDF 以 `%PDF` 开头，含表格数据行（非单 label 占位）。
- Excel 为 PK zip（xlsx），含 section sheet。
- Word 为 PK zip（docx），含表格段落。
- `exportHook.placeholder=false`。

### Case 20 — Dataset 模式报表运行

> **自动化签收**：`tests/test_report_manual_cases_p3.py::test_case_20_dataset_mode_run_returns_rows`

**前置**：

- 已创建 Dataset + bind-query-config（`boundConfigId`）
- 模板 extension 中某 metric 设为 **Dataset** 模式（`queryMode=dataset`，填写 `datasetId` + `boundConfigId`）

**操作步骤**：

1. **报表模板** → 扩展配置 → 指标行切换 **Dataset** → 选择 Dataset 与绑定配置 → 保存。
2. **全部报表** → 打开该模板 → **运行**（web 格式）。
3. 查看运行结果表格列与行。

**预期**：

- 运行成功，`renderSpec.sections` 含 Dataset 查数返回的 columns/rows。
- 切换回 SQL 模式后仍可用 `expression` 查数（存量兼容）。

### 结论

- **UI / 导航 / 文案 / 壳层**：与用例预期一致（含近期 UX 修复项）。
- **运行类主路径**（模板 run、预制 run、调度历史）：受 **本地元数据/数据源未齐** 影响，需补实体物理表 + 模板 `dataSourceId` 后再跑 Case 2.2、3.1、3.2、6.2。
- **建议复测**：配置 `equipment` 实体表与角色默认报表后，用 **5176** 端口重跑第三、四、六组。
