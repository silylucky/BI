## Review Card

- **主 JTBD**：登录用户在不找管理员的情况下，维护自己的身份资料、登录密码、界面偏好，并（可选）指定登录后优先进入的仪表板。
- **成功长什么样**：改完资料刷新仍一致；改密后明确知道要不要重登；偏好页能看懂「我现在登录会进哪」且设置一次就生效。
- **最贵失败**：改密以为还能用、实际 JWT 已废却无人告知；或设了「默认看板」登录仍进错页，用户认定「系统坏了」。
- **未真机**：是（本轮未 MCP 浏览器走查）

## 执行摘要（刁钻口吻）

- **最锋利的三刺**：① 改密成功 toast 后**不引导重新登录**，与后端 `TOKEN_REVOKED` 行为打架（`ChangePasswordSection.tsx` vs `test_auth_profile.py`）；② 「个人视图」靠把名称改成魔法字 **「默认」** 才能 landing（`UserViewsSection.tsx:117-128` + `defaultViewResolve.ts:40`），产品文案只解释了一半；③ **权限范围**只显示「N 项已授权」却不让普通人看懂自己到底能干什么（`AccountInfoCard.tsx:70-78`）。
- **唯一值得先修的主线**：**改密闭环**（成功 → 明确会话结束 → 跳转登录）+ **默认入口一条线**（合并「角色默认 / 个人视图 / 设为默认」叙事，消灭魔法命名）。
- **不该再加的功能**：2FA、会话列表、头像上传——在默认看板与改密闭环没立住之前，都是演示型菜单膨胀。

## 改进建议与方案

### P0

#### B-1 · 改密成功后的会话闭环

| 项 | 内容 |
|----|------|
| 刺点 | toast 成功但 JWT 已吊销，用户未被告知须重登 |
| 产品改法 | 改密成功 = **结束当前会话**；成功页/对话框明确「请用新密码重新登录」，自动 `logout` + 跳转 `/login` |
| 第一刀切片 | 改密成功 3 秒内出现「密码已更新，请重新登录」+ 跳转；验收：旧 token 调 `/me` 401 且 UI 已在登录页 |
| 证据路径 | `ChangePasswordSection.tsx` · `auth-context` logout · `test_auth_profile.py` |
| 不做 | 不做「保持登录」选项（与安全模型冲突） |
| 预期提分 | 维6 → 82；总分 +4 |

#### B-2 · 消灭「默认」魔法命名

| 项 | 内容 |
|----|------|
| 刺点 | 设默认 = 改视图名为「默认」，用户不可理解 |
| 产品改法 | API/模型增加 `isDefault` 或专用「设为登录入口」布尔；UI 只显示「登录入口」徽章，不改用户起的名称 |
| 第一刀切片 | 列表「设为默认」不改名，仅打标；`defaultViewResolve` 读标志位；迁移旧 `name==='默认'` |
| 证据路径 | `UserViewsSection.tsx` · `backend/app/views/user_override.py` · `defaultViewResolve.ts` |
| 不做 | 不顺手做「多默认」 |
| 预期提分 | 维3 → 78；维5 → 72 |
