## Review Card

- **主 JTBD**：业务分析员按固定业务对象（分析包）查看「当前态势」，并与**上一统计周期**的自动快照做维度增减对比，辅助周期例会决策。
- **成功长什么样**：选包 → 选主题（如区域分布）→ 点「对比上期」→ 一眼看到「本期 vs 上期 vs 增减」，并知道本期键、上期键、快照是否已生成；无上期时有明确下一步（等待或手动首期快照）。
- **最贵失败**：用户把「对比上期」当成实时同比/自由选期对比，或以为功能坏了（上期全是 `—`），最终回 Excel 手工拉数。
- **未真机**：是（依据截图 + 代码/API 走查）

## 执行摘要（刁钻口吻，短）

- **最锋利的三刺**：（1）「对比」其实是**实时查询 vs 上一周期自动快照**，页面从不解释；（2）无上期快照时仍展示四列表格、上期/增减全 `—`，像半成品而不是「等待快照」；（3）快照只有后端 cron + API，消费端**看不见、点不了、验不了**。
- **唯一值得先修的主线**：把「对比什么、本期是什么、上期从哪来、没有上期怎么办」做成消费端**一等公民状态**，再谈主题/图表 polish。
- **体验依赖能力缺口（须进 PRD）**：消费端快照可观测 + 首期快照引导（B-3、B-7）；可选历史期次对比（B-7）。
- **不该再加的功能**：在对比未立住前加更多主题、图表类型、或把报表扩展 yoy/mom 硬塞进本页。

### 直接回答：「这能对比什么？」

| 能对比 | 不能对比 |
|--------|----------|
| 同一分析包、同一主题下，各**维度值（计数）**的「**当前实时聚合**」vs「**上一周期自动快照**」 | 任意两期自选（如 8 月 vs 6 月） |
| 四个固定主题：生命周期（状态计数）、区域分布（区域计数）、活跃度/趋势（按创建日计数） | 自定义指标、同比/环比窗口、跨分析包 |
| 增减绝对值（`delta`）；后端还算了 `deltaPct` 但 **FE 未展示** | 邮件/PDF 投递结果、看板截图 |
| 依赖字段映射 + Dataset 出数正确 | 绑定配置错误时的可读错误（仍可能 500） |

**你截图里的状态**：「本期」列有数（29/35/36）= 实时查询已成功；「上期」「增减」全 `—` = **还没有上一周期的快照**（新包/未到 cron/scheduler 未跑），不是「对比逻辑算了但没差」。

## 改进建议与方案

### P0

#### B-1 + B-5 · 说清「对比什么」

| 项 | 内容 |
|----|------|
| 分类 | experience_fix |
| 刺点 | 本期/上期定义缺失 |
| 产品改法 | 对比模式页眉固定三行：**本期** = 当前实时查询（`currentPeriodKey`）；**上期** = 上一周期自动快照（`previousPeriodKey`）；**快照节奏** = 包配置的 daily/weekly/monthly + 下次计划时间（若能从 scheduler 读到） |
| 第一刀切片 | 用户点「对比上期」后 3 秒内能回答「跟谁比、比什么字段」；验收：新用户不读文档能复述 |
| 证据路径 | `StandardAnalysisResultPanel.tsx`；`compare.py` CompareOut 字段 |
| 不做 | 不改对比算法、不加新主题 |
| 预期提分 | 维5 → 58；维6 → 50 |

#### B-2 · 无上期时的诚实空态

| 项 | 内容 |
|----|------|

## 开放问题（待产品裁定）

1. **「本期」是否应改为「当前周期快照」而非实时？** 现实现是实时 vs 上期快照，混合口径可能影响信任；若改需动 `compare.py` 语义。
2. **首期快照是否默认在保存分析包时自动 capture 一次？** 可减少空窗期，但需定义失败策略。
3. **对比是否默认隐藏**，直到至少有一期快照？可降低误触，但削弱「先看实时」价值。
