> **相关 PRD**：[F16-DATA](../automate/prd/F16-DATA.md) · **壳层 IA**：[layout.md](../ui/layout.md) · **域说明**：[ingestion.md](../services/ingestion.md)

## 同步任务能做什么

| 能力 | 说明 |
|------|------|
| **MySQL → 托管分析库** | 从业务 MySQL 源表读取数据，写入平台托管 PostgreSQL 分析库 |
| **全量 / 增量同步** | 全量每次覆盖目标表；增量按主键 upsert，保留已有数据 |
| **引用已有数据源** | 直接选用「数据连接」里登记过的 MySQL，无需重复填连接信息 |
| **定时调度（Cron）** | 可选 Cron 表达式，任务启用后按规律自动执行 |
| **清洗规则（ETL）** | 列重命名、类型转换、空值填充、行过滤，在写入分析库前生效 |
| **手动运行与历史** | 随时触发一次同步，并在历史页查看状态、行数、Trace ID |
| **同步后出图引导** | 编辑页提示如何把分析库表接到图表 / 仪表板 |

**数据流向（概念）**：

```
业务 MySQL 源表  →  [同步任务 + 可选 ETL]  →  托管 PostgreSQL 分析库目标表  →  图表 / 仪表板 SQL 查询
```

> 不了解「托管分析库」？见下文 **[托管分析库是什么？](#托管分析库是什么)** 与 **[本地环境准备](#本地环境准备同步前检查)**。

|------|----------|----------|

## 托管分析库是什么？

**托管分析库**是 VitalSpan 专门用来存放 **同步清洗后的业务数据** 的 PostgreSQL 数据库，供图表、仪表板、SQL 查询消费。同步任务从业务源库 **读**，向托管分析库 **写**；BI 再从分析库 **查**。

```
业务 MySQL（源表 dirty_orders）
        ↓ 读取
  [同步任务 + 可选 ETL 清洗]
        ↓ 写入
托管 PostgreSQL 分析库（目标表 orders_clean）
        ↓ SQL 查询
   图表 / 仪表板
```

### 和平台里其他库的区别

本地开发环境通常同时存在 **三个** 数据库，职责不要混淆：

| 库 | 本地典型地址 | 存什么 | 谁写入 |
|----|--------------|--------|--------|
| **平台元库** | `localhost:5432/vitalspan` | 用户、看板、同步任务配置、运行历史、ETL 规则 | VitalSpan 平台 |
| **托管分析库** | `localhost:5433/analytics` | 同步后的业务表（如 `orders_clean`） | **同步任务执行器** |
| **样例 MySQL 源库** | `localhost:3307/sample_db` | 原始业务表（如 `dirty_orders`） | 外部业务 / 演示种子数据 |

要点：

- 表单里的 **目标表** = 写入 **托管分析库** 的表名，不是 MySQL 里的表。
- **元库** 记录「任务怎么配、跑过几次」；**分析库** 才是分析用的数据。
- 平台 **不会自动** 在「数据连接」里帮你登记分析库；同步成功后需 **手动登记一次** PostgreSQL 数据源，才能在图表里选到它（见下文「同步完成后：在 BI 里使用数据」）。

### 同步表单 vs 登记分析库（为何不冲突）

两处都可能出现「数据源」字样，但配置的是 **不同库、不同阶段**：

| 配置位置 | 填什么 | 典型地址 | 作用 |
|----------|--------|----------|------|
| **同步任务 · MySQL 源库** | 业务 MySQL 连接 + 源表 | `127.0.0.1:3307/sample_db` | 同步任务 **从哪里读**（如 `dirty_orders`） |
| **同步任务 · 同步目标 · 目标表** | 仅表名（不填连接） | 写入 `5433/analytics` | 同步任务 **往哪里写**（如 `orders_clean`） |
| **数据连接 · 登记分析库** | PostgreSQL 连接 | `127.0.0.1:5433/analytics` | 图表/看板 **从哪里查** 已同步表 |

要点：

- 同步表单里的 **3307** 是 **源库**，**不要**改成 5433。
- **5433 分析库** 的写入连接由后端 `ANALYTICS_DATABASE_URL` 负责；用户只填 **目标表名**。
- 同步成功后，还需在 **连接管理** 登记一次 **PostgreSQL 5433**，图表下拉里才能选到分析库。

```
MySQL 3307（表单配置）  →  同步任务  →  分析库 5433（env 写入）
                                              ↓
                              连接管理登记 PG 5433  →  图表 SQL 查询
```

### 后端如何连接分析库

后端通过环境变量 **`ANALYTICS_DATABASE_URL`** 连接托管分析库（与元库 `DATABASE_URL` 分离）。本地 `backend/.env.example` 默认：

```text
ANALYTICS_DATABASE_URL=postgresql+psycopg://vitalspan:vitalspan@localhost:5433/analytics
```

若该变量未配置或分析库服务未启动，手动/定时同步会在 **写入阶段失败**，运行历史中常见 `connection timeout` 一类错误。

### 如何启动（本地 Docker）

在项目根目录执行：

```powershell
docker compose up -d sample-mysql analytics-postgres
```

> **网络提示**：若拉取 `postgres:16-alpine` 超时，本仓库 `docker-compose.yml` 已改用 DaoCloud 镜像 `docker.m.daocloud.io/library/postgres:16-alpine`。仍失败时可手动：`docker pull docker.m.daocloud.io/library/postgres:16-alpine`，再 `docker compose up -d analytics-postgres`。

| Compose 服务 | 宿主机端口 | 库名 | 账号/密码 |
|--------------|------------|------|-----------|
| `sample-mysql` | 3307 | `sample_db` | `sample` / `sample` |
| `analytics-postgres` | 5433 | `analytics` | `vitalspan` / `vitalspan` |

确认端口可用（PowerShell）：

```powershell
Test-NetConnection 127.0.0.1 -Port 3307   # MySQL 源
Test-NetConnection 127.0.0.1 -Port 5433   # 托管分析库
```

同时需要：

- 后端：`uvicorn app.main:app --reload --host 127.0.0.1 --port 8000`（`backend/` 目录）
- 前端：`pnpm dev`（`fe/` 目录）

## 本地环境准备（同步前检查）

在创建或运行同步任务前，建议按顺序确认：

| # | 检查项 | 通过标准 |
|---|--------|----------|
| 1 | 样例 MySQL | `3307` 可连接；存在源表（如 `dirty_orders`） |
| 2 | 托管分析库 | `5433` 可连接；`ANALYTICS_DATABASE_URL` 已配置 |
| 3 | 后端 / 前端 | `8000` / `5173` 可访问管理端 |
| 4 | 源数据源（可选） | **数据连接 → 连接管理** 中已有 MySQL 条目且测试通过 |

调试阶段建议：**Cron 留空**或 **停用任务**，先用手动 **运行** 验证全链路，再开定时，避免分析库未就绪时整点任务占坑失败。

## 进入同步任务

1. 登录管理端（本地开发一般为 `http://localhost:5173/admin`）。
2. 在左侧导航展开 **数据连接**。
3. 点击 **同步任务**（路径：`/admin/ingestion/sync-jobs`）。

列表页顶部有 **新建任务** 按钮；空列表时会显示四步引导：**配置源库 → 目标与清洗 → 运行监控 → 登记分析库并出图**。

## 快速上手：创建第一个同步任务

以下示例：把 MySQL 表 `dirty_orders` 同步到分析库表 `orders_clean`，仅手动运行（不填 Cron）。

### 1. 打开新建页

1. 在 **同步任务** 列表页，点击右上角 **新建任务**。
2. 页标题为 **新建同步任务**。

### 2. 填写基本信息

| 字段 | 说明 | 示例 |
|------|------|------|
| **任务名称** | 列表与日志中的显示名，必填 | `订单表同步` |

### 3. 配置数据源

**方式 A：使用已有数据源（推荐）**

1. 在 **数据源** 区块，选择 **使用已有数据源**。
2. 在 **MySQL 数据源** 下拉框中选择已登记的连接（需先在 **数据连接 → 连接管理** 中创建 MySQL 数据源）。
3. 下方会显示 `主机:端口/库名` 摘要。

> 引用数据源时会**快照**当前连接信息。若之后在连接管理中修改了密码，需回到本任务点 **保存** 重新快照。

**方式 B：手动填写连接**

1. 选择 **手动填写连接**。
2. 填写 **主机、端口、数据库、用户名、密码**。
3. 编辑已有任务时，密码可留空表示「不修改」。

### 4. 配置同步目标

| 字段 | 说明 | 示例 |
|------|------|------|
| **源表** | MySQL 中要读取的表名 | `dirty_orders` |
| **目标表** | 写入托管分析库的表名 | `orders_clean` |

表名仅允许字母、数字、下划线（符合 SQL 标识符规范）。

> **一表一任务**：平台把 **目标表名** 当作 Dataset ID，**禁止** 多个同步任务写入同一目标表（保存时返回 409）。新建任务时系统会按源表自动建议 **唯一** 目标表名（如 `orders_clean`、`orders_clean_2`）。若环境中仍有历史共表数据，列表会显示 **「N 历史共表」** badge，建议迁移到独立目标表名。

### 4.1 清理存量重复目标表（运维）

若列表里多个任务都指向 `orders_clean` 等同一目标表，可按以下步骤整理：

| 步骤 | 操作 |
|------|------|
| 1 | 决定 **保留哪一个** 任务继续写 `orders_clean`（通常保留主同步任务） |
| 2 | 其余任务：**编辑 → 修改目标表** 为唯一新名（如 `orders_clean_2`），或 **删除** 不再需要的任务 |
| 3 | 对改了目标表的任务 **重新运行同步**，写入新物理表 |
| 4 | 在列表/历史页对该任务 **一键创建 Dataset 并绑定**，得到 **新的 Dataset** |
| 5 | 看板中改用新 Dataset；旧的 `orders_clean` Dataset 不会自动删除，不用时可手动清理 |

改目标表 **不会迁移** 已有分析库数据；新表需重新同步后才有数据。

### 5. 选择同步策略

| 模式 | 行为 | 适用场景 |
|------|------|----------|
| **全量** | 每次运行 **清空目标表** 后重新写入 | 数据量小、允许短暂空表、需要完整镜像 |
| **增量** | 按 **主键 upsert**，不清空；只拉取水位之后的新/变更行 | 大表、需保留历史、频繁更新 |

选择 **增量** 后需额外填写：

| 字段 | 说明 | 示例 |
|------|------|------|
| **主键字段** | 源表中唯一标识一行的列（单列） | `id` |
| **增量字段** | 整型或时间戳列，用于比较「上次同步到哪」 | `updated_at` |

> 增量任务**首次运行**等同 bootstrap：会拉取全量数据建立基线，之后只拉水位之后的变更。

### 6. 调度与状态

| 字段 | 说明 |
|------|------|
| **定时 Cron（可选）** | 留空 = 仅手动运行；填写合法 Cron 后，任务 **启用** 时会按 schedule 自动执行 |
| **启用任务** | 关闭后不参与 Cron 调度，但仍可手动运行 |

### 7. 创建并验证

1. 点击底部 **创建**。
2. 成功后会跳转到 **编辑同步任务** 页，并出现 toast「同步任务已创建」。
3. 返回列表，在对应行点击 **运行**（播放图标），在确认框中再次点 **运行**。
4. 点击 **查看运行历史**（历史图标），确认状态为 **成功**，并记录 **Trace ID** 备查。

## 定时 Cron 详细说明

### Cron 是什么？

Cron 是一种用**短字符串**描述「什么时候自动执行」的写法。在 VitalSpan 中，它决定同步任务是否在后台**定时自动跑**。

- **不填 Cron**：只靠人工在列表页点 **运行**。
- **填写 Cron 且任务已启用**：平台按表达式在对应时刻触发同步（与手动运行共用同一套执行逻辑）。

### 格式（五段式 Unix Cron）

VitalSpan 使用 **5 个字段**，字段之间用**空格**分隔：

```
分  时  日  月  周
```

| 段 | 含义 | 取值 | 示例 |
|----|------|------|------|
| 1. 分 | 小时的第几分钟 | 0–59 | `0` = 整点；`30` = 半点 |
| 2. 时 | 一天中的第几小时 | 0–23 | `2` = 凌晨 2 点 |
| 3. 日 | 每月第几天 | 1–31 | `1` = 每月 1 号 |
| 4. 月 | 第几月 | 1–12 | `*` = 每月 |
| 5. 周 | 星期几 | 0–6（0=周日）或 1–7 | `1` = 周一 |

### 常用符号

| 符号 | 含义 | 示例 |
|------|------|------|
| `*` | 该段任意值都匹配 | `* * * * *` = 每分钟（不推荐用于生产同步） |
| `,` | 列举多个值 | `0 8,12 * * *` = 每天 8:00 和 12:00 |
| `-` | 连续范围 | `1-5` 在周字段 = 周一到周五 |
| `/` | 步长（从 0 或起始值每隔 N） | `*/15` 在分字段 = 每 15 分钟 |

### 表单内置预设（推荐）

新建/编辑页 **定时 Cron** 输入框下方有四个快捷按钮，点击即可填入：

| 按钮 | 表达式 | 含义 |
|------|--------|------|
| 每天 02:00 | `0 2 * * *` | 每天凌晨 2:00 |
| 每天 06:00 | `0 6 * * *` | 每天早上 6:00 |
| 每小时 | `0 * * * *` | 每小时的第 0 分（整点） |
| 每周一 02:00 | `0 2 * * 1` | 每周一凌晨 2:00 |

### 更多示例

| 需求 | Cron 表达式 |
|------|-------------|
| 每 6 小时 | `0 */6 * * *` |
| 工作日 08:30 | `30 8 * * 1-5` |
| 每月 1 号 00:00 | `0 0 1 * *` |
| 每 15 分钟 | `*/15 * * * *` |

### 常见错误写法

| 错误示例 | 原因 |
|----------|------|
| `0 0 *0 *15 *` | 段数/顺序混乱；`*15`、`*0` 不是合法写法 |
| `0 2 * *` | 只有 4 段，缺少「周」 |
| `每天2点` | 必须是 Cron 表达式，不能写中文 |

填写非法表达式时，保存会失败，页面会提示 **「Cron 表达式格式无效（定时 Cron）」**，并在 Cron 输入框下方显示红色说明。不确定时：**留空**或点预设按钮。

### Cron 与「启用任务」的关系

| Cron | 启用任务 | 结果 |
|------|----------|------|
| 留空 | 开 / 关 | 仅可手动运行 |
| 已填写 | **开** | 手动 + 定时都会生效 |
| 已填写 | **关** | 不会自动调度，仍可手动运行 |

## 配置清洗规则（ETL）

清洗规则在数据**写入托管分析库之前**执行，按列表顺序依次应用。

### 进入规则页

1. 在任务列表某一行，点击 **配置清洗规则**（齿轮图标）。
2. 或从编辑页通过列表返回后进入（路径：`/admin/ingestion/sync-jobs/{任务ID}/etl-rules`）。

### 规则类型

| 类型 | 作用 | 必填项 |
|------|------|--------|
| **列重命名** | 将源列名改为目标列名 | 源列名、目标列名 |
| **类型转换** | 将列转为 float / integer / boolean / string | 列名、目标类型 |
| **空值填充** | 把 NULL 替换为指定文本 | 列名、填充值 |
| **行过滤** | 按条件丢弃行 | 列名、操作符、比较值（部分操作符可留空） |

**行过滤操作符**：

| 操作符 | 含义 |
|--------|------|
| 等于 | 列值等于比较值 |
| 不等于 | 列值不等于比较值 |
| 为空 | 列为 NULL |
| 非空 | 列不为 NULL |

### 推荐规则链示例

页面提示的推荐顺序：

1. `product_name` → `product`（列重命名）
2. `amount` → `float`（类型转换）
3. `note` 填「无备注」（空值填充）
4. 过滤 `status` 不等于 `deleted`（行过滤）

### 保存规则

1. 可点击 **添加规则** 增加多行；每行可 **删除规则**。
2. 填写不完整时无法保存，会提示「请填写完整的列重命名规则」或「请填写规则涉及的列名」。
3. 点击 **保存规则**，成功 toast「清洗规则已保存」。
4. **下次同步**（手动或定时）会应用最新规则；已写入分析库的历史数据不会自动回溯修改。

## 管理任务列表

列表列说明：

| 列 | 含义 |
|----|------|
| **任务** | 任务名称 |
| **源** | 数据源名称或内联连接摘要 |
| **同步方式** | 全量 / 增量 |
| **目标表** | 分析库表名；历史同表多任务时显示 **「N 历史共表」** badge（新建已禁止共表） |
| **调度** | Cron 表达式，或「手动」 |
| **任务状态** | 已启用 / 已停用 |
| **最近运行** | 最近一次执行状态与时间 |

### 工具栏筛选

- **搜索**：按任务名称过滤。
- **状态筛选**：全部 / 已启用 / 已停用 / 已配置定时。

### 行操作（需 `ingestion:manage`）

| 图标 | 操作 |
|------|------|
| 播放 | **手动运行**（会弹出确认框） |
| 齿轮 | **配置清洗规则** |
| 铅笔 | **编辑任务** |
| 垃圾桶 | **删除任务**（不可恢复，历史一并清除） |

所有用户均可点击 **历史** 图标查看运行记录。

### 手动运行确认文案

- **全量任务**：提示将 **清空并覆盖** 目标表全部现有数据。
- **增量任务**：提示将拉取水位之后数据并 **upsert**，不会清空现有数据。

同一任务若已有运行在进行中，需等待完成后再触发。

## 查看运行历史

1. 在列表行点击 **查看运行历史**。
2. 页头说明：最多展示最近 **100** 次运行。
3. 每条记录包含：**状态**（成功 / 失败 / 运行中）、**开始/结束时间**、**同步行数**、**Trace ID**、**错误信息**（失败时）。

**Trace ID** 可用于在后端日志中定位一次具体执行，排查连接超时、SQL 错误等问题。

历史页底部有 **同步后如何出图** 引导（与编辑页相同）。

## 同步完成后：在 BI 里使用数据（推荐路径）

同步成功后，列表页会出现 **「同步成功 · 下一步出图」** 动作卡；运行历史页顶部也有相同入口。

**主路径只需两步：**

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 手动运行同步任务 | 数据写入托管分析库目标表 |
| 2 | 点击 **一键创建数据集并绑定** | 系统自动登记分析库（若尚未登记），并创建 Dataset + 查询绑定 |
| 3 | 点击 **创建看板** | 在图表配置中选择该 Dataset 出图（无需在看板写 SQL） |

系统会在同步成功时 **自动准备分析库连接**（基于服务端 `ANALYTICS_DATABASE_URL`），通常无需再手动去连接管理重复登记 5433。

### 高级：手动登记分析库（排障 / 覆盖）

仅在自动准备失败、或需连接非默认分析库时使用：

1. 进入 **数据准备 → 数据连接 → 连接管理**。
2. 新建 **PostgreSQL**：`127.0.0.1:5433/analytics`（用户/密码见 compose）。
3. 测试连接成功后，仍可使用动作卡 **一键创建数据集并绑定**。

| 库 | 典型地址 | 作用 |
|----|----------|------|
| 平台元库 | `5432/vitalspan` | 任务配置、运行历史 |
| 托管分析库 | `5433/analytics` | 同步后的业务表 |
| 样例 MySQL | `3307/sample_db` | 同步源表 |

### 手动创建 Dataset（可选）

若不用一键绑定，可进入 **数据准备 → 数据集 → 新建**，选择分析库与目标表。Dataset 为 **单表** 语义：在 **数据表** Tab 顶栏选择数据源后，于 Schema 树 **单击表名** 设为当前数据表（非多表累加）。在底部 **字段工作台** 中勾选维度/指标、预览样例数据；点击 **保存** 即同时更新 Dataset 与出图绑定（无需单独的「绑定配置」Tab）。

同步产物 Dataset 编辑时，字段工作台会锁定为托管分析库连接，可在此调整出图列并保存生效。

### 空白看板出图

1. 进入 **分析 → 仪表板**，创建空白看板。
2. 添加图表，绑定模式选 **Dataset**，选择已绑定的 Dataset。
3. 从字段面板拖维度/指标出图。

编辑任务页底部的 **同步后如何出图** 参考卡片仍保留三步文字说明（高级路径）。

### ETL 与 Dataset 分工

| 层 | 职责 |
|----|------|
| **同步 + ETL** | 入湖前清洗（如 `dirty_orders` 演示模板：cast `amount`、过滤 `status=deleted`） |
| **Dataset** | 选表、计算字段、字段工作台管理出图列；**不**自动洗脏数据 |
| **看板/大屏** | 选 Dataset、拖字段；**不**暴露 SQL 编辑（对标 DataEase/Superset） |

源表为 `dirty_orders` 时，可在 **清洗规则** 页点击 **「应用演示清洗模板」** 后再运行同步。

## 排障指南

### 创建 / 保存失败，提示「Cron 表达式格式无效」

**原因**：Cron 字段填了非法表达式。  
**处理**：

1. 清空 Cron 字段，或改用预设按钮 / 上文示例。
2. 查看 Cron 输入框下方红色提示。
3. 页面顶部错误条与 toast 也会显示同一信息。

### 创建失败但看不出原因

1. 看页面**顶部红色错误条**和右下角 **toast**。
2. 打开浏览器开发者工具 → Network，查看 `POST /api/v1/ingestion/sync-jobs` 返回的 422 详情。
3. 常见字段错误：表名非法、增量模式未填主键/增量字段、数据源模式未选数据源。

### 手动运行失败

1. 打开 **运行历史**，查看 **错误信息** 与 **Trace ID**。
2. 常见原因：
   - MySQL 连接失败（主机/端口/账号/防火墙）
   - 源表不存在或无权访问
   - **托管分析库不可用**（`5433` 未启动、`ANALYTICS_DATABASE_URL` 未配置）→ 错误常含 `connection timeout`
   - ETL 规则导致异常（如类型转换失败）

### 点击「运行 / 重新同步」提示失败，Network 里为 409

**现象**：终端或浏览器 Network 显示 `POST .../run` → **409 Conflict**；历史里有一条 **运行中** 长时间不结束。

**原因**：同一任务已有一条 `running` 状态的运行记录（常见于：上一次同步卡在连分析库、定时任务刚触发尚未结束）。后端错误码为 **`RUN_ALREADY_IN_PROGRESS`**，不允许并发再跑。

**处理**：

1. 打开 **运行历史**，看是否仍有 **运行中**；若已超过数分钟，多半是上次挂起，先 **刷新** 页面。
2. **优先启动托管分析库**：`docker compose up -d analytics-postgres`，确认 `5433` 可连。
3. 等待卡住的记录变为 **失败**（连接超时后会自动结束，可能需数分钟）；若确认无真实进程在跑，联系运维将异常 `running` 记录标为失败后再试。
4. 再次点击 **运行** 或历史页 **重新同步**。

> 刷新前端后，409 应提示：**「该任务正在运行中，请稍后在运行历史中查看结果」**（而非笼统的「操作失败」）。

### 运行历史显示「connection timeout」或连接分析库失败

**原因**：**托管分析库**（`localhost:5433`）未启动或网络不通；同步已从 MySQL 读到数据，但 **写分析库** 失败。

**处理**：

1. `docker compose up -d analytics-postgres`
2. `Test-NetConnection 127.0.0.1 -Port 5433`
3. 确认 `backend/.env` 中 `ANALYTICS_DATABASE_URL` 指向 `...5433/analytics`
4. 重启 uvicorn 后，在历史页 **重新同步**

### 增量同步「没有新数据」

**原因**：增量字段水位已追上源表最大值，或源表 `updated_at` 未更新。  
**处理**：确认源表确有新行或增量列有变化；必要时与管理员评估是否需全量重建。

### 全量运行后分析库数据不对

1. 检查 **清洗规则** 是否过滤或改名列。
2. 确认运行的是 **全量** 任务（会 truncate 目标表）。
3. 对比源表行数与历史中的 **同步行数**。

### 定时任务没有自动跑

1. 确认 **启用任务** 为开。
2. 确认 **定时 Cron** 已填写且合法。
3. 确认后端调度进程 / 服务正常运行（需运维检查部署环境）。

### 无「新建任务」或无法编辑

当前账号缺少 `ingestion:manage` 权限，联系管理员分配角色。
